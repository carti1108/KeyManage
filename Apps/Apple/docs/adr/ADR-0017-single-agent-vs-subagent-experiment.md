### ADR-0017 단일 에이전트 vs 서브에이전트 비교 실험 (Antigravity·Gemini 고정)
- 상태: 채택
- 날짜: 2026-10-30
- 배경: KeyManage는 영지식(Zero-Knowledge) 비밀번호 관리자이며, 최근 Anthropic의 에이전트 아키텍처 연구("Delete Your Subagents") 등에서 제기된 "과도한 서브에이전트 스캐폴딩의 비효율(토큰 낭비, 맥락 손실, 레이턴시)"과 "단일 에이전트 루프의 우수성" 주장을 실증적으로 검증할 필요가 있다. 기존 ADR-0016(웹 vs Apple 간 플랫폼·모델 비교)과 병행하여, 모델·도구·플랫폼을 100% 동일하게 통제한 상태에서 순수하게 "에이전트 구조(단일 에이전트 vs 서브에이전트)"가 소프트웨어 품질(보안/스펙 준수율)과 비용(토큰/시간/사람 개입)에 미치는 영향을 정밀 측정하기 위한 내부 A/B 실험을 설계한다.
- 결정: Apple 클라이언트 구현 과정에서 다음 조건과 절차에 따른 A/B 비교 실험을 수행한다:
  1. **고정 조건 (통제 변수)**:
     - 실행 도구: Google Antigravity
     - 사용 모델: Gemini (동일 모델)
     - 플랫폼 및 언어: macOS / Apple Swift 6, Tuist Micro-Features 5계층 모듈화 아키텍처
     - 공통 불변 규칙: 웹 코드(`Apps/Web/`) 열람 일체 금지, 확인 기준 통일(정책, 외부 의존성, 암호·데이터 형식·보안 경계 변경 시에만 중단 질의, 나머지는 추천 기본값으로 진행), 마지막에 `bash Scripts/verify-apple.sh`와 `bash Scripts/check-docs.sh` exit 0 통과 필수.
  2. **비교 변수 (독립 변수: 에이전트 구조)**:
     - **단일 에이전트 (Single Agent)**:
       - 메인 에이전트 하나가 테스트 작성(RED) ➡️ 구현(GREEN) ➡️ 자체 점검까지 단일 루프에서 완결.
       - 서브에이전트는 일체 호출하지 않으며, 필요한 규칙 및 스킬 파일은 지연 로딩(Lazy Loading)으로 직접 읽어 수행.
     - **서브에이전트 활용 (Multi-Subagent)**:
       - 테스트 작성 서브에이전트: 스펙만 보고 RED 테스트 작성 및 커밋 (구현 코드는 일체 보지 않음).
       - 구현 서브에이전트: 테스트와 스펙만 보고 통과(GREEN) 구현 및 커밋 (테스트 코드는 절대 수정 불가, 오류 시 보고만 가능).
       - 리뷰 서브에이전트: 4레이어(Build&Infra, Core, Feature, Governance) + 보안 리뷰를 수행하고 P1/P2 결함을 반영.
       - 메인 에이전트는 작업 분배 및 조율만 수행.
  3. **실험 절차 및 블라인드 판정**:
     - (1) **은닉 합격 테스트(Holdout Acceptance Tests)**: 기능 착수 전, 별도 세션에서 스펙 문서만 보고 작성하여 `Tests/Acceptance/`에 두고 실험 에이전트들에게는 공개하지 않음.
     - (2) **동일 시작 커밋에서 병렬 워크트리 분기**: `exp/<기능>-single`, `exp/<기능>-sub` 생성.
     - (3) **독립 세션 실행 및 순서 교차(Crossover)**:
       - 1단계 암호 모듈: 단일 에이전트 먼저 ➡️ 서브에이전트
       - 2단계 볼트 모델·병합: 서브에이전트 먼저 ➡️ 단일 에이전트
       - 3단계 자동 잠금(SEC-003): 단일 에이전트 먼저 ➡️ 서브에이전트
     - (4) **블라인드 판정**: 은닉 합격 테스트 실행 + 새 세션의 판정 리뷰어가 결과물을 A·B로만 받아 블라인드 평가 (4레이어 + 보안).
     - (5) **결과 처리**: 측정 표를 채우고, 종합 판정에서 우수한 쪽의 결과물만 정리하여 PR로 머지. 다른 쪽 브랜치는 측정 기록만 남기고 삭제.
- 고려했던 대안:
  1. 윈도우(Claude)와 맥(Gemini) 사이의 비교만 단독 수행 — 모델·도구·플랫폼이 함께 달라 에이전트 구조만의 순효과를 분리할 수 없으므로 기각 (해당 비교는 거시적 프로세스 비교인 ADR-0016으로 병행 운영).
- 결과:
  1. **측정 항목 (기능마다 AI 로그 기록)**:
     - 합격 테스트 통과 수 / 전체
     - 판정 리뷰 지적 수 (P1/P2/P3, 보안 확신도 8 이상)
     - 사람 개입 횟수
     - 토큰 사용량 및 소요 시간
     - 규칙 위반 건수 (RED 없는 구현, 웹 코드 열람, 테스트 임의 수정 등)
     - [서브만] 에이전트 간 재작업 횟수, "테스트 오류" 보고 수 / 실제 결함 수
  2. **한계**:
     - 실험 대상 기능 수가 3개로 표본 크기가 제한적이므로, 통계적 일반화보다는 정량적 지표를 동반한 엔지니어링 경향(Trend) 관찰에 초점을 맞춘다.
