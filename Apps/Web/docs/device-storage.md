# 웹 기기 저장 명세

웹 클라이언트가 공통 정책 [VLT-003](../../../docs/policies/VLT/VLT-003-device-vault-persistence.md)(기기 볼트 보존)과 [VLT-002](../../../docs/policies/VLT/VLT-002-offline-pending-sync.md)(오프라인 동기화 대기)를 브라우저에서 어떻게 지키는지 적은 구현 계약이다. 동작 규칙은 정책이 기준이며, 이 문서는 정책을 바꾸지 않는다.

## 1. 저장소

| 항목 | 값 |
| :--- | :--- |
| 저장소 | IndexedDB. localStorage는 문자열만 담고 용량 한도가 5MB 안팎이라 5MB 볼트를 담지 못할 수 있어 쓰지 않는다. |
| 데이터베이스 | 이름 `keymanage`, 버전 1 |
| 저장소(object store) | `device`, 키 `account` 하나 (기기에 한 계정만 둔다) |
| 포트 | `DeviceStore` (`src/domain/device/deviceRecord.ts`) |
| 어댑터 | `src/adapters/browser/indexedDbDeviceStore.ts` |

## 2. 기록 형식 (`DeviceRecord`, 버전 1)

| 필드 | 뜻 |
| :--- | :--- |
| `version` | 기록 형식 버전. 형식을 바꾸면 올리고 이전 기록을 옮기는 절차를 둔다. |
| `email` | 계정 이메일 |
| `kdf` | salt와 반복 횟수 |
| `payload` | 암호화된 마지막 볼트. 동기화 대기 중이면 대기 내용을 담은 볼트다. |
| `revision` | `payload`가 바탕으로 삼은 서버 revision |
| `lastSeenRevision` | 되돌림 감지 기준 |
| `pendingSync` | 동기화 대기 여부 |

- 비밀이 아니거나 암호화된 값만 담는다. 세션 토큰, 암호화 키, 인증 해시, 평문 볼트는 담지 않는다.
- 읽은 값은 믿지 않고 `parseDeviceRecord`로 확인한다.

## 3. 동작 계약

1. **열기 제한 시간:** 저장소 열기가 3초(`OPEN_TIMEOUT_MS`) 안에 끝나지 않거나 다른 탭 때문에 막히면 실패로 본다. 실패하면 로그인 화면에서 시작한다.
2. **읽지 못한 기록 재확인:** 클라이언트는 기기에 쓸 때마다 기록을 다시 읽는다(7번). 그래서 시작할 때 기록을 읽지 못했어도 대기 내용을 덮어쓰지 않는다 (VLT-003 규칙 6, ADR-WEB-001).
3. **쓰기 순서:** 기기 쓰기는 한 번에 하나씩 요청한 순서대로 한다(`src/domain/device/devicePersistence.ts`). 쓰기가 실패해도 메모리의 볼트는 그대로 쓰고, 다음 쓰기가 성공할 때까지 경고한다.
4. **떠남 확인:** 기기에 아직 저장하지 못한(쓰는 중이거나 실패한) 대기 내용이 있으면 `beforeunload`로 브라우저 기본 떠남 확인을 띄운다. 문구는 브라우저가 정한다(`src/app/pendingSyncWiring.ts`).
5. **재전송:** `online` 이벤트와 30초 간격으로 대기 내용을 다시 보낸다. 여러 탭이 열려 있으면 `navigator.locks`의 `keymanage-sync` 잠금을 `ifAvailable`로 얻은 탭 하나만 보낸다. 잠금을 얻지 못한 탭은 이번 차례를 건너뛴다.
6. **세션 토큰:** 세션 토큰은 기기에 두지 않는다. 새로고침이나 재시작 뒤에는 세션 없이 잠금 화면을 열고, SEC-003 규칙 10에 따라 인증 해시로 다시 로그인한다.
7. **탭 간 쓰기:** 기기 기록 쓰기는 `navigator.locks`의 `keymanage-device` 잠금 안에서만 한다. 잠금 안의 순서는 다음과 같다.
   1. 기록을 다시 읽고 `parseDeviceRecord`로 확인한다.
   2. 같은 계정의 기록이고 이 탭이 잠금 해제 상태이면, 기록의 볼트를 복호화해 메모리의 볼트와 `mergeVaults`로 합친다. 항목마다 최종 변경 시각(삭제 시각 포함)이 늦은 쪽을 고른다.
   3. 합친 내용이 한쪽과 같으면(그쪽이 다른 쪽 변경을 모두 담음) 그쪽의 암호문과 `pendingSync`를 그대로 쓴다. 그쪽이 서버와 맞춰졌으면 다른 쪽 변경도 이미 올라간 것이다. 같은 내용을 다시 암호화하지 않으므로 탭끼리 병합을 주고받으며 끝없이 쓰지 않는다.
   4. 둘 다 새 내용을 가졌으면 합친 볼트를 암호화해 쓰고, `pendingSync`는 둘 중 하나라도 대기면 대기로 둔다. `revision`과 `lastSeenRevision`은 어느 경우든 둘 중 높은 값을 쓴다. 합친 볼트가 메모리와 다르면 이 탭의 메모리와 화면도 바꾼다.
   - 잠긴 탭은 병합하지 못한다. 잠긴 탭은 읽은 기록이 자기가 마지막으로 읽거나 쓴 기록과 같을 때만 쓴다.
   - 서버 전송이 성공하면 잠금 안에서 기록을 다시 읽는다. 기록이 전송 직전에 병합한 값 그대로일 때만 `pendingSync`를 끈다. 그사이 다른 탭이 썼으면 다시 병합하고 대기로 둔다.
   - 기록이 없고 이 탭이 전에 기록을 읽거나 쓴 적이 있으면, 쓰지 않고 이 탭도 로그아웃한다. 처음 로그인해 기록이 없으면 그냥 쓴다.
   - 같은 이메일인데 KDF 값이 다르거나 복호화에 실패하면, 쓰지 않고 이 탭을 로그인 화면으로 보낸다(SEC-003 규칙 11).
   - 다른 계정의 기록이면 쓰지 않고 이 탭은 로그아웃한다.
   - 로그아웃의 기록 삭제와 다른 계정 인증 때의 이전 기록 삭제도 같은 잠금 안에서 한다.
8. **탭 간 알림:** 클라이언트는 `BroadcastChannel`의 `keymanage` 채널로 다른 탭에 알린다. 메시지에는 종류와 보낸 탭 식별자만 담는다. 키, 평문, 인증 해시, 세션 토큰, 이메일은 담지 않는다. 받은 탭은 모르는 형식을 버리고, 필요한 값을 IndexedDB에서 직접 읽는다.

   | 메시지 | 잠금 해제된 탭 | 잠긴 탭 | 로그인 전 탭 |
   | :--- | :--- | :--- | :--- |
   | `record-changed` (기록을 새로 씀) | 기록을 읽어 메모리 볼트와 병합하고 화면을 갱신한다 | 메모리의 암호화된 볼트와 revision을 기록 값으로 바꾼다 | 무시 |
   | `locked` (계정을 잠금) | 잠근다 | 그대로 | 무시 |
   | `logged-out` (로그아웃) | 로그아웃한다. 기기 기록은 지우지 않는다(보낸 탭이 지웠다) | 같다 | 무시 |
   | `activity` (사용자 조작) | 자동 잠금 타이머를 다시 시작한다 | 무시 | 무시 |

   - `activity`는 잠금 해제된 탭만 보낸다. 1초에 최대 한 번 보낸다.
9. **잠금 전파 범위:** 잠금 버튼, 보이는 탭의 자동 잠금 시간 초과, 로그아웃, 다른 계정 인증은 같은 계정의 모든 탭에 적용한다. 새로고침·탭 닫기·떠남·동결(`pagehide`, `freeze`), "즉시" 설정에서 탭이 숨겨짐, 숨겨졌다 돌아오거나 첫 조작에서 발견한 시간 초과는 그 탭만 잠근다 (SEC-003).
10. **로그아웃 확인:** 로그아웃 전 확인은 기기 기록의 `pendingSync`로 판단한다. 다른 탭이 쓰는 중이면 `keymanage-device` 잠금을 얻은 뒤 읽는다.
11. **탭 간 기능 미지원:** `navigator.locks`나 `BroadcastChannel`이 없으면, 탭 안에서만 쓰기를 직렬화하고 알림을 보내지 않는다. 이때는 4장의 탭 하나 전제가 적용된다.

## 4. 알려진 제약

- **미지원 브라우저의 탭 하나 전제:** `navigator.locks`나 `BroadcastChannel`이 없는 브라우저에서 같은 계정을 여러 탭에서 열면, 탭끼리 기록을 덮어써 한 탭의 대기 내용이 사라질 수 있다. 지원 범위는 Chrome·Edge·Firefox 최신, Safari 15.4 이상, Tauri 웹뷰(WebView2·WKWebView)다.
- **사생활 보호 모드·저장 공간 부족:** 쓰기가 실패할 수 있다. 이때는 VLT-003의 저장 실패 경고를 보인다.
