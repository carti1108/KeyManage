# 웹 기기 저장 명세

웹 클라이언트가 공통 정책 [VLT-003](../../../docs/policies/VLT/VLT-003-device-vault-persistence.md)(기기 볼트 보존)과 [VLT-002](../../../docs/policies/VLT/VLT-002-offline-pending-sync.md)(오프라인 동기화 대기)를 브라우저에서 어떻게 지키는지 적은 구현 계약이다. 동작 규칙은 정책이 기준이며, 이 문서는 정책을 바꾸지 않는다.

## 1. 저장소

| 항목 | 값 |
| :--- | :--- |
| 저장소 | IndexedDB. localStorage는 문자열만 담고 용량 한도가 5MB 안팎이라 5MB 볼트를 담지 못할 수 있어 쓰지 않는다. |
| 데이터베이스 | 이름 `keymanage`, 버전 1 |
| 저장소(object store) | `device`, 키 `account` 하나 (기기에 한 계정만 둔다) |
| 포트 | `DeviceStore` (`src/domain/device/deviceRecord.ts`) |
| 어댑터 | `src/adapters/browser/indexedDbDeviceStore.ts` |

## 2. 기록 형식 (`DeviceRecord`, 버전 1)

| 필드 | 뜻 |
| :--- | :--- |
| `version` | 기록 형식 버전. 형식을 바꾸면 올리고 이전 기록을 옮기는 절차를 둔다. |
| `email` | 계정 이메일 |
| `kdf` | salt와 반복 횟수 |
| `payload` | 암호화된 마지막 볼트. 동기화 대기 중이면 대기 내용을 담은 볼트다. |
| `revision` | `payload`가 바탕으로 삼은 서버 revision |
| `lastSeenRevision` | 되돌림 감지 기준 |
| `pendingSync` | 동기화 대기 여부 |

- 비밀이 아니거나 암호화된 값만 담는다. 세션 토큰, 암호화 키, 인증 해시, 평문 볼트는 담지 않는다.
- 읽은 값은 믿지 않고 `parseDeviceRecord`로 확인한다.

## 3. 동작 계약

1. **열기 제한 시간:** 저장소 열기가 3초(`OPEN_TIMEOUT_MS`) 안에 끝나지 않거나 다른 탭 때문에 막히면 실패로 본다. 실패하면 로그인 화면에서 시작한다.
2. **읽지 못한 기록 재확인:** 시작할 때 기록을 읽지 못했으면, 로그인한 뒤 기기에 처음 쓰기 전에 다시 읽는다 (VLT-003 규칙 6).
3. **쓰기 순서:** 기기 쓰기는 한 번에 하나씩 요청한 순서대로 한다(`src/domain/device/devicePersistence.ts`). 쓰기가 실패해도 메모리의 볼트는 그대로 쓰고, 다음 쓰기가 성공할 때까지 경고한다.
4. **떠남 확인:** 기기에 아직 저장하지 못한(쓰는 중이거나 실패한) 대기 내용이 있으면 `beforeunload`로 브라우저 기본 떠남 확인을 띄운다. 문구는 브라우저가 정한다(`src/app/pendingSyncWiring.ts`).
5. **재전송:** `online` 이벤트와 30초 간격으로 대기 내용을 다시 보낸다.
6. **세션 토큰:** 세션 토큰은 기기에 두지 않는다. 새로고침이나 재시작 뒤에는 세션 없이 잠금 화면을 열고, SEC-003 규칙 10에 따라 인증 해시로 다시 로그인한다.

## 4. 알려진 제약

- **탭 하나 전제:** 같은 계정을 여러 탭에서 열면 탭끼리 기록을 덮어써 한 탭의 대기 내용이 사라질 수 있다. 탭 간 잠금은 후속 과제(#65)다.
- **사생활 보호 모드·저장 공간 부족:** 쓰기가 실패할 수 있다. 이때는 VLT-003의 저장 실패 경고를 보인다.
