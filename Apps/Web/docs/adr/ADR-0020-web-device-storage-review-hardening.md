### ADR-0020 웹 기기 저장: 다른 계정 인증 시 이전 기록 삭제, KDF 변경에도 되돌림 검사 유지, 읽지 못한 기록 재확인
- 상태: 일부 대체됨 (결정 3·6 → ADR-WEB-001)
- 날짜: 2026-11-01
- 배경: ADR-0019는 웹 기기 저장 범위를 정했다. 구현(PR #66)의 독립 보안 리뷰와 코드 리뷰에서 ADR-0019의 결정만으로는 막지 못하는 경로가 나왔다.
  1. 다른 계정으로 바꿀 때 새 계정의 볼트를 준비하지 못하거나 기기 쓰기가 실패하면, 이전 계정의 이메일과 암호화된 볼트가 기기에 남는다.
  2. "KDF 값이 바뀌면 기기 사본을 버리고 서버 볼트로 연다"는 결정을 그대로 구현하면, 서버가 salt만 바꿔도 되돌림 감지가 꺼진다. 그러면 서버 쪽 유실을 정상처럼 보이게 하고 기기에 남은 유일한 사본까지 덮어쓸 수 있다.
  3. 앱을 열 때 기기 기록을 읽지 못하면(열기 시간 초과 등) 로그인 화면으로 간다. 이때 같은 계정으로 로그인하면 기기에만 있던 대기 내용이 서버 볼트로 덮어써진다.
  4. 세션 없이 잠금을 풀 때 서버가 인증 실패가 아닌 이유(출처 거부 등)로 거절하면, 비밀번호를 이 기기에서 확인했는데도 볼트가 열리지 않는다. 다시 입력할 때도 실제 사유 대신 "연결할 수 없음"만 보인다.
- 결정: ADR-0019의 결정을 모두 이어받고 다음을 바꾸거나 더한다.
  1. 다른 계정의 인증(로그인·가입)이 성공하면, 그 계정의 볼트를 열기 전이라도 이전 계정의 기록을 먼저 지운다. 인증에 실패하면 지우지 않는다. (ADR-0019 결정 2를 바꾼다)
  2. 같은 이메일로 로그인할 때 서버 KDF 값이 저장한 값과 다르면 옛 키로 암호화된 대기 내용은 버린다. 되돌림 감지 기준은 지우지 않고 검사를 그대로 하며, 기기 사본은 볼트를 연 뒤에야 새 기록으로 바뀐다. 실제 비밀번호 변경은 볼트를 다시 암호화해 저장하므로 revision이 올라가 이 검사를 통과한다. (ADR-0019 결정 5를 바꾼다)
  3. 앱을 열 때 기기 기록을 읽지 못했으면, 로그인한 뒤 기기에 처음 쓰기 전에 기록을 다시 읽는다. 같은 계정의 대기 내용이 있으면 병합해 올리고, 다른 계정의 기록이면 결정 1에 따라 지운다.
  4. 세션 없이 잠금을 풀 때 서버가 인증 실패가 아닌 이유로 거절하면 볼트는 세션 없이 열고 그 사유를 알린다. 비밀번호를 다시 입력해도 로그인하지 못하면 실제 사유(연결 실패, 서버 오류, 거절)를 보여 준다.
  5. 기기 저장소 열기가 막히거나 3초 안에 끝나지 않으면 실패로 본다.
  6. 웹 기기 기록은 탭 하나를 전제로 한다. 같은 계정을 여러 탭에서 열면 기록을 서로 덮어쓸 수 있으며, 탭 간 잠금은 후속 과제(#65)로 둔다.
- 고려했던 대안:
  1. 이전 계정 기록은 새 계정의 볼트를 연 뒤에 덮어쓴다(ADR-0019 원안). 쓰기 실패나 볼트 준비 실패 때 이전 계정의 볼트가 공용 기기에 남아서 기각했다.
  2. KDF 값이 바뀌면 되돌림 기준을 지운다. 서버가 salt만 바꿔 되돌림 감지를 피하고 기기 사본을 지울 수 있어서 기각했다.
  3. 기기 기록을 읽지 못하면 로그인 대신 "다시 시도" 화면을 보인다. 사용자 조작이 늘고, 계속 읽지 못하는 기기에서는 앱을 쓸 수 없어서 기각했다(사용자 선택).
  4. 세션 없이 잠금을 풀다 서버가 거절하면 볼트도 열지 않는다. 비밀번호를 이미 이 기기에서 확인했으므로 이 기기의 볼트를 막을 이유가 없어서 기각했다.
- 결과:
  - 얻는 것: 계정을 바꿀 때 공용 기기에 이전 계정의 볼트가 남지 않는다. 서버가 KDF 값을 바꿔도 되돌림 경고를 피하지 못한다. 기기 기록을 늦게 읽어도 대기 내용을 잃지 않는다. 동기화하지 못하는 실제 이유를 사용자가 알 수 있다.
  - 비용: 다른 계정의 인증은 성공했지만 볼트를 준비하지 못하면, 이전 계정의 기기 기록이 이미 지워져 있다. 이전 계정의 대기 내용은 그 탭의 메모리에만 남고 새로고침하면 사라진다. 실제 비밀번호 변경 기능을 만들 때는 다시 암호화한 볼트를 revision을 올려 저장해야 한다.
- 관련: ADR-0019(대체), VLT-001, SEC-003, PR #66, 이슈 #64, 이슈 #65
