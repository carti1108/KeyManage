### ADR-0012 데스크톱 앱 틀로 Tauri v2, 웹 클라이언트는 Vite + React 정적 앱 채택
- 상태: 채택
- 날짜: 2026-10-29
- 배경: ADR-0010은 웹 클라이언트 하나를 브라우저와 데스크톱 앱이 함께 쓰기로 하고 데스크톱 앱 틀(Tauri 또는 Electron) 선택을 미뤘다. 이후 브라우저보다 데스크톱 앱을 주로 쓰는 방향이 정해졌다. 패스워드 매니저는 클립보드 자동 삭제(COM-001)처럼 브라우저 탭에서는 완전히 보장할 수 없는 기능이 있고, 공격받을 수 있는 면을 줄이는 것이 중요하다.
- 결정: (1) 데스크톱 앱 틀은 Tauri v2를 쓴다. (2) 웹 클라이언트는 서버 렌더링 없는 정적 앱으로 Vite + React + TypeScript + Tailwind CSS(+ shadcn/ui)로 만들고, 테스트는 Vitest로 한다. (3) 클립보드·안전한 저장소 같은 플랫폼 기능은 포트로 분리해 브라우저용과 Tauri용 구현을 갈아 끼운다(ADR-0004). (4) Tauri 틀은 화면이 어느 정도 만들어진 뒤 별도 작업으로 붙인다.
- 고려했던 대안: (1) Electron — 레퍼런스가 많고 Node만 있으면 되지만 Chromium을 통째로 담아 무겁고, Node 런타임 때문에 보안 설정에 더 신경 써야 해 기각. (2) Next.js 정적 내보내기 — 서버 기능을 꺼서 쓰는 셈이라 구조가 과하고 데스크톱에 담을 이점이 없어 기각. (3) 브라우저 전용 — 클립보드 자동 삭제를 완전히 보장할 수 없고 주 사용 형태와 맞지 않아 기각.
- 결과: 앱이 가볍고 권한을 기능 단위로 제한할 수 있으며, 클립보드를 네이티브로 제어해 COM-001을 데스크톱에서 그대로 지킬 수 있다. 반면 빌드에 Rust와 플랫폼 빌드 도구(Windows는 Visual Studio C++ 빌드 도구)가 필요하고, OS마다 내장 웹뷰가 달라 렌더링이 조금씩 다를 수 있다. 브라우저에서는 클립보드 제약이 남는다.
- 관련: ADR-0004, ADR-0010, COM-001, 이슈 #28
