### ADR-WEB-002 웹 자동 잠금 시간 설정은 localStorage 키 하나에 기기별로 저장하고, `storage` 이벤트로 다른 탭에 반영한다
- 상태: 채택
- 날짜: 2026-11-01
- 영역: 웹

> **요약** 자동 잠금 시간은 localStorage의 `keymanage.autoLockMs` 키 하나에 밀리초 문자열로 저장한다. 읽을 때 선택지인지 검사하고, 아니면 기본 5분을 쓴다. 다른 탭은 `storage` 이벤트를 받아 새 시간으로 다시 잰다.

#### 배경

SEC-003은 자동 잠금 시간을 기기마다 저장하고 서버·다른 기기와 동기화하지 않으며, 로그아웃·계정 전환 뒤에도 남긴다고 정했다. 지금 웹은 `App.tsx`에서 기본 5분을 고정으로 넘긴다.

#### 결정

1. **저장소는 localStorage 키 하나다.** 키는 `keymanage.autoLockMs`이고, 값은 선택지(`AUTO_LOCK_OPTIONS_MS`) 중 하나의 밀리초 문자열이다.
2. **읽을 때 검사한다.** 값이 없거나 숫자가 아니거나 선택지가 아니면 기본 5분을 쓴다. 저장소에 접근할 수 없을 때(예외)도 5분이다. 그래서 "잠그지 않음"은 만들어지지 않는다.
3. **저장 실패는 이번 실행에만 적용한다.** 쓰기에 실패하면 이 탭의 메모리 값으로만 쓰고 따로 안내하지 않는다.
4. **바꾸면 새 시간으로 다시 잰다.** 바꾼 탭은 그 순간부터, 다른 탭은 `storage` 이벤트를 받은 순간부터 새 시간으로 잰다.
5. **계정과 묶지 않는다.** 로그아웃·계정 전환 때 이 키는 지우지 않는다. IndexedDB 기기 기록과는 따로다.
6. **계층.** localStorage 접근은 `src/adapters/browser/`에만 둔다. 도메인에는 저장소 인터페이스와 값 검증만 둔다.

#### 고려했던 대안

| 대안 | 고르지 않은 이유 |
| :--- | :--- |
| IndexedDB 기기 기록(`DeviceRecord`)에 필드 추가 | 기기 기록은 계정 하나의 기록이라 로그아웃·계정 전환 때 지워져 SEC-003의 "설정 유지"와 맞지 않는다. 저장 형식 버전도 올려야 한다. |
| IndexedDB에 별도 저장소 추가 | 읽기가 비동기라 시작할 때 기다려야 하고, 탭 간 반영을 BroadcastChannel로 따로 알려야 한다. 값 하나에 비해 복잡하다. |
| 서버(계정 설정)에 저장해 동기화 | SEC-003의 기기별 저장과 맞지 않고, 서버 API·스키마를 바꿔야 한다. |

#### 결과

- 장점: 동기로 읽어 시작할 때 바로 적용한다. 탭 간 반영은 브라우저의 `storage` 이벤트가 맡는다. 데스크톱 앱(Tauri)도 앱마다 따로 유지된다.
- 비용: 기기에 접근할 수 있는 사람이 값을 바꿀 수 있다. 선택지 밖의 값은 무시되고 비밀 정보가 아니므로 영지식 경계에는 영향이 없다. 개인정보 보호 모드에서는 창을 닫으면 사라져 5분으로 돌아간다.
