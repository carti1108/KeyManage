# SEC-005 계정 삭제 정책
- 상태: 확정
- 적용 범위: 모든 클라이언트(iOS/macOS, Android, Web)와 백엔드

> **요약** 사용자는 마스터 비밀번호와 확인 문구를 입력해 계정을 삭제할 수 있다. 서버는 계정, 볼트, 세션을 즉시 지우고 되돌리지 않는다. 클라이언트는 이 기기의 기록을 지우고 모든 창을 로그아웃한다.

## 규칙

> **주의** 삭제는 되돌릴 수 없다. 서버에도 볼트를 복구할 방법이 없다.

1. 계정 삭제는 잠금이 풀린 볼트에서, 서버에 연결된 상태에서만 한다. 읽기 전용 볼트에서도 할 수 있다.
2. 클라이언트는 삭제 전에 되돌릴 수 없다는 안내와 백업 권유를 보이고, 마스터 비밀번호와 확인 문구 `계정 삭제`를 입력받는다. 확인 문구가 정확히 같아야 삭제 버튼이 켜진다.
3. 클라이언트는 입력한 비밀번호로 인증 해시를 만들어 보낸다. 서버는 인증 해시를 확인하고, 로그인과 같은 시도 제한(SEC-002)을 적용한다.
4. 서버는 확인되면 계정을 즉시 지운다. 계정이 지워진 순간이 삭제 확정이다. 이어서 그 계정의 볼트와 세션을 모두 지운다. 볼트를 지우지 못해도 어느 계정도 가리키지 않는 볼트는 서버가 정리한다.
5. 삭제가 끝나면 클라이언트는 이 기기의 기록(VLT-003)을 지우고, 같은 기기의 다른 창·탭도 로그아웃하고, 로그인 화면에 완료 안내를 보인다. 자동 잠금 시간 같은 기기 설정은 남긴다.
6. 다른 기기는 다음 요청에서 세션 만료를 받고 로그인 화면으로 간다. 그 기기에서 아직 올리지 못한 변경은 버린다.
7. 같은 이메일로 바로 다시 가입할 수 있다.
8. 내보낸 백업 파일은 삭제와 관계없이 남고, 새 계정에서 그 파일의 비밀번호로 복원할 수 있다(VLT-004).

## 값

| 항목 | 값 | 경계·비고 |
| :--- | :--- | :--- |
| 삭제 시점 | 즉시 | 유예 기간 없음 |
| 확인 문구 | `계정 삭제` | 앞뒤 공백을 포함해 정확히 같아야 한다. |

## 예외

1. 다른 기기에서 지워진 계정으로 로그인하면 서버는 계정 존재 여부를 드러내지 않으므로(SEC-002), 비밀번호가 바뀐 경우와 같은 안내(SEC-003 규칙 11)를 받는다.
2. 응답을 받지 못하면 클라이언트는 결과를 알 수 없다. 다음 요청의 세션 만료 흐름을 따른다.

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 서버 테스트 | 인증 해시가 맞으면 계정·볼트·세션 모두 삭제; 틀리면 아무것도 지우지 않음과 시도 제한; 삭제 뒤 그 계정의 토큰은 401; 볼트 삭제 실패 시에도 계정 삭제는 확정되고 남은 볼트는 정리; 삭제 뒤 같은 이메일 재가입 가능 |
| 클라이언트 테스트 | 확인 문구가 정확할 때만 삭제 버튼 활성; 오프라인에서 막음; 비밀번호 틀림 문구; 완료 뒤 기기 기록 삭제와 다른 창 로그아웃, 로그인 화면 완료 안내; 기기 기록 삭제 실패 안내; 다른 기기에서 삭제된 뒤 세션 만료 |
