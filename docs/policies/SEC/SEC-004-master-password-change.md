# SEC-004 마스터 비밀번호 변경 정책
- 상태: 확정
- 적용 범위: 모든 클라이언트(iOS/macOS, Android, Web)와 백엔드

> **요약** 사용자는 현재 마스터 비밀번호를 확인받은 뒤 새 비밀번호로 바꿀 수 있다. 클라이언트가 새 키로 볼트를 다시 암호화하고, 서버는 인증 정보와 볼트를 한 번에 교체한 뒤 다른 기기의 세션을 모두 끝낸다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 키 교체 | 새 salt로 새 마스터 키를 만들고, 그 키로 볼트를 다시 암호화하고 인증 해시를 바꾸는 것 |

## 규칙

> **주의** 서버에서 인증 정보와 볼트 중 하나만 바뀌면 그 계정은 볼트를 열 수 없게 된다. 교체는 전부 되거나 전부 안 되어야 한다.

1. 마스터 비밀번호 변경은 잠금이 풀린 볼트에서, 서버에 연결된 상태에서만 한다. 읽기 전용 볼트(VLT-001)에서는 하지 않는다.
2. 클라이언트는 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력받는다. 새 비밀번호는 SEC-002의 규칙을 따르고 현재 비밀번호와 달라야 한다.
3. 바꾸기 전에 다른 기기와 옛 백업에 미치는 영향을 안내한다.
4. 클라이언트는 새 salt(16바이트)를 만들고 반복 횟수는 현재 값을 유지해 새 키를 만든다(SEC-001). 화면의 볼트(동기화 대기 중인 변경 포함)를 새 키로 다시 암호화하고 새 인증 해시를 만든다.
5. 서버는 현재 인증 해시를 확인한 뒤 KDF 값, 인증 해시, 볼트를 한 번에 교체한다. 그 사이 볼트가 바뀌었으면(revision 불일치) 아무것도 바꾸지 않고 충돌로 거절한다.
6. 현재 인증 해시 확인에는 로그인과 같은 시도 제한(SEC-002)을 적용한다.
7. 교체가 끝나면 서버는 그 계정의 세션을 모두 끝내고, 바꾼 기기에만 새 세션 토큰을 준다. 교체 전에 발급된 세션은 교체와 겹쳐 발급됐더라도 무효다. 교체는 확정됐지만 새 토큰을 주지 못하면 세션 만료로 응답하고, 클라이언트는 새 비밀번호로 로그인한다.
8. 다른 기기는 다음 요청에서 세션 만료를 받고, 로그인할 때 KDF 값이 바뀐 것을 알아 비밀번호가 바뀌었다고 안내한다(SEC-003 규칙 11). 그 기기에서 아직 올리지 못한 변경은 버린다(VLT-003). 같은 기기의 다른 창·탭도 다른 기기와 같이 다룬다.
9. 응답을 받지 못하면 클라이언트는 결과를 알 수 없다. 별도 처리 없이 다음 요청의 세션 만료와 규칙 8의 흐름을 따른다.
10. 옛 백업 파일은 옛 비밀번호로 연다(VLT-004).

## 값

| 항목 | 값 | 경계·비고 |
| :--- | :--- | :--- |
| 새 salt | 16바이트 난수 | 클라이언트가 만든다. |
| 반복 횟수 | 현재 계정 값 유지 | SEC-001·SEC-002 범위(600,000~10,000,000) |
| 새 비밀번호 | SEC-002와 같음 | 현재 비밀번호와 같으면 거절 |

## 예외

1. 마스터 비밀번호를 잊은 경우의 재설정은 없다. 영지식 구조라 서버도 볼트를 열 수 없다.

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 서버 테스트 | 현재 인증 해시가 맞으면 KDF 값·인증 해시·볼트를 함께 교체; 틀리면 아무것도 바꾸지 않음과 시도 제한; revision 불일치 시 거절하고 아무것도 바꾸지 않음; 교체 중 실패하면 옛 계정과 볼트가 그대로; 다른 세션 모두 폐기와 새 토큰 발급; 교체 뒤 새 인증 해시로만 로그인 |
| 클라이언트 테스트 | 새 비밀번호 규칙과 현재와 같음 거절; 오프라인·읽기 전용에서 막음; 대기 변경까지 새 키로 암호화; 현재 비밀번호 틀림·충돌·완료 문구; 완료 뒤 새 비밀번호로 잠금 해제; 다른 기기에서 바뀐 뒤 비밀번호 바뀜 안내 |
