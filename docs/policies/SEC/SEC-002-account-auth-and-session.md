# SEC-002 계정 인증 및 세션 정책
- 상태: 확정
- 적용 범위: 모든 클라이언트(iOS/macOS, Android, Web)의 키 유도·로그인 화면, 백엔드 인증 API와 볼트 API 접근 제어

> **요약** 클라이언트는 인증 해시만 보내고, 서버는 세션 토큰으로 계정 볼트 접근을 지킨다. 로그인 실패는 이메일 존재 여부를 드러내지 않는다.

## 규칙

> **주의** 인증 해시와 토큰 원문이 로그에 남으면 계정을 빼앗길 수 있다.

1. 클라이언트는 마스터 키에서 HKDF로 분리한 인증 해시만 서버로 보낸다. 서버는 이를 Argon2id로 다시 해시해 저장한다.
2. 로그인에 성공하면, 서버는 서버 저장형 세션 토큰을 발급한다. 볼트 API는 유효한 토큰의 계정 볼트에만 접근을 허용한다.
3. 로그인에 실패하면, 서버는 이메일 존재 여부를 응답 내용이나 응답 시간으로 드러내지 않는다.
4. 서버는 계정 단위와 IP 단위로 로그인 시도를 제한한다.
5. 클라이언트는 `localhost`·`127.0.0.1`이 아닌 서버에는 HTTPS로만 접속한다.
6. 인증 해시와 토큰 원문은 로그에 남기지 않는다.
7. 가입할 때 마스터 비밀번호는 최소 길이를 넘고 확인 입력과 같아야 한다. 서버는 마스터 비밀번호를 볼 수 없으므로 이 검사는 클라이언트가 한다.

## 값

| 항목 | 값 | 경계·비고 |
| :--- | :--- | :--- |
| 마스터 비밀번호 | 최소 12자 | 유니코드 코드포인트 수로 세고 앞뒤 공백도 그대로 센다. 최대 길이 제한은 없다. 가입할 때만 검사하고 기존 계정 로그인은 막지 않는다. |
| KDF | PBKDF2-HMAC-SHA256 600,000회 | 가입할 때 600,000 이상을 허용한다. 클라이언트는 10,000,000을 넘는 값을 거절해 기기가 오래 멈추지 않게 한다. |
| 계정 salt | 16바이트 | |
| HKDF | HKDF-SHA256, info "keymanage-enc"·"keymanage-auth", 출력 32바이트 | |
| 서버 해시 | Argon2id(메모리 19MiB, 반복 2, 병렬도 1) | |
| 세션 토큰 | 256비트, 유효 30일 | 연장 없음. 서버에는 SHA-256 해시만 저장한다. |
| 계정당 로그인 실패 | 15분 안에 5회 | 15분 잠금. 성공하면 초기화. |
| IP당 요청 | 1분에 30회 | 넘으면 거절. 가입·로그인·prelogin 합산. |
| 이메일 | 최대 254자 | 앞뒤 공백 제거, 소문자 |
| 서버 비밀키(가짜 salt용 HMAC 키) | 32바이트 | 환경 변수 `KEYMANAGE_SERVER_SECRET`이 있으면 그 값을 쓰고, 없으면 첫 실행 때 만들어 데이터 폴더에 보관한다. |
| 가입 허용 설정 | `keymanage.auth.registration-enabled` | 기본 true |
| 신뢰 프록시 설정 | `keymanage.http.trusted-proxies` | 기본 비어 있음. 비어 있으면 `X-Forwarded-For`를 무시하고 접속 IP를 쓴다. |

## 예외

1. prelogin·가입·로그인 요청만 토큰 없이 호출할 수 있다.

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 서버 단위 테스트 | 없는 이메일의 prelogin이 같은 이메일에 항상 같은 salt를 돌려줌; 틀린 인증 해시와 없는 이메일이 같은 401; 5회 실패 후 잠금과 성공 시 초기화; 동시 가입은 1건만 성공; 만료·폐기된 토큰은 401; 로그아웃은 멱등; 다른 계정 볼트에 접근 불가; 가입이 꺼지면 403; 신뢰하지 않는 프록시의 `X-Forwarded-For` 무시 |
| 클라이언트 테스트 | 11자·확인 불일치 가입을 막고 12자는 허용 |
| 로그 확인 | 인증 해시·토큰 원문이 없음 |
