# KeyManage 미결정 및 검토 필요 사항 (Open Questions)

현재 검토 중이거나 합의되지 않은 정책 후보 목록입니다. 결정이 완료되면 해당 정책에 반영하고 이 문서에서 정리합니다.

* **사전 패턴·재사용 비밀번호 진단 기준 (GEN 영역, 예정)**: 제거된 api-spec 2.2에 있던 흔한 비밀번호 패턴 감지(예: `password!`), 볼트 내 중복 사용 감지, 마스킹 형식, 경고 문구를 클라이언트 진단에서 어떻게 정할지 미정. 클라이언트 진단 화면 구현 전에 정책으로 확정한다.
* **삭제 표시 항목의 영구 삭제 시점 (VLT 영역, 예정)**: `deletedAt`이 기록된 항목을 볼트에서 언제 완전히 제거할지(보존 기간, 모든 기기 동기화 확인 방법) 미정. 볼트 용량(5MB) 관리와 함께 클라이언트 동기화 구현 전에 확정한다.
* **기존 기기 승인으로 새 기기 추가 (SEC 영역, 후속)**: 이미 로그인된 기기가 새 기기를 승인해 키를 넘겨주는 방식(애플 iCloud 키체인의 신뢰 기기 방식 참고). 2단계 인증·기기 관리와 함께 검토한다 (ADR-0008).
* **마스터 비밀번호 변경 (SEC 영역, 후속)**: 마스터 키가 바뀌면 인증 해시 갱신과 볼트 재암호화가 함께 필요하다. 절차와 실패 시 복구 방법 미정.
* **이메일 인증 (SEC 영역, 후속)**: 가입 이메일 소유 확인 여부와 방법 미정. 현재 목표(포트폴리오·시연)에서는 하지 않는다.
* **2단계 인증 (SEC 영역, 후속)**: TOTP 등 추가 인증 수단 도입 여부 미정.
* **배포 방식 (운영, 후속)**: 직접 운영·셀프 호스팅(오픈소스)·시연 전용 중 실제 배포 방식과 라이선스, Docker 제공 여부는 백엔드 완성 후 ADR로 정한다.
