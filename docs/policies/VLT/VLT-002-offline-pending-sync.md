# VLT-002 오프라인 동기화 대기 및 재전송 정책
- 상태: 확정
- 적용 범위: 모든 클라이언트(iOS/macOS, Android, Web)

> **요약** 서버에 닿지 못한 저장은 동기화 대기로 두고 성공으로 처리한다. 대기 내용은 재연결, 30초 간격, 잠금 해제 때 다시 보낸다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 동기화 대기 | 서버에 올리지 못한 변경 사항을 로컬에 두고 나중에 다시 보내는 상태 |
| 대기 내용 | 동기화 대기 중인 변경 사항 |
| 분명한 거절 | 다시 보내도 서버가 받지 않는 실패: 용량 초과, 읽기 전용, 형식 오류, 되돌림 감지 |

## 규칙

> **주의** 대기 내용은 아직 서버에 없다. 대기 내용을 버리는 경우(다른 계정 로그인, 서버가 받을 수 없는 내용)에는 변경 사항이 사라진다.

1. 오프라인이면, 클라이언트는 로컬 볼트를 쓰고 화면 상단에 미동기화 경고를 보인다.
2. 저장이 다음 이유로 실패하면, 클라이언트는 변경 사항을 동기화 대기로 로컬에 두고 저장은 성공으로 처리한다: 네트워크 오류, 요청 시간 초과, 서버 5xx, 요청 제한(429), 응답 형식 오류.
3. 분명한 거절(용량 초과, 읽기 전용, 형식 오류, 되돌림 감지)만 오류로 알린다.
4. 저장 응답의 revision이 기대값과 다르면, 클라이언트는 서버 규약 위반으로 보고 대기로 숨기지 않는다.
5. 대기 중에 다시 고치면, 클라이언트는 대기 내용 위에 쌓는다. 기준 revision은 마지막으로 서버와 맞춘 값을 쓴다.
6. 클라이언트는 네트워크가 다시 연결되면 즉시, 대기 중 일정 간격마다, 잠금 해제 직후에 대기 내용을 다시 보낸다. 충돌하면 VLT-001의 병합 절차를 따른다.
7. 다시 보내다 충돌이 아닌 분명한 거절을 받으면, 클라이언트는 알린다. 그 뒤로는 사용자가 저장하거나, 잠금을 풀거나, 다시 로그인할 때까지 자동으로 다시 보내지 않는다.
8. 잠금 해제 직후에는, 대기 내용이 있어도 클라이언트는 서버 볼트를 먼저 받아 되돌림을 검사한다.
9. 잠겨도 대기 내용은 암호화해 남긴다. 잠금을 풀면 서버 볼트로 덮어쓰지 않고 병합해 올린다.
10. 세션이 만료(401)되면, 클라이언트는 로그인 화면으로 보낸다.
    - 같은 계정으로 다시 로그인하면 대기 내용을 병합해 올린다.
    - 다른 계정의 로그인이 성공하면 대기 내용을 버린다. 로그인 실패로는 버리지 않는다.
    - 다시 로그인할 때 올리기가 충돌·되돌림으로 실패하면 로그인을 실패시키고 대기 내용을 남긴다.
    - 서버가 받을 수 없는 대기 내용(읽기 전용, 용량 초과 등)이면 서버 볼트로 열고 대기 내용을 버린 뒤 그 오류를 알린다.
11. 대기 중에 사용자가 로그아웃하면, 클라이언트는 확인을 받는다. 잠금 화면에서 로그아웃할 때도 같다.
12. 기기에 저장하지 못한 대기 내용이 있는 채로 앱을 닫거나 다시 불러오려 하면, 플랫폼이 허용하는 경우 클라이언트는 떠남 확인을 띄운다.

## 값

| 항목 | 값 | 경계·비고 |
| :--- | :--- | :--- |
| 대기 재전송 간격 | 30초 | 대기 중일 때만. 재연결 이벤트와 별개 |

## 예외

1. 재연결했을 때 서버 revision이 앞서 있으면, VLT-001의 충돌 처리 절차를 따른다.
2. 대기 내용을 다시 보내다 자동 재시도 3회가 모두 충돌하면, 클라이언트는 VLT-001의 충돌 문구를 보인다. 대기 내용은 남겨 다음 재전송 때 다시 시도한다.
