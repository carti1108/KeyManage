# VLT-004 암호화 백업 내보내기와 복원 정책
- 상태: 확정
- 적용 범위: 모든 클라이언트(iOS/macOS, Android, Web)

> **요약** 사용자는 볼트를 암호화된 백업 파일로 내보내고, 그 파일로 백업에 있던 항목을 백업 시점 내용으로 되돌릴 수 있다. 백업 뒤에 새로 만든 항목은 남긴다. 파일은 내보낸 시점의 마스터 비밀번호로 잠기며, 모든 처리는 클라이언트 안에서만 한다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 백업 파일 | 볼트를 암호화한 내용과 그 키를 만드는 데 쓴 KDF 값(salt, 반복 횟수)을 담은 파일. 형식은 [vault-spec.md](../../vault-spec.md) 6장 |

## 규칙

> **주의** 평문 볼트는 기기 밖으로 나가지 않는다. 백업 파일에는 암호문만 담는다.

1. 내보내기와 복원은 잠금이 풀린 볼트 화면에서만 한다.
2. 내보내면, 클라이언트는 화면에 보이는 볼트(동기화 대기 중인 변경 포함)를 지금 키로 새로 암호화하고 현재 계정의 KDF 값과 함께 파일로 저장한다.
3. 백업 파일에는 이메일 등 계정 정보를 넣지 않는다.
4. 내보내기 전에는 파일을 여는 비밀번호에 대한 안내를 보인다. 마스터 비밀번호를 다시 묻지 않는다.
5. 복원하면, 클라이언트는 파일의 비밀번호를 입력받아 파일의 KDF 값으로 키를 만들고 복호화한다. 다른 계정의 백업도 비밀번호가 맞으면 복원한다.
6. 복원하면, 백업에서 지워지지 않은 항목은 백업 시점 내용으로 되돌린다. 백업 뒤에 고친 항목은 백업 내용으로 돌아가고, 지운 항목은 되살아난다. 되돌린 항목의 수정 시각은 복원한 시각으로 정하되 지금 항목의 마지막 변경 시각이 더 늦으면 그보다 1초 뒤로 정해, 다른 기기와 병합할 때도 복원한 내용이 남게 한다.
7. 복원은 아무것도 지우지 않는다. 백업 뒤에 새로 만든 항목과 백업에서 지워진 상태인 항목은 지금 상태 그대로 둔다. 지금 내용이 백업과 같은 항목은 건드리지 않는다.
8. 복원을 실행하기 전에 되돌아가는 범위에 대한 안내를 보인다.
9. 복원 결과는 일반 수정처럼 저장한다. 서버에 닿지 못하면 동기화 대기로 둔다(VLT-002).
10. 읽기 전용 볼트(VLT-001)에는 복원하지 않는다. 내보내기는 한다.
11. 내보내기·복원 내용과 결과는 서버에 보내거나 남기지 않는다.

## 값

| 항목 | 값 | 경계·비고 |
| :--- | :--- | :--- |
| 크기 | `vault` 필드 5MB 이하, 파일 전체는 5MB + 64KB 이하 | `vault` 필드는 압축 JSON으로 다시 직렬화한 크기에 볼트 한도(VLT-001)를 적용한다. 머리 필드·들여쓰기 몫으로 파일 전체에 64KB 여유를 둔다. 넘으면 형식 오류로 거절한다. |
| 파일 이름 | `keymanage-backup-YYYYMMDD.json` | 날짜는 내보낸 기기의 현지 날짜 |
| 키 유도 | 파일의 KDF 값 | SEC-001의 반복 횟수·salt 검증을 그대로 적용한다. |

## 예외

1. 백업 파일의 볼트 스키마 버전이 앱이 아는 버전보다 높으면 복원하지 않는다.
2. 복원 결과가 볼트 한도를 넘으면 저장 실패로 처리한다(VLT-001 문구).
3. 복호화는 됐지만 볼트 내용이 규격에 맞지 않으면 VLT-001의 볼트 형식 오류 문구를 쓴다.
4. 읽기 전용 볼트에서 내보낸 파일은 그 스키마 버전을 아는 앱에서만 복원된다(예외 1).
5. 복원은 이 기기가 이미 받은 볼트를 기준으로 한다. 다른 기기에서 아직 동기화되지 않은 변경(백업 뒤의 수정·삭제, 시계가 앞선 기기의 수정)이 나중에 도착하면 복원한 항목을 덮을 수 있다. 복원 직전에 서버 볼트를 먼저 받는 방식은 후속으로 둔다.

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 내보내기 전 안내 | 백업 내보내기 | 이 파일은 내보낸 시점의 마스터 비밀번호로만 열 수 있습니다. 비밀번호를 바꾼 뒤에도 이 파일은 예전 비밀번호로 엽니다. | 내보내기 |
| 비밀번호가 틀렸거나 파일이 손상됨 | | 백업을 열 수 없습니다. 비밀번호가 맞는지, 파일이 손상되지 않았는지 확인해 주세요. | |
| 형식이 아니거나 크기 초과, KDF 값이 SEC-001 범위 밖 | | KeyManage 백업 파일이 아닙니다. | |
| 더 새 버전의 백업 | | 더 새 버전의 앱에서 만든 백업입니다. 앱을 업데이트한 뒤 복원해 주세요. | |
| 복원 전 안내 | 백업에서 복원 | 백업에 있던 항목은 백업 시점 내용으로 돌아갑니다. 백업 뒤에 고치거나 지운 내용은 되돌아가고, 백업 뒤에 새로 만든 항목은 그대로 남습니다. | 복원 |
| 복원 완료 | | 백업에서 항목 N개를 복원했습니다. | |

AES-GCM은 비밀번호가 틀린 경우와 파일이 손상된 경우를 구분하지 못하므로 한 문구로 묶는다.

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 클라이언트 테스트 | 내보낸 파일에 평문·이메일이 없음; 대기 중인 변경까지 내보냄; 같은 비밀번호로 복원하면 백업 뒤 고친 항목은 백업 내용으로, 지운 항목은 되살아나고 새 항목은 남음; 복원한 항목이 다른 기기 병합에서도 남음; 지금과 같은 항목은 건드리지 않음; 틀린 비밀번호·손상 파일·형식 아님·5MB 초과·높은 버전 거절과 문구; 다른 계정 백업 복원; 읽기 전용 볼트 복원 거절; 복원 결과 저장과 오프라인 대기; 복원 중 중복 실행 막음 |
| 상호 운용 | 한 플랫폼에서 내보낸 파일을 다른 플랫폼이 복원(구현한 플랫폼끼리) |
