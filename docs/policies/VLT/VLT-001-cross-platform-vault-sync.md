# VLT-001 크로스 플랫폼 볼트 동기화 및 충돌 해결 정책
- 상태: 확정
- 규칙: 모든 플랫폼(iOS/macOS, Android, Web)은 동등한 권한으로 암호화된 볼트를 생성·수정·조회할 수 있어야 한다. 동기화는 앱 실행 시 및 볼트 데이터 변경 즉시 이벤트 기반으로 수행되며, 다중 기기 충돌은 낙관적 잠금으로 감지한다. 서버는 저장 성공 시 1씩 증가하는 `revision`을 발급하고, 클라이언트가 보낸 `expectedRevision`이 서버 값과 다르면 409로 거절한다. 거절받은 클라이언트는 최신 볼트를 받아 항목별 `updatedAt`(삭제는 `deletedAt`)이 최신인 쪽으로 자동 병합해 다시 저장하며, 최대 3회까지 재시도한다. 삭제한 항목은 id·생성·수정·삭제 시각만 남기고 내용(아이디·비밀번호·URL·메모 등)을 지운다. 클라이언트는 자신이 모르는 필드를 지우지 않고 보존해 다시 저장하며, 자신이 아는 것보다 높은 스키마 버전의 볼트는 읽기 전용으로 열어 저장하지 않는다. 서버가 준 revision이 이 기기가 마지막으로 본 값보다 낮으면(서버 복구 또는 옛 볼트 재전송) 동기화를 멈추고 경고하며, 사용자가 확인한 경우에만 서버 볼트를 받아들인다. 오프라인 상태에서는 로컬 볼트를 우선 사용하되 상단에 미동기화 경고를 노출해야 한다. 저장이 네트워크 오류·요청 시간 초과·서버 5xx·요청 제한(429)·응답 형식 오류로 실패하면 변경 사항을 동기화 대기로 로컬에 두고 저장은 성공으로 처리하며, 분명한 거절(용량 초과, 읽기 전용, 형식 오류, 되돌림 감지)만 오류로 알린다. 대기 중에 다시 수정하면 대기 내용 위에 쌓고, 기준 revision은 마지막으로 서버와 맞춘 값을 쓴다. 대기 내용은 네트워크 재연결, 대기 중 일정 간격, 잠금 해제 직후에 다시 보내며 충돌하면 위 병합 절차를 따른다. 다시 보내다 충돌이 아닌 분명한 거절을 받으면 알리고, 사용자가 저장하거나 잠금을 풀거나 다시 로그인할 때까지 자동으로 다시 보내지 않는다. 잠금 해제 직후에는 대기 내용이 있어도 서버 볼트를 먼저 받아 되돌림을 검사한다. 잠겨도 대기 내용은 암호화해 남기고, 잠금 해제 때 서버 볼트로 덮어쓰지 않고 병합해 올린다. 세션이 만료(401)되면 로그인 화면으로 보내되 같은 계정으로 다시 로그인하면 대기 내용을 병합해 올리고, 다른 계정의 로그인이 성공하면 버린다(로그인 실패나 올리기 거절로는 버리지 않는다). 대기 중에 로그아웃하면 잠금 화면에서도 확인을 받고, 웹에서 대기 중에 탭을 닫거나 새로고침하면 잠긴 상태나 세션 만료 뒤 남은 대기 내용까지 포함해 브라우저 떠남 확인을 띄운다. 항목은 서비스 이름이 있어야 하며(앞뒤 공백을 뺀 뒤 1자 이상), 아이디·비밀번호·URL·메모는 비워 둘 수 있다. 삭제는 사용자 확인을 받은 뒤 한다.
- 값: 볼트 최대 허용 용량 5MB(5,242,880바이트, 요청 페이로드 JSON 기준, 이 값과 같으면 허용); 요청 제한 시간 30초(5MB 볼트 업로드 기준, 응답 본문 수신 포함); revision은 정수이며 첫 저장 시 1, 볼트가 없을 때 기대값 0; 자동 병합 재시도 최대 3회(첫 저장 포함 최대 4번 요청); 항목 시간이 같으면 서버 쪽 우선; 동기화 대기 재전송 간격 30초(대기 중일 때만, 재연결 이벤트와 별개)
- 적용 범위: 모든 클라이언트(iOS/macOS, Android, Web) 및 백엔드 볼트 컨트롤러/저장소
- 예외: 오프라인 모드에서는 서버 전송을 생략하고 로컬 저장소만 갱신하며, 네트워크 재연결 시 즉시 동기화를 시도한다. 재연결 시 서버 revision이 앞서 있으면 충돌 처리 절차를 따른다. 대기 내용을 다시 보내다 자동 재시도 3회가 모두 충돌하면 충돌 문구를 보여 주고 대기 내용은 남겨 다음 재전송 때 다시 시도한다
- 사용자 문구: 
  - 서비스 이름 없음: 본문 "서비스 이름을 입력해 주세요."
  - 항목 삭제 확인: 제목 "항목 삭제" / 본문 "이 항목을 삭제할까요? 다른 기기에서도 삭제됩니다." / 버튼 "삭제"·"취소"
  - 용량 초과: 제목 "저장 실패" / 본문 "볼트 허용 용량(5MB)을 초과했거나 데이터 규격이 올바르지 않습니다."
  - 오프라인 경고: 본문 "오프라인 상태입니다. 변경 사항이 서버에 동기화되지 않습니다."
  - 대기 중 로그아웃 확인: 제목 "동기화되지 않은 변경 사항" / 본문 "로그아웃하면 서버에 올리지 못한 변경 사항이 사라집니다." / 버튼 "로그아웃"·"취소"
  - 동기화 충돌(자동 재시도 3회 모두 실패 시): 제목 "동기화 충돌" / 본문 "다른 기기의 변경 사항과 충돌했습니다. 잠시 후 다시 시도해 주세요."
  - revision 되돌림: 제목 "서버 볼트가 이전 상태로 돌아감" / 본문 "서버의 볼트가 이 기기에서 마지막으로 본 상태보다 이전으로 돌아갔습니다. 서버를 복구한 경우가 아니라면 받아들이지 마세요." / 버튼 "서버 볼트 받아들이기"·"취소"
  - 읽기 전용(높은 스키마 버전): 본문 "새 버전 앱에서 저장한 볼트입니다. 앱을 업데이트하기 전까지는 읽기만 할 수 있습니다."
  - 볼트 형식 오류(복호화는 됐지만 내용 규격이 틀림): 제목 "볼트를 열 수 없음" / 본문 "볼트 데이터 형식이 올바르지 않습니다." (덮어쓰지 않는다)
- 근거: docs/vault-spec.md; docs/api-spec.md; docs/adr/ADR-0006-optimistic-locking-vault-sync.md
- 검증 방법: 단위 테스트(기대 revision 일치 시 저장 후 +1, 불일치 시 충돌 오류, 같은 revision으로 동시 2건 저장 시 1건만 성공, 용량 5,242,880바이트 허용·1바이트 초과 거절, 볼트 없을 때 기대값 0으로 첫 저장), 클라이언트 테스트(항목 병합과 삭제 표시, 삭제 항목 내용 제거, 모르는 필드 보존, 높은 스키마 버전 저장 거절, revision 되돌림 감지, 409 후 병합 재저장과 4번 연속 충돌 시 오류, 오프라인 모드 전환 시 배너 노출, 네트워크·5xx 저장 실패 시 대기로 두고 성공 처리, 분명한 거절은 오류, 대기 위 연속 수정, 재연결·30초·잠금 해제 시 재전송, 잠금 뒤 대기 내용 보존과 병합, 401 뒤 같은 계정 재로그인 시 병합·다른 계정은 버림, 대기 중 로그아웃 확인)
- 비고: SEC-001, ADR-0001, ADR-0003, ADR-0006, ADR-0018. revision은 암호문으로 인증되지 않는 값이라, 되돌림 경고는 서버를 백업에서 복구한 경우 같은 정직한 서버의 실수를 알리는 장치이며 악의적인 서버의 옛 볼트 재전송은 막지 못한다(막으려면 암호문 안에 증가하는 값을 두는 별도 결정이 필요하다). 웹 클라이언트는 현재 '마지막으로 본 revision'을 앱이 켜져 있는 동안만 기억하며, 재시작 뒤에도 기억하는 저장은 기기 저장 단계(ADR-0018)에서 붙인다. 웹의 동기화 대기 내용도 그 전까지는 메모리에만 있다
- 이력: 2026-10-27 초기 등록; 2026-10-28 충돌 해결을 Last-Write-Wins에서 낙관적 잠금과 클라이언트 병합으로 변경 (ADR-0006); 2026-10-29 삭제 항목 내용 제거, 모르는 필드 보존·높은 버전 읽기 전용, revision 되돌림 경고, 요청 제한 시간 30초; 2026-10-31 항목 서비스 이름 필수, 삭제 확인 추가; 2026-10-31 저장 실패 시 동기화 대기, 재전송 시점(재연결·30초·잠금 해제), 잠금·세션 만료 시 대기 내용 보존, 대기 중 로그아웃 확인 추가(429·응답 형식 오류도 대기, 분명한 거절 뒤 자동 재전송 중단 포함)
