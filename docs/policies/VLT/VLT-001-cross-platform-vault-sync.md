# VLT-001 크로스 플랫폼 볼트 동기화 및 충돌 해결 정책
- 상태: 확정
- 규칙:
  1. 모든 클라이언트(iOS/macOS, Android, Web)는 같은 권한으로 암호화된 볼트를 만들고, 고치고, 조회한다.
  2. 클라이언트는 앱을 열 때와 볼트를 바꾼 즉시 동기화한다.
  3. 서버는 저장에 성공할 때마다 `revision`을 1 올려 발급한다.
  4. 클라이언트가 보낸 `expectedRevision`이 서버 값과 다르면 서버는 409로 거절한다.
  5. 409를 받은 클라이언트는 최신 볼트를 받아 항목별로 병합한 뒤 다시 저장한다. 병합은 `updatedAt`(삭제는 `deletedAt`)이 늦은 쪽을 고른다.
  6. 삭제한 항목은 id와 생성·수정·삭제 시각만 남긴다. 아이디·비밀번호·URL·메모 등 내용은 지운다.
  7. 클라이언트는 자신이 모르는 필드를 지우지 않고 그대로 다시 저장한다.
  8. 클라이언트는 자신이 아는 것보다 높은 스키마 버전의 볼트를 읽기 전용으로 열고 저장하지 않는다.
  9. 서버가 준 revision이 이 기기가 마지막으로 본 값보다 낮으면 동기화를 멈추고 경고한다. 사용자가 확인한 경우에만 서버 볼트를 받아들인다.
  10. 항목에는 서비스 이름이 있어야 한다(앞뒤 공백을 뺀 뒤 1자 이상). 아이디·비밀번호·URL·메모는 비워 둘 수 있다.
  11. 항목은 사용자 확인을 받은 뒤 삭제한다.
- 값:
  - 볼트 최대 용량: 5MB(5,242,880바이트). 요청 페이로드 JSON 기준이며, 이 값과 같으면 허용한다.
  - 요청 제한 시간: 30초. 5MB 볼트 업로드 기준이며 응답 본문 수신을 포함한다.
  - revision: 정수. 첫 저장 결과는 1, 볼트가 없을 때 기대값은 0.
  - 자동 병합 재시도: 최대 3회(첫 저장을 포함해 최대 4번 요청).
  - 항목 시각이 같으면 서버 쪽을 고른다.
- 적용 범위: 모든 클라이언트(iOS/macOS, Android, Web), 백엔드 볼트 컨트롤러와 저장소
- 예외: 오프라인일 때와 저장이 실패했을 때의 동작은 VLT-002를 따른다.
- 사용자 문구:
  - 서비스 이름 없음: 본문 "서비스 이름을 입력해 주세요."
  - 항목 삭제 확인: 제목 "항목 삭제" / 본문 "이 항목을 삭제할까요? 다른 기기에서도 삭제됩니다." / 버튼 "삭제"·"취소"
  - 용량 초과: 제목 "저장 실패" / 본문 "볼트 허용 용량(5MB)을 초과했거나 데이터 규격이 올바르지 않습니다."
  - 동기화 충돌(자동 재시도 3회 모두 실패): 제목 "동기화 충돌" / 본문 "다른 기기의 변경 사항과 충돌했습니다. 잠시 후 다시 시도해 주세요."
  - revision 되돌림: 제목 "서버 볼트가 이전 상태로 돌아감" / 본문 "서버의 볼트가 이 기기에서 마지막으로 본 상태보다 이전으로 돌아갔습니다. 서버를 복구한 경우가 아니라면 받아들이지 마세요." / 버튼 "서버 볼트 받아들이기"·"취소"
  - 읽기 전용(높은 스키마 버전): 본문 "새 버전 앱에서 저장한 볼트입니다. 앱을 업데이트하기 전까지는 읽기만 할 수 있습니다."
  - 볼트 형식 오류(복호화는 됐지만 내용 규격이 틀림): 제목 "볼트를 열 수 없음" / 본문 "볼트 데이터 형식이 올바르지 않습니다." (덮어쓰지 않는다)
- 근거: docs/vault-spec.md; docs/api-spec.md; docs/adr/ADR-0006-optimistic-locking-vault-sync.md
- 검증 방법:
  - 서버 단위 테스트: 기대 revision이 같으면 저장 뒤 +1, 다르면 충돌 오류; 같은 revision으로 동시에 2건 저장하면 1건만 성공; 5,242,880바이트 허용·1바이트 초과 거절; 볼트가 없을 때 기대값 0으로 첫 저장
  - 클라이언트 테스트: 항목 병합과 삭제 표시; 삭제 항목 내용 제거; 모르는 필드 보존; 높은 스키마 버전 저장 거절; revision 되돌림 감지; 409 뒤 병합 재저장과 4번 연속 충돌 시 오류; 서비스 이름 검사; 삭제 확인
- 비고:
  - 관련: SEC-001, VLT-002, VLT-003, ADR-0001, ADR-0003, ADR-0006
  - revision은 암호문으로 인증되지 않는 값이다. 되돌림 경고는 서버를 백업에서 복구한 경우 같은 정직한 서버의 실수를 알리는 장치이며, 악의적인 서버가 옛 볼트를 다시 보내는 것은 막지 못한다. 막으려면 암호문 안에 증가하는 값을 두는 별도 결정이 필요하다.
- 이력: 2026-10-27 초기 등록; 2026-10-28 충돌 해결을 Last-Write-Wins에서 낙관적 잠금과 클라이언트 병합으로 변경 (ADR-0006); 2026-10-29 삭제 항목 내용 제거, 모르는 필드 보존·높은 버전 읽기 전용, revision 되돌림 경고, 요청 제한 시간 30초; 2026-10-31 항목 서비스 이름 필수, 삭제 확인 추가; 2026-10-31 저장 실패 시 동기화 대기 추가; 2026-11-01 웹 기기 저장 추가 (ADR-0019, ADR-0020); 2026-11-01 오프라인 대기·기기 저장 규칙을 모든 클라이언트 공통으로 정리; 2026-11-01 오프라인 동기화 대기를 VLT-002로, 기기 보존을 VLT-003으로 나누고 규칙을 번호 목록으로 다시 씀. 플랫폼 구현 세부는 각 플랫폼 문서로 옮김(동작 변경 없음)
