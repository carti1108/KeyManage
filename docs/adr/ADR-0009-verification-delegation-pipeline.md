### ADR-0009 AI 작업의 검증 위임 체계 (CI·뮤테이션 테스트·독립 리뷰)
- 상태: 채택
- 날짜: 2026-10-28
- 배경: AI가 작성한 코드와 문서를 사람이 매번 직접 검증하는 시간이 개발 속도의 병목이 되었다. 동시에 AI가 "통과했다"고 보고하는 것만으로는 신뢰할 수 없다. 같은 AI가 코드와 테스트를 함께 쓰면 같은 맹점을 공유하고, 지금까지 검증 결과는 로컬 실행을 AI가 말로 전한 것이었다.
- 결정: 검증을 기계 판정, 테스트 품질 측정, 독립 리뷰의 3단으로 AI·자동화에 위임하고, 사람은 의도와 증거 요약과 실제 동작만 확인한다. (1) GitHub Actions가 PR과 main 푸시마다 `./gradlew check`와 `Scripts/check-docs.sh`를 실행한다. (2) PIT 뮤테이션 테스트를 `:domain`부터 적용해 테스트가 심어진 결함을 잡는 비율을 PR에 보고한다. 처음에는 기록만 하고, 기준선이 잡히면 하한선을 정한다. (3) 코드 PR은 열기 전에 작성 맥락과 분리된 서브에이전트로 `/code-review`를 실행하고, 인증·암호·저장소 변경은 `/security-review`를 추가한다. 결과 요약은 PR 본문에 남긴다. (4) PR 템플릿에 "사람이 확인할 것"(바뀐 결정, 테스트 이름 목록, 데모 명령)을 둔다.
- 고려했던 대안: (1) 사람이 모든 변경을 직접 검토 — 신뢰도는 높지만 병목이 해소되지 않아 기각. (2) 코드를 작성한 AI의 자기 검증만 사용 — 작성 맥락의 맹점을 공유해 기각. (3) 커버리지(JaCoCo) 지표 — 커버리지가 높아도 결함을 잡지 못하는 테스트를 걸러 내지 못해 기각하고 뮤테이션 점수를 쓴다.
- 결과: 사람은 코드 줄 대신 정책·ADR·테스트 이름 목록과 CI·뮤테이션·리뷰 결과, 데모 한 번만 확인하면 된다. 반면 CI 실행 시간(비공개 저장소 무료 한도 안), 뮤테이션 테스트 실행 시간(수 분), Gradle 플러그인 의존성이 추가된다. 테스트로 잡히지 않는 보안 결함(타이밍 등)은 독립 보안 리뷰와 사람의 설계 검토에 남는다.
- 관련: ADR-0002, 이슈 #21
