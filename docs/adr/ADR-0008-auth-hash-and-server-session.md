### ADR-0008 마스터 키 분리 기반 인증 해시와 서버 저장형 세션 채택
- 상태: 채택
- 날짜: 2026-10-28
- 배경: 볼트 API가 `X-Vault-ID`만으로 접근 가능해 볼트 ID를 아는 누구나 남의 볼트를 내려받거나 덮어쓸 수 있었다(#10). 또한 vault-spec은 마스터 비밀번호에서 유도한 키로 볼트를 바로 암호화해 서버에 보낼 인증 정보를 안전하게 만들 수 없었고, salt가 암호화된 볼트 안에 있어 새 기기가 로그인 전에 키를 유도할 수 없었다.
- 결정: 마스터 키 = PBKDF2-HMAC-SHA256(마스터 비밀번호, 계정 salt, 600,000회). 마스터 키에서 HKDF-SHA256으로 암호화 키(info "keymanage-enc")와 인증 해시(info "keymanage-auth")를 분리하고, 인증 해시만 서버로 보낸다. 서버는 인증 해시를 Argon2id로 다시 해시해 저장한다. 계정 salt와 반복 횟수는 로그인 전 prelogin으로 조회하며, 없는 이메일에는 서버 비밀키 HMAC으로 만든 일관된 가짜 salt를 돌려준다. 세션은 256비트 난수 토큰(30일)을 발급하고 서버에는 SHA-256 해시만 저장한다. 계정당 볼트는 1개이며 볼트 API는 토큰의 계정으로 볼트를 찾는다. 서버 비밀키, 가입 허용 여부, 신뢰 프록시는 설정으로 두어 로컬 시연과 셀프 호스팅·직접 운영 어느 쪽에서도 동작하게 한다.
- 고려했던 대안: (1) SRP — 인증 해시조차 서버로 보내지 않지만 iOS·Android·Web 세 플랫폼에 구현·검증하는 비용이 커 기각. (2) 평문 비밀번호 로그인 — 영지식 원칙(ADR-0001) 위반으로 기각. (3) JWT 세션 — 단일 인스턴스(ADR-0007)에서는 무상태 토큰의 이점이 없고 즉시 폐기가 어려워 기각. (4) 애플 iCloud 키체인식 기기 신뢰 그룹·HSM 에스크로 — 하드웨어와 OS를 통제해야 가능한 구조라 기각하되, 기존 기기 승인으로 새 기기를 추가하는 방식은 후속 기능으로 검토한다.
- 결과: 서버가 인증 해시와 볼트를 모두 가져도 암호화 키를 계산할 수 없어 영지식 원칙이 유지되고, 볼트 접근이 계정 단위로 통제된다. 반면 클라이언트 키 유도 방식이 바뀌어 vault-spec이 바뀌고, 반복 횟수 증가로 로그인·잠금 해제가 기기에서 수백 ms 느려진다. 마스터 비밀번호를 잊으면 계정을 복구할 수 없다. 현재 목표는 포트폴리오·시연이며, 실제 배포 방식은 백엔드 완성 후 별도 ADR로 정한다.
- 관련: ADR-0001, ADR-0006, ADR-0007, SEC-001, SEC-002, 이슈 #10
