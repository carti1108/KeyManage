### ADR-0006 볼트 동기화 충돌 해결을 낙관적 잠금과 클라이언트 병합으로 전환
- 상태: 채택
- 날짜: 2026-10-28
- 배경: VLT-001은 다중 기기 충돌 시 볼트 `updatedAt`이 최신인 쪽으로 덮어쓰는 Last-Write-Wins를 정했다. 그러나 볼트는 서버가 내용을 볼 수 없는 단일 암호문 덩어리이므로, 두 기기가 거의 동시에 서로 다른 항목을 추가하면 나중에 저장한 쪽이 다른 기기의 변경을 통째로 지운다. 또한 `updatedAt`은 클라이언트 시계 기준이라 기기 시간이 틀어지면 오래된 데이터가 이길 수 있다.
- 결정: 서버가 볼트마다 저장 성공 시 1씩 증가하는 `revision`을 발급한다. 클라이언트는 저장 시 마지막으로 받은 revision을 `expectedRevision`으로 보내고, 서버 값과 다르면 서버는 409 `VAULT_CONFLICT`로 거절한다. 거절받은 클라이언트는 최신 볼트를 받아 복호화한 뒤 항목별 `updatedAt`(삭제는 `deletedAt` 표시)으로 병합하고 다시 저장한다. 서버는 revision만 비교하며 암호문 내용은 해석하지 않는다.
- 고려했던 대안: (1) Last-Write-Wins 유지 — 구현이 가장 단순하지만 위와 같이 데이터가 영구 소실되어 기각. (2) 서버 측 항목 단위 병합 — 서버가 항목을 보려면 평문이나 항목별 메타데이터가 필요해 영지식 원칙(ADR-0001)을 깨므로 기각. (3) 충돌 시 사용자에게 어느 쪽을 남길지 선택하게 함 — 항목 단위 자동 병합으로 대부분 해결되는 상황에서 매번 사용자 판단을 요구해 사용성이 나빠 기각.
- 결과: 동시 수정이 일어나도 데이터가 사라지지 않고, 서버는 여전히 암호문만 다룬다. 반면 클라이언트마다 병합 로직과 삭제 표시를 구현해야 하고, 저장소는 revision 비교와 교체를 원자적으로 처리해야 한다.
- 관련: ADR-0001, ADR-0003, VLT-001, SEC-001
