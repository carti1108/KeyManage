### ADR-0024 계정 삭제는 비밀번호와 확인 문구로 확인한 뒤 서버에서 즉시 지우고, 계정 삭제를 확정 시점으로 한다
- 상태: 채택
- 날짜: 2026-11-02
- 영역: 공통(백엔드, 모든 클라이언트)

> **요약** 클라이언트는 마스터 비밀번호로 만든 인증 해시를 `POST /api/v1/auth/delete-account`로 보낸다. 서버는 확인 뒤 계정을 지워 삭제를 확정하고, 볼트와 세션을 이어서 지운다. 유예 기간은 두지 않는다. 화면은 확인 문구 `계정 삭제`를 입력해야 삭제 버튼을 켠다.

#### 배경

사용자가 자기 데이터를 서버에서 지울 방법이 없었다. 삭제는 되돌릴 수 없으므로 실수를 막는 확인과, 일부만 지워진 상태가 남지 않는 순서를 정해야 한다. 이 서비스는 이메일 소유를 확인하지 않으므로(미결 질문) 이메일 인증으로 삭제를 확인할 수 없다.

#### 결정

1. **확인:** 마스터 비밀번호를 다시 입력받아 인증 해시로 서버가 확인한다. 화면은 추가로 확인 문구 `계정 삭제`를 입력해야 삭제 버튼을 켠다.
2. **요청 하나:** `POST /api/v1/auth/delete-account`에 Bearer 토큰과 인증 해시를 보낸다(api-spec 2.5.6). 시도 제한은 로그인과 같다.
3. **즉시 삭제:** 유예 기간 없이 바로 지운다.
4. **확정 순서:** 계정을 먼저 지운다. 계정이 지워지면 그 계정의 토큰은 인증되지 않고(세션은 계정의 볼트 ID에 묶여 있다), 남은 볼트는 어느 계정도 가리키지 않아 시작 때 정리 대상이 된다. 그다음 볼트와 세션을 지운다. 뒤 단계가 실패해도 삭제는 확정된 것으로 응답한다.
5. **클라이언트 정리:** 성공하면 이 기기의 기록을 지우고 같은 기기의 다른 창·탭을 로그아웃한다. 기기 설정은 남긴다.

#### 고려했던 대안

| 대안 | 고르지 않은 이유 |
| :--- | :--- |
| 유예 기간(예: 7일) 뒤 삭제 | 실수를 되돌릴 수 있지만 대기 상태, 예약 삭제 작업, 취소 화면이 필요하다. 비밀번호 재입력과 확인 문구, 백업 안내로 실수를 충분히 막는다. |
| 이메일을 다시 입력해 확인 | 이메일 인증이 없는 구조에서는 의미가 헷갈린다. 고정 문구가 같은 효과를 낸다. |
| 비밀번호만 확인 | 확인 단계가 하나뿐이라 버튼을 잘못 누르는 실수를 막기 어렵다. |
| 볼트를 먼저 지우고 계정을 나중에 | 계정 삭제가 실패하면 볼트 없는 계정이 남는다. 계정이 먼저 지워지면 남은 볼트는 해가 없고 자동으로 정리된다. |

#### 결과

- 장점: 일부만 지워진 상태가 사용자에게 보이지 않는다. 기존 세션 결속(볼트 ID)과 고아 볼트 정리를 그대로 쓴다.
- 비용: 삭제를 되돌릴 수 없다. 다른 기기에서 지워진 계정으로 로그인하면 계정 존재 여부를 드러내지 않으려고 비밀번호 바뀜과 같은 안내를 받는다.
