### ADR-0005 비밀번호 생성·진단의 클라이언트 전용 수행
- 상태: 채택
- 날짜: 2026-10-28
- 배경: api-spec 2.1(서버가 비밀번호를 생성해 평문으로 반환)과 2.2(클라이언트가 평문 비밀번호 목록을 서버로 보내 진단)는 "평문 비밀번호는 네트워크를 타거나 서버 메모리에 올라가지 않는다"는 SEC-001·ADR-0001과 충돌한다. 이슈 #7(`:domain` 생성기·감사기 구현) 착수 전 GEN-001 검토에서 발견했다.
- 결정: 비밀번호 생성과 엔트로피 진단은 각 클라이언트 내부에서만 수행한다. 백엔드는 생성·진단 엔드포인트를 두지 않고 볼트 동기화, 인증, 요청 제한에 집중한다. api-spec 2.1·2.2는 제거하며, 규칙은 GEN-001을 유일한 기준으로 각 클라이언트가 구현한다.
- 고려했던 대안: (1) 서버 생성·진단을 유지하고 SEC-001에 예외 추가 — 구현이 한 곳으로 모이지만 영지식 원칙에 구멍이 생기고 서버 침해나 로그 유출 시 실제 볼트 비밀번호가 노출될 수 있어 기각. (2) 진단(2.2)만 제거하고 생성(2.1)은 비회원용 공개 유틸리티로 유지 — 서버가 만든 비밀번호를 볼트에 저장하면 서버가 평문을 본 셈이라 같은 문제가 남고, 비회원 데모 요구사항이 아직 없어 기각. (3) 백엔드 Kotlin 구현을 클라이언트와 공유(KMP) — ADR-0004에서 기각한 코드 공유 방식이라 기각.
- 결과: 평문 비밀번호가 서버로 가는 경로가 사라져 영지식 원칙이 일관되고, 오프라인에서도 생성·진단이 동작한다. 반면 iOS·Android·Web이 같은 규칙을 각자 구현해야 하므로 플랫폼 간 점수가 어긋날 위험이 있어, GEN-001의 공통 샘플 기대값으로 각 플랫폼 테스트를 맞춘다. 이슈 #7은 백엔드 범위가 사라져 닫는다.
- 관련: ADR-0001, ADR-0002, ADR-0004, SEC-001, GEN-001, 이슈 #7
