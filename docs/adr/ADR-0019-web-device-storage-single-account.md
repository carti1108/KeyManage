### ADR-0019 웹 기기 저장은 한 계정만 두고, 인증 해시는 잠금 해제 요청 하나 안에서만 쓴다
- 상태: 대체됨 (→ ADR-0020)
- 날짜: 2026-11-01
- 배경: ADR-0018은 웹 클라이언트가 기기에 저장할 범위를 정했다. 구현 전 보안 리뷰(PR #62)에서 빈틈 세 가지가 나왔다.
  1. 계정마다 기록을 남기고 로그아웃할 때만 지운다. 그래서 다른 계정이 로그인해도 이전 계정의 암호화된 볼트와 이메일이 디스크에 남는다. 이는 VLT-001의 "다른 계정의 로그인이 성공하면 대기 내용을 버린다"는 규칙과 어긋난다.
  2. 오프라인일 때 인증 해시를 메모리에 남긴다. 인증 해시는 토큰과 달리 서버에서 무효화할 수 없고, 비밀번호를 바꾸기 전까지 계속 쓸 수 있는 로그인 자격 증명이다. ADR-0018은 이 위험을 "암호화 키보다 크지 않다"고 낮게 봤다.
  3. 다른 기기에서 마스터 비밀번호를 바꿔도 이 기기의 사본은 옛 비밀번호로 계속 열린다.
- 결정:
  1. 저장하는 값은 ADR-0018과 같다.
     - 저장하는 값: 이메일, KDF 값(salt와 반복 횟수), 암호화된 볼트, 기준 revision, 마지막으로 본 revision, 대기 표시, 레코드 형식 버전(처음 값 1).
     - 저장하지 않는 값: 세션 토큰, 암호화 키, 인증 해시, 평문 볼트.
     - 저장소는 IndexedDB를 쓰고, `navigator.storage.persist()`로 브라우저가 지우지 않게 요청한다. 데스크톱 앱(Tauri WebView2)도 같은 코드를 쓴다.
  2. 기기에는 한 계정의 기록만 둔다.
     - 다른 계정의 로그인이나 가입이 성공하면 이전 기록을 지우고 새 기록을 쓴다. 로그인에 실패하면 지우지 않는다.
     - 로그아웃하면 지운다. 대기 중이면 확인을 받은 뒤에 지운다.
  3. 앱을 다시 열면 저장된 계정은 잠금 화면으로 시작한다. 마스터 비밀번호로 저장된 볼트를 복호화해 확인하므로 오프라인에서도 열린다.
  4. 인증 해시는 잠금 해제 요청 하나 안에서만 쓴다.
     - 세션 토큰이 없는 상태에서 온라인으로 잠금을 풀면, 그때 만든 인증 해시로 바로 로그인하고 응답을 받는 즉시 0으로 덮어 지운다.
     - 오프라인이거나 로그인 요청이 서버에 닿지 못하면 인증 해시를 바로 지운다. 이 경우 볼트는 열리지만 세션이 없어 동기화하지 못한다.
     - 다시 연결되면 마스터 비밀번호를 다시 입력받아 로그인하고, 대기 내용을 올린다.
  5. 같은 이메일로 로그인할 때 서버가 준 KDF 값이 저장된 값과 다르면 비밀번호가 바뀐 것으로 본다. 기기 사본과 대기 내용을 버리고 서버 볼트로 연다. 대기 내용은 옛 키로 암호화돼 있어 새 키로는 열 수 없다.
  6. 잠금을 푼 뒤 로그인이 인증 실패(AUTH_FAILED)로 거절되면 비밀번호가 바뀌었다고 안내하고 로그인 화면으로 보낸다. 기기 기록은 결정 5에 따라 새 비밀번호로 로그인에 성공할 때 버린다.
- 고려했던 대안:
  1. 인증 해시를 볼트가 열려 있는 동안 메모리에 둔다(ADR-0018). 다시 연결돼도 비밀번호를 다시 묻지 않지만, 무효화할 수 없는 자격 증명이 오래 남아서 기각했다.
  2. 세션 토큰을 볼트 키로 암호화해 기기에 저장한다. 다시 열어도 로그인할 필요가 없고 토큰은 무효화할 수 있다. 하지만 디스크에 비밀(토큰)을 두지 않는다는 앞선 결정을 되돌리고 키 유도 용도를 하나 더 늘려서 기각했다.
  3. 계정마다 기록을 남긴다(ADR-0018). 계정을 오가는 사람은 오프라인에서도 열 수 있지만, 공용 기기에 남의 볼트가 남아서 기각했다.
- 결과:
  - 얻는 것:
    - 디스크에는 마지막에 쓴 계정 하나만 남는다.
    - 무효화할 수 없는 인증 해시가 요청 하나보다 오래 메모리에 남지 않는다. 그래서 SEC-003에 예외가 필요 없다.
    - 비밀번호가 바뀐 기기 사본이 정리된다.
  - 비용:
    - 오프라인으로 연 뒤 다시 연결되면 비밀번호를 한 번 더 입력해야 동기화된다.
    - 다른 계정으로 바꾸면 이전 계정은 오프라인에서 열 수 없다.
    - 비밀번호가 바뀌면 이 기기에서 올리지 못한 변경 사항은 사라진다.
    - 기기 접근자의 오프라인 비밀번호 대입 위험과 레코드 형식 비용은 ADR-0018과 같다.
- 관련: ADR-0018(대체), VLT-001, SEC-001, SEC-002, SEC-003, PR #62, 이슈 #64
