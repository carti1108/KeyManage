### ADR-0021 데모는 받은 사람의 로컬 Docker Compose로 실행하고, 데스크톱 릴리스는 `https://localhost:8443`을 서버 주소로 빌드한다
- 상태: 채택
- 날짜: 2026-11-01
- 영역: 공통(백엔드, 웹, 데스크톱)

> **요약** 데모용 서버는 따로 운영하지 않는다. 레포를 받은 사람이 `docker compose up`으로 자기 PC에 백엔드와 웹을 띄운다. 데스크톱 앱은 각자의 로컬 서버(`https://localhost:8443`)에 접속하고, HTTPS 인증서는 받은 사람이 mkcert로 만든다.

#### 배경

데모를 보여 줄 배포 방식을 정해야 한다. 상시 무료 호스팅은 조건이 자주 바뀌고, 배포 방식은 나중에 바뀔 수 있다.

지금 구조의 제약은 다음과 같다.

- 백엔드는 볼트와 계정을 서버 디스크의 파일로 저장하고 한 대로만 운영한다.
- 데스크톱 릴리스 빌드는 빌드할 때 정한 HTTPS 서버 출처 하나에만 접속한다. 데스크톱 릴리스 빌드 규칙은 `http://localhost`도 거절한다. SEC-002는 개발용 localhost HTTP를 허용하지만, 배포하는 앱은 더 엄격하게 둔 것이다.

#### 결정

1. **실행 구성:** 루트 `docker-compose.yml`에 서비스 두 개를 둔다.
   - `backend`: Spring Boot jar를 실행한다.
   - `caddy`: 웹 정적 파일을 내보내고 `/api`를 백엔드로 넘긴다.
   - 볼트·인증 데이터는 이름 붙은 Docker 볼륨에 둔다.
2. **여는 주소:** 포트는 루프백(`127.0.0.1`)에만 연다. 같은 네트워크의 다른 기기에서는 접속할 수 없다.
   - `http://localhost:8080`: 웹 전용. mkcert 없이 바로 쓴다. 평문 루프백이라 SEC-002가 허용하는 개발용 localhost HTTP와 같은 수준이다. 같은 PC의 다른 프로그램을 걱정하면 8443을 쓴다.
   - `https://localhost:8443`: 웹과 데스크톱 앱이 쓴다.
3. **HTTPS 인증서:** 받은 사람이 mkcert로 `localhost` 인증서를 만들어 정해진 폴더에 둔다. Caddy는 그 파일을 읽기 전용으로 쓴다. 인증서와 키는 레포에 넣지 않는다.
4. **데스크톱 릴리스:** GitHub Releases에 올리는 데스크톱 앱은 서버 주소를 `https://localhost:8443`으로 빌드한다. HTTPS만 허용하는 규칙은 그대로 지킨다.
5. **백엔드 설정:**
   - CORS 허용 출처는 `http://tauri.localhost`(데스크톱)와 `https://localhost:8443`(TLS를 끝내는 프록시 뒤 같은 출처 웹)이다.
   - Caddy 컨테이너에 고정 IP를 주고 그 IP를 신뢰 프록시로 지정한다. 인증 요청 제한이 실제 클라이언트 IP로 동작하게 하기 위해서다.
6. **바뀌는 경우:** 호스팅 서버를 두게 되면 새 ADR로 이 ADR을 대체한다. 같은 Compose 설정을 서버에서 다시 쓰고, 데스크톱 앱은 그 주소로 다시 빌드한다.

#### 고려했던 대안

| 대안 | 고르지 않은 이유 |
| :--- | :--- |
| 무료 VM(Oracle Cloud 등)에 상시 배포 | 가입·자원 확보 조건이 불안정하고 놀고 있으면 회수될 수 있다. OS·보안 관리 부담이 데모에 과하다. |
| 집 PC + Cloudflare Tunnel | 고정 주소에 도메인이 필요하고 PC를 끄면 멈춘다. TLS가 Cloudflare에서 끝나 인증 해시가 그곳에서 평문이 된다. 따로 검토한다. |
| 로컬 전용 데스크톱 빌드에서 `http://localhost` 허용 | 배포하는 데스크톱 앱이 평문 주소를 받게 되어 릴리스 빌드 규칙(HTTPS만)을 약하게 만든다. 브라우저 웹(8080)은 사용자가 8443을 고를 수 있지만, 데스크톱 앱은 빌드에 박힌 주소 하나만 쓰므로 고를 수 없다. |
| 소스에서 직접 실행(JDK·Node 설치) 안내만 | 받은 사람이 설치할 것이 많고, 데스크톱 앱에 필요한 HTTPS를 따로 구성해야 한다. |

#### 결과

- 장점: 운영 비용이 없다. 받은 사람은 Docker와 mkcert만 설치한다. 같은 Compose 설정을 나중에 서버 배포에 다시 쓴다.
- 비용: `mkcert -install`은 받은 사람의 PC에 루트 인증서를 등록한다. README에 위험과 삭제 방법(`mkcert -uninstall`)을 적는다. 데스크톱 앱은 8443 포트의 로컬 서버 전용이라, 그 포트를 다른 프로그램이 쓰거나 서버를 띄우지 않으면 쓸 수 없다.
