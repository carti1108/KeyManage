### ADR-0004 영역 간 완전 격리 및 백엔드 교체형 DIP 아키텍처 채택
- 상태: 채택
- 날짜: 2026-10-28
- 배경: 백엔드와 멀티 플랫폼(iOS, Android, Web) 클라이언트 간에 코드 종속성이나 결합도가 존재하면, 특정 영역의 변경이나 장애가 다른 플랫폼으로 번져 전체 프로젝트의 유지보수성과 확장성이 급격히 악화된다.
- 결정: (1) 모든 플랫폼 클라이언트(`Apps/*`)와 백엔드(`Back/`)는 물리적으로 분리된 독립 프로젝트로 관리하며, 양측의 유일한 접점은 오직 사전 확정된 REST JSON 계약(`docs/api-spec.md`)만으로 제한한다. (2) 각 클라이언트 내부에서는 의존성 역전(DIP)을 엄격히 적용하여 UI가 네트워크 구현체가 아닌 추상 프로토콜/인터페이스(`VaultSyncService`)에만 의존하게 하고, 조립 지점에서 어댑터를 갈아끼움으로써 백엔드를 Mock, Spring Boot, BaaS 등으로 1초 만에 교체 가능하도록 설계한다.
- 고려했던 대안: (1) Kotlin Multiplatform(KMP) 등을 통한 클라이언트-백엔드 간 모델 코드 직접 공유 — 초기 보일러플레이트는 줄어드나 빌드 도구와 플랫폼 간 결합도가 생겨 독립성이 훼손되므로 기각. (2) 클라이언트 화면이 구체 네트워크 클래스를 직접 참조하는 방식 — 백엔드 교체나 오프라인 모드 대응 시 화면 코드를 전부 뜯어고쳐야 하므로 기각.
- 결과: 백엔드가 꺼져 있거나 개발되지 않았어도 Mock 어댑터를 꽂아 클라이언트 단독 개발 및 100% 독립 테스트가 가능해지며, 향후 백엔드 인프라가 변경되어도 클라이언트 UI 코드는 단 1줄도 수정되지 않는다. 반면 인터페이스와 어댑터를 분리 작성해야 하는 초기 코드가 소폭 증가한다.
- 관련: ADR-0001, ADR-0002, ADR-0003, VLT-001
