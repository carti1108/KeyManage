### ADR-0022 백업 파일은 볼트 암호화 컨테이너에 KDF 값을 붙인 JSON으로 하고, 내보낸 시점의 마스터 비밀번호로 잠근다
- 상태: 채택
- 날짜: 2026-11-01
- 영역: 공통(모든 클라이언트)

> **요약** 백업 파일은 기존 `EncryptedVaultPayload`에 형식 표시와 KDF 값(이름, 반복 횟수, salt)을 붙인 JSON이다. 따로 정하는 백업 비밀번호 없이 내보낸 시점의 마스터 비밀번호로 연다. 복원은 백업에 있던 항목을 백업 시점 내용으로 되돌리고, 백업 뒤에 새로 만든 항목은 남긴다.

#### 배경

VLT-004로 암호화 백업 내보내기와 복원을 추가한다. 마스터 비밀번호를 잃거나 서버 데이터가 사라지면 볼트를 되찾을 길이 없기 때문이다. 백업 파일은 플랫폼 사이에서 오가므로 형식이 공통이어야 하고, 한번 사용자 손에 나가면 바꾸기 어렵다.

#### 결정

1. **형식:** JSON 하나에 아래 필드를 둔다(상세는 vault-spec 6장).
   - `format`: `"keymanage-backup"` 고정 문자열
   - `formatVersion`: 백업 형식 버전. 지금은 1
   - `createdAt`: 내보낸 시각(ISO 8601 UTC)
   - `kdf`: `{ "name", "iterations", "salt" }`. prelogin 응답과 같은 이름과 인코딩
   - `vault`: 기존 `EncryptedVaultPayload` 그대로
2. **키:** 내보낸 시점의 마스터 비밀번호와 파일의 `kdf`로 SEC-001과 같은 방식으로 키를 만든다. 백업 전용 비밀번호를 두지 않는다.
3. **새로 암호화:** 내보낼 때 서버나 기기에 있는 암호문을 복사하지 않고, 화면의 볼트를 새 IV로 다시 암호화한다. 대기 중인 변경까지 담기 위해서다.
4. **계정 정보 제외:** 이메일, revision, 세션 정보는 넣지 않는다.
5. **복원:** 백업에서 지워지지 않은 항목은 백업 시점 내용으로 되돌리고 수정 시각을 복원 시각으로 정한다(지금 항목의 변경 시각이 더 늦으면 그 1초 뒤). 백업 뒤에 새로 만든 항목과 백업에서 지워진 항목은 건드리지 않는다. 동기화 병합 규칙(VLT-001)은 바꾸지 않고 복원에만 이 규칙을 쓴다.

#### 고려했던 대안

| 대안 | 고르지 않은 이유 |
| :--- | :--- |
| 백업 전용 비밀번호 | 마스터 비밀번호와 무관하게 열 수 있지만, 외울 비밀번호가 하나 더 생기고 별도 비밀번호 규칙을 정해야 한다. 데모 범위에 과하다. |
| 평문(CSV·JSON) 내보내기 | 다른 앱으로 옮기기 쉽지만 파일이 새면 모든 비밀번호가 드러난다. 평문 내보내기는 경고·재확인 정책을 정한 뒤 따로 다룬다. |
| 서버 암호문을 그대로 복사 | 구현이 가장 쉽지만 동기화 대기 중인 변경이 빠진다. |
| 복원 시 동기화 병합 규칙 그대로 | 항목마다 나중에 바뀐 쪽이 이겨, 백업 뒤에 고치거나 지운 항목이 되돌아가지 않는다. "백업에서 복원"이라는 행동의 기대와 맞지 않는다. |
| 복원 시 볼트 전체를 백업으로 바꾸기 | 백업 뒤에 새로 만든 항목까지 사라져 잃는 것이 가장 많다. |
| 복원 시 항목 추가만 | 지운 항목도 되살릴 수 있지만 같은 항목이 중복된다. |

#### 결과

- 장점: 새 암호 코드가 필요 없고, 기존 암호화 코드를 그대로 쓴다. 파일이 새도 서버 암호문이 샌 것과 같은 수준으로 보호된다.
- 비용: 마스터 비밀번호를 바꾼 뒤에는 옛 백업을 옛 비밀번호로 열어야 한다. 복원하면 백업 뒤에 고친 내용은 백업 내용으로 돌아간다(복원 전에 안내한다). 형식을 바꾸면 `formatVersion`을 올리고 이전 버전 읽기를 유지해야 한다.
