### ADR-0018 웹 클라이언트는 기기에 암호화된 볼트와 동기화 상태만 저장하고 세션 토큰은 저장하지 않는다
- 상태: 채택
- 날짜: 2026-10-31
- 배경: VLT-001은 오프라인일 때 로컬 볼트를 쓰고 다시 연결되면 동기화하라고 정한다. 그런데 웹 클라이언트는 모든 값을 메모리에만 둔다. 그래서 탭을 닫으면 동기화하지 못한 변경 사항이 사라지고, 인터넷이 없을 때 앱을 새로 열면 볼트를 열 수 없다. 되돌림 감지 기준(마지막으로 본 revision)도 재시작하면 0으로 돌아가서 재시작 직후의 되돌림을 잡지 못한다. 저장 범위는 보안 경계이고 한번 정하면 저장 데이터 형식이 생기므로 구현 전에 정한다.
- 결정:
  1. 계정마다 기기에 다음 값을 저장한다.
     - 정규화한 이메일
     - KDF 값(salt, 반복 횟수)
     - 암호화된 볼트. 최신 볼트이며, 대기 중인 변경 사항이 있으면 그것을 담은 볼트다.
     - 기준 revision. 이 볼트가 바탕으로 삼은 서버 revision이다.
     - 마지막으로 본 revision. 되돌림 감지 기준이다.
     - 대기 표시. 동기화하지 못한 변경 사항이 있는지 나타낸다.
     - 레코드 형식 버전. 처음 값은 1이다.
  2. 세션 토큰, 암호화 키, 인증 해시, 평문 볼트는 저장하지 않는다.
  3. 저장소는 IndexedDB를 쓰고, `navigator.storage.persist()`로 브라우저가 지우지 않게 요청한다. 데스크톱 앱(Tauri WebView2)도 같은 코드를 쓴다.
  4. 앱을 다시 열면 저장된 계정은 잠긴 상태로 시작한다. 마스터 비밀번호로 저장된 볼트를 복호화해 확인하므로 오프라인에서도 열린다.
  5. 토큰을 저장하지 않으므로 잠금 해제 때 이미 만든 인증 해시로 바로 로그인한다. 비밀번호를 두 번 묻지 않는다.
  6. 오프라인이면 인증 해시를 볼트가 열려 있는 동안만 메모리에 둔다. 다시 연결되어 로그인하면 바로 지우고, 잠기면 함께 지운다.
  7. 로그아웃하면 그 계정의 레코드를 지운다.
- 고려했던 대안:
  1. 세션 토큰까지 저장한다. 새로 열 때 다시 로그인하지 않아도 되지만, XSS나 기기 접근으로 토큰을 빼 가면 서버 볼트를 덮어쓰거나 지울 수 있어서 기각했다.
  2. localStorage에 저장한다. 문자열만 담을 수 있고 용량 한도가 5MB 안팎이라 VLT-001의 5MB 볼트를 담지 못할 수 있어서 기각했다.
  3. 대기 중인 변경 사항만 저장하고 볼트 전체는 저장하지 않는다. 오프라인에서 새로 열 수 없어서 목적을 이루지 못해 기각했다.
  4. 지금처럼 아무것도 저장하지 않는다. VLT-001의 오프라인 규칙을 지키지 못해서 기각했다.
- 결과:
  - 얻는 것: 오프라인에서도 새로 열어 볼트를 쓸 수 있고, 동기화하지 못한 변경 사항이 탭을 닫아도 남고, 되돌림 감지 기준이 재시작 뒤에도 유지된다.
  - 비용 1: 기기에 이메일이 남아 이 기기를 누가 쓰는지 드러난다.
  - 비용 2: 기기에 접근할 수 있는 사람은 암호화된 볼트를 가져가 오프라인으로 비밀번호 대입을 시도할 수 있다. 서버 유출과 같은 수준의 위험이며 12자 이상 비밀번호(SEC-002)와 KDF(SEC-001)로 막는다.
  - 비용 3: 기기에 저장한 revision은 기기 접근자가 바꿀 수 있다. 되돌림 경고는 원래 정직한 서버의 실수를 알리는 장치이므로 이 위협은 범위 밖이다.
  - 비용 4: 인증 해시를 볼트가 열려 있는 동안 메모리에 둘 수 있다. 같은 시간 동안 메모리에 있는 암호화 키보다 위험이 크지 않다. SEC-003에는 구현할 때 이 예외를 반영한다.
  - 비용 5: 기기 저장 레코드 형식이 생기므로, 앞으로 형식을 바꿀 때는 이전 레코드를 옮기는 절차가 필요하다.
- 관련: VLT-001, SEC-001, SEC-002, SEC-003, ADR-0001, ADR-0006, ADR-0010, 이슈 #61
