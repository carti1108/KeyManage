### ADR-0007 파일 볼트 저장소의 원자적 쓰기와 단일 인스턴스 제약
- 상태: 채택
- 날짜: 2026-10-28
- 배경: ADR-0003은 볼트 저장소를 파일 기반 어댑터로 정했고, ADR-0006은 저장소가 revision 비교와 교체를 원자적으로 처리할 것을 요구한다. 파일 시스템에는 트랜잭션이 없으므로, 동시 요청 직렬화와 쓰기 도중 장애 시 파일 손상 방지 방법을 정해야 했다.
- 결정: 볼트 1개를 파일 1개(`{vaultId}.json`, 내용은 revision과 payload)로 저장한다. 같은 볼트에 대한 비교·교체는 프로세스 안의 볼트별 잠금으로 직렬화하고, 파일은 같은 폴더의 임시 파일에 먼저 쓴 뒤 `ATOMIC_MOVE`로 교체해 읽는 쪽이 반쯤 쓰인 파일을 보지 않게 한다. 백엔드는 단일 인스턴스로만 운영한다. `vaultId`는 파일 경로에 쓰이므로 도메인에서 UUID 형식만 허용한다.
- 고려했던 대안: (1) OS 파일 잠금(`FileChannel.lock`) — 여러 프로세스 간 잠금이 가능하지만 OS·파일 시스템마다 동작이 달라(특히 네트워크 파일 시스템) 신뢰하기 어렵고, 단일 인스턴스에서는 이점이 없어 기각. (2) 잠금 없이 파일에 직접 덮어쓰기 — 동시 요청 시 revision 검사가 깨지고 쓰기 도중 장애 시 볼트가 손상되어 기각. (3) 지금 RDBMS로 전환해 트랜잭션 사용 — ADR-0003에서 기각한 운영 비용이 그대로 남아 기각.
- 결과: 별도 인프라 없이 동시 저장 충돌 감지와 장애 시 파일 무결성을 보장한다. 반면 서버를 여러 대로 늘리면 잠금이 공유되지 않아 이 보장이 깨지므로, 수평 확장이 필요해지면 RDBMS나 조건부 쓰기를 지원하는 오브젝트 스토리지 어댑터로 교체하고 이 ADR을 대체해야 한다.
- 관련: ADR-0003, ADR-0006, VLT-001, 이슈 #13
