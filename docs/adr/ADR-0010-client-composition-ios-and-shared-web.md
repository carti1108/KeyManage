### ADR-0010 클라이언트 구성: iOS 네이티브와 웹 코드 공유(브라우저·데스크톱) 우선
- 상태: 채택
- 날짜: 2026-10-28
- 배경: 대상 플랫폼은 iOS, Android, Web, macOS, Windows다. 플랫폼마다 네이티브로 만들면 코드베이스가 4~5개로 늘어난다. 1Password·Bitwarden은 웹 기술로 만든 화면을 데스크톱 앱 틀로 감싸 웹과 데스크톱이 같은 코드를 쓴다. 현재 목표는 포트폴리오·시연이므로 적은 코드베이스로 더 많은 플랫폼을 지원하는 쪽이 유리하다.
- 결정: (1) 웹 클라이언트 하나를 브라우저용과 데스크톱 앱(우선 Windows)으로 함께 쓴다. 데스크톱 앱 틀(Tauri 또는 Electron)은 데스크톱 패키징 단계에서 정한다. 웹 클라이언트는 데스크톱에 그대로 담을 수 있도록 서버 렌더링 없는 정적 앱으로 만든다. (2) iOS는 SwiftUI 네이티브로 만든다. (3) 구현 순서는 iOS와 웹을 먼저, Android 네이티브는 마지막이며 만들지 않을 수도 있다. (4) macOS는 SwiftUI 네이티브와 웹 코드 공유 중 나중에 정한다.
- 고려했던 대안: (1) 모든 플랫폼 네이티브 — 플랫폼별 사용감은 가장 좋지만 코드베이스가 늘어 기각. (2) Windows는 브라우저로만 지원 — 데스크톱 앱이 없어 실제 패스워드 매니저 사용 경험과 거리가 멀어 기각. (3) Flutter·React Native로 모바일까지 하나로 — Keychain, 자동 완성 확장, 클립보드 만료 같은 보안 관련 OS 기능을 결국 네이티브로 연결해야 하고, iOS 네이티브의 이점이 커 기각.
- 결과: 웹 코드 하나로 브라우저와 Windows(필요하면 macOS·Linux)를 지원한다. 데스크톱 앱은 코드를 앱 안에 담아 배포하므로, 서버가 내려주는 JavaScript를 그대로 실행하는 웹의 영지식 한계가 데스크톱에서는 줄어든다. 반면 설치 파일, 자동 업데이트, 코드 서명 같은 데스크톱 패키징 비용이 생기고, macOS 방식 결정은 미뤄진다.
- 관련: ADR-0001, ADR-0004, ADR-0008
