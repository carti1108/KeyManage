# 2026-11-01 · 웹 자동 잠금 시간 설정

- 이슈·PR: 없음(PR 전)
- 커밋: 31e1d21, 037c6db, 3e2fcc0, f580d9e, 3a3fc37, b8af1e9, 7fad512, 6e83beb, 58b8a4a

> **요약** 웹에서 5분으로 고정돼 있던 자동 잠금 시간을 사용자가 고를 수 있게 했다. 설정은 기기마다 localStorage에 저장하고 서버와 동기화하지 않는다. 사람이 저장 범위(기기별, 동기화 안 함)와 정책·ADR 안을 승인했다.

## 사용 도구

- 도구: Claude Code (Opus 5.5). 구현 서브에이전트 1개, 독립 리뷰 서브에이전트 1개
- 플러그인·스킬: superpowers:brainstorming, policy-manager, adr-manager, project-docs:ai-usage

## 요청

인수인계 문서의 남은 일 후보 중 자동 잠금 설정 화면을 골랐다. 화면 형태에는 특별한 요구 없이 잠그기만 하면 된다는 방향을 주었고, 작업 전에 main을 최신으로 받도록 했다.

## AI 산출물

- SEC-003 수정안(8개 항목 점검): 기기별 저장·동기화 안 함, 로그아웃·계정 전환 뒤에도 유지, 잘못된 저장값은 기본 5분, 바꾸면 그때부터 다시 잼, 웹 다른 탭 즉시 반영
- ADR-WEB-002: localStorage 키 하나에 저장, `storage` 이벤트로 탭 간 반영. 대안은 IndexedDB 기기 기록 필드, IndexedDB 별도 저장소, 서버 동기화
- 도메인 저장소 인터페이스와 값 검증, localStorage 어댑터, 설정값에 묶인 자동 잠금 연결 훅, 볼트 화면의 "자동 잠금" 선택 칸
- `Apps/Web/docs/device-storage.md`에 설정 저장 위치 추가

## 검증하지 못한 것

1. 실제 브라우저 여러 탭에서의 `storage` 이벤트 반영. 테스트는 가짜 Storage와 합성 이벤트로 확인했다.
2. Tauri 웹뷰(WebView2)에서 설정이 앱 재시작 뒤 유지되는지
3. 개인정보 보호 모드에서 저장소 접근이 막힐 때의 실제 동작(테스트는 예외 주입으로만 확인)
4. 리뷰 반영 수정 커밋에 대한 2차 독립 리뷰는 하지 않았다.
5. 재연결 누수·구독 해제 테스트는 구현 전에도 통과해, 정리 함수를 잠시 빼서 실패하는 것을 확인했다.
6. 고치지 않은 LOW 2건: 다른 탭의 `localStorage.clear()`는 무시해 탭마다 값이 다를 수 있음, 키보드로 선택을 넘길 때마다 바로 저장됨

## AI의 오류와 정정

| 오류 | 발견 | 조치 |
| :--- | :--- | :--- |
| 공통 정책 SEC-003에 웹 ADR 링크를 넣음(공통 문서는 플랫폼 문서를 참조하지 않는 규칙 위반) | AI가 작성 가이드를 읽고 발견(문서 검사는 통과했음) | 커밋 전에 링크를 지움 |
