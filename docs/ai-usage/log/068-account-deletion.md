# 2026-11-02 · 계정 삭제 (SEC-005)

- 이슈·PR: 없음(PR 전)
- 커밋: 82c1664, 2248e81, 4e26594, 1c88383, 4ae96b6, 7d22fd1, b3ea0af, 3d5a77b, 05f2d8a, 61bf7e0, 2a96b48, 09e5fb2, 456bf21, b7b3166, d7e0da0, 9bb3e7b, eeae944, 4387f98, 7524306, 298d721

> **요약** 마스터 비밀번호와 확인 문구 `계정 삭제`로 확인한 뒤 서버가 계정·볼트·세션을 즉시 지우고, 클라이언트가 이 기기 기록을 지우고 모든 창을 로그아웃하는 계정 삭제를 백엔드와 웹에 넣었다. 계정을 먼저 지우는 순간을 확정으로 하고, 지우지 못한 볼트는 삭제 예정 목록으로 시작 때 정리한다. 사람이 즉시 삭제를 고르고, 이메일 재입력 확인이 이메일 인증이 없는 구조에서 헷갈린다고 지적해 고정 확인 문구로 바꿨다.

## 사용 도구

- 도구: Claude Code (Opus 5.5). 구현 서브에이전트 1개, 독립 리뷰 서브에이전트 1개
- 플러그인·스킬: policy-manager, adr-manager, project-docs:ai-usage

## 요청

남은 작업을 순서대로 하도록 한 흐름의 세 번째로 계정 삭제를 진행했다. 중간에 GitHub Actions가 결제 문제로 돌지 않자 저장소를 공개로 바꿨다.

## AI 산출물

- 정책 SEC-005, 공통 ADR-0024(확인 방식, 즉시 삭제, 확정 순서), 백엔드 ADR-BE-002(삭제 예정 볼트 목록, 시작 때 세션 정리), api-spec 2.5.6
- 백엔드: `DeleteAccountUseCase`, 계정 저장소 삭제, 삭제 예정 목록 파일, 시작 때 무효 세션 정리
- 웹: 세션의 계정 삭제(저장 대기열에 줄 세우기, 인증 해시 버퍼 지우기, 기기 기록·탭 기억 삭제, 다른 탭 로그아웃), 공용 `ModalDialog` 분리, 계정 삭제 대화상자(NFC 정규화한 확인 문구 비교)
- 정책 감사 스크립트의 SEC-005 웹 규칙, 통합 테스트
- 저장소를 공개로 바꾼 뒤 CI가 정상 실행되는지 확인

## 사람의 판단

| 판단 | 내용 |
| :--- | :--- |
| 채택 | 유예 기간 없이 즉시 삭제하는 추천안을 골랐다. |
| 수정 | AI가 추천한 "비밀번호 + 이메일 재입력" 확인에 대해, 이메일 인증이 없는 구조라 의미가 애매하다고 지적했다. 고정 확인 문구 `계정 삭제` 입력으로 바꿨다. |
| 결정 | Actions 결제 문제로 CI가 돌지 않자 저장소를 공개로 바꿨다. |
| 확인 | 확인 문구, 틀린 비밀번호, 정상 삭제, 다른 탭, 재가입을 직접 확인했다. |

| 독립 리뷰 | CRITICAL 없음. MEDIUM 2(마지막 계정 삭제 시 볼트가 남음, 실패한 삭제가 기존 경고를 지움), LOW 여러 건, 불안정 테스트를 모두 반영 |
| 사람의 확인 | 브라우저에서 삭제 흐름 정상 |

## 검증하지 못한 것

1. 실제 다른 물리 기기에서 삭제 뒤 세션 만료 흐름

3. 삭제 예정 목록 파일이 손상되면 시작 정리를 건너뛴다. 수동으로 지워야 한다.
4. Apple 클라이언트의 대응(후속 이슈 예정)

## AI의 오류와 정정

| 오류 | 발견 | 조치 |
| :--- | :--- | :--- |
| 이메일 인증이 없는 구조에서 이메일 재입력을 확인 방식으로 추천함 | 사람이 지적 | 고정 확인 문구로 바꿈 |
| 정리 장치가 계정 0개면 건너뛰어, 마지막 계정을 지울 때 볼트가 남을 수 있음(정책 위반) | 독립 리뷰 | 삭제 예정 목록(ADR-BE-002) |
