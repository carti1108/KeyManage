# 2026-10-28 · 와이어프레임 빌더의 실제 Figma 실행 실패 정정

> 요약: 모의 검증을 통과한 와이어프레임 빌더(로그 017)가 실제 Figma에서는 화면 일부와 Web·macOS 페이지를 만들지 못했다. 원인 두 가지(잘못된 constraints 값, 무료 요금제 페이지 3개 제한)를 고치고, 같은 종류의 실패를 모의 검증기가 잡도록 보강했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Node.js, Figma(사용자 실행)
- 플러그인/스킬: `project-docs:ai-usage`

## 요청

- Figma에서 실행하니 Android 와이어프레임만 보인다며 경고 알림 화면을 공유받았다.

## AI 산출물

- 원인 분석: (1) 게이지 막대의 세로 constraints에 현재 API가 받지 않는 `TOP_BOTTOM`을 넣어 게이지가 있는 화면(가입, 상세, 편집, 생성기)이 실패했다. (2) Figma 무료(Starter) 요금제는 페이지가 3개까지라 기본 페이지에 iOS·Android 페이지를 더한 뒤 Web·macOS 페이지를 만들지 못했다.
- 수정: constraints 값을 `STRETCH`로 바꾸고, 네 플랫폼을 `📐 Wireframes` 페이지 하나에 위아래로 그리도록 변경. 새 페이지를 만들 수 없으면 비어 있는 현재 페이지만 쓰고, 내용이 있는 페이지는 지우지 않고 오류 알림을 띄운다.
- 모의 검증기 보강: constraints 허용 값 검사, 페이지 3개 제한, 페이지가 꽉 찬 파일(현재 페이지가 빈 경우·내용이 있는 경우)에서 사용자 내용이 지워지지 않는지 검사.

## 사람의 판단

- 실제 Figma에서 실행해 결과와 오류 알림을 공유했다. 모의 검증만으로는 알 수 없던 실패를 사람의 실제 실행이 드러냈다.

## 검증

- 보강한 모의 검증기를 사용자가 실행한 이전 버전 코드에 돌려, 사용자가 본 두 오류(constraints `TOP_BOTTOM`, 페이지 3개 제한)를 그대로 재현해 실패로 잡는 것을 확인.
- 수정한 코드는 모의 검증 4개 시나리오(새 파일 2회 실행, 꽉 찬 파일 두 경우, 글꼴 없음) 통과.

## 검증하지 못한 것

1. 수정 후 실제 Figma 실행은 아직 하지 않았다. 사용자가 다시 실행해 확인해야 한다.

## AI의 오류와 정정

1. 모의 검증기는 내가 알고 있던 규칙만 흉내 냈기 때문에, API 값 검증과 요금제 제한처럼 몰랐던 실패를 잡지 못했다. 모의 검증은 실제 환경을 대신하지 못하며, 실제 실행에서 나온 실패를 검증기 규칙으로 되돌려 넣는 방식으로 보강했다.
2. 플랫폼마다 페이지를 하나씩 만드는 설계가 무료 요금제 제한을 고려하지 않았다. 페이지 하나에 모두 그리도록 바꿨다.
