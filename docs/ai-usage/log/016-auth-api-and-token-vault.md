# 2026-10-28 · 인증 API 구현과 볼트 API 토큰 전환 (#19, #10 해결)

> 요약: prelogin·가입·로그인·로그아웃 API, 기본 거부 방식의 Bearer 토큰 필터, IP 시도 제한을 TDD로 구현하고 볼트 API를 토큰의 계정 기준으로 전환했다. ADR-0009 체계에 따라 코드 리뷰와 보안 리뷰를 독립 서브에이전트로 돌렸고, 경로 표기를 바꿔 필터 판단을 우회할 수 있던 문제를 포함해 8건을 반영했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), GitHub Actions
- 플러그인/스킬: `superpowers:test-driven-development`, `code-review`, `security-review`(Claude Code 내장, 독립 서브에이전트), `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 검증 위임 체계(PR #22) 머지 후 이슈 #19 진행을 요청받았다.

## AI 산출물

- `:domain` testFixtures: 가짜 저장소·해셔·시계를 모듈 간 공유하도록 옮기고 중복 제거.
- `:api` `auth` 패키지: `AuthController`, `AuthTokenFilter`(인증 API 4개만 허용하고 나머지는 모두 토큰 요구), `AuthRateLimitFilter`, `IpRateLimiter`(1분 고정 구간), `ClientIpResolver`(신뢰 프록시의 X-Forwarded-For만, 여러 줄·IPv6 표기 정규화), `RequestPaths`(경로 정규화), `BearerTokens`, 필터용 `ErrorResponses`.
- 볼트 API 전환: `X-Vault-ID`·`vaultId`를 없애고 토큰 계정의 볼트만 조회·저장.
- `:domain` `LoginAttemptLimiter`: 추적 항목 상한과 1분 주기 정리, `compute` 기반 원자적 갱신.
- `:app` `WebConfiguration`(필터 순서: 본문 크기 → IP 제한 → 토큰), `keymanage.http.trusted-proxies` 설정, 가입부터 로그아웃까지의 통합 테스트.

## 사람의 판단

- 이슈 #19의 범위를 승인하고 진행을 지시했다. 이번 작업은 합의한 확인 범위에 따라 중간 승인 없이 진행했다.

## 검증

- RED: 뼈대 상태에서 새 테스트 37개 실패 확인. 리뷰 반영용 테스트 6개도 수정 전 실패를 확인했다(1개는 이전 구현으로 되돌려 실패 확인).
- GREEN: `./gradlew check` 153개 통과, 뮤테이션 점수 87%(98개 중 85개).
- 독립 코드 리뷰 10건: 8건 반영(경로 정규화와 기본 거부, X-Forwarded-For 여러 줄, IPv6 표기, 정리 주기 제한, 원자적 갱신, 필터 내 예상 밖 오류의 표준 응답, 통합 테스트의 409·파일 기록 검증 복원), 1건 유지(고정 구간 경계에서 순간 2배 허용은 정책 해석으로 명시), 1건 후속(IP 맵 크기).
- 독립 보안 리뷰: 확신도 8 이상의 취약점 없음. 경로 표기로 토큰 필터 판단을 건너뛸 수 있으나 컨트롤러의 필수 계정 속성 때문에 데이터 접근은 불가하다는 판단과 함께 방어 강화를 권고했고, 기본 거부로 바꿔 반영했다.
- 실제 서버 기동 후 curl 11개 시나리오: 토큰 없음·경로 우회 시도 401, 가입 201, prelogin(대소문자 정규화, 없는 이메일도 200), 볼트 저장·조회, 틀린 해시와 없는 이메일이 같은 401 본문, 로그아웃 204 후 401. 서버 로그에 토큰·인증 해시 원문 0건.

## 검증하지 못한 것

1. 실제 리버스 프록시(Caddy 등) 뒤에서 신뢰 프록시 설정과 X-Forwarded-For 처리를 확인하지 않았다(단위 테스트로만 확인).
2. IP 제한 맵은 한 구간 동안 들어온 IP 수만큼 커진다. IPv6 대역을 바꿔 가며 보내는 경우의 상한은 배포 방식 결정 때 다룬다.
3. 클라이언트(iOS·Android·Web)의 키 유도와 인증 해시 계산은 아직 구현되지 않아, 서버와 실제 클라이언트 간 연동은 확인하지 않았다.

## AI의 오류와 정정

1. 첫 smoke test에서 토큰 없는 볼트 요청이 401이 아닌 400을 돌려주고 가입 요청이 멈췄다. 원인은 몇 시간 전 smoke test에서 띄운 서버가 Git Bash의 `kill`로 종료되지 않고 같은 포트에 남아 있어, 새 서버는 기동에 실패하고 요청이 옛 코드로 간 것이었다. 남은 프로세스를 확인해 종료하고, 이후 smoke test는 포트가 비었는지 먼저 확인하고 포트 기준으로 프로세스를 종료하도록 바꿨다.
2. 첫 구현의 토큰 필터와 IP 제한 필터는 원본 URI 문자열로 경로를 판단해, `;x=1`, `//`, `..;` 같은 표기로 판단을 건너뛸 수 있었다. 독립 리뷰가 지적해 정규화된 경로로 판단하고 토큰 필터를 기본 거부로 바꿨다.
3. 리뷰 반영 중 "잠금이 끝나면 항목을 통째로 지우는" 이전 동작이, 잠금 해제 뒤 쌓인 실패 기록까지 지워 버리는 결함을 새로 발견했다. 실패하는 테스트를 추가하고 잠금만 풀도록 고쳤다.
