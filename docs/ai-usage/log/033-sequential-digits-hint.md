# 2026-10-31 · 비밀번호에 이어지는 숫자가 있으면 안내 (#55)

> 요약: 흔한 패턴 검사는 기준이 모호해 빼고, 규칙으로 정할 수 있는 이어지는 숫자(123, 987 등)만 안내하기로 사람이 정했다. 점수에 반영하는 안 대신 점수는 그대로 두고 안내만 하는 안을 골랐다. GEN-001과 웹 항목 폼에 반영했고, 독립 코드 리뷰의 낮음 3건을 모두 반영했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest
- 플러그인/스킬: `policy-manager:policy-manager`, `superpowers:test-driven-development`, 독립 코드 리뷰 서브에이전트, `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 생성기 PR에서 정책 공식이 흔한 패턴을 걸러내지 못한다는 점을 보고하자, 흔한 패턴은 추상적이라 어렵고 이어지는 숫자는 거르면 좋겠다는 의견을 받았다.

## AI 산출물

- GEN-001: 이어지는 숫자 안내 규칙(3자리 이상, 한 방향으로 1씩 오르내리는 ASCII 숫자, 9↔0 넘김·방향 전환·다른 문자 끼임은 끊김), 문구, 검증 샘플.
- `domain/generator/passwordStrength`: `hasSequentialDigits`.
- 항목 폼: 취약 경고 영역 안에 안내 문구. 점수가 높아도 보인다. 생성기 결과에는 붙이지 않는다.

## 사람의 판단

- 흔한 패턴(사전 단어 등) 검사는 하지 않고 이어지는 숫자만 다룬다.
- 점수는 그대로 두고 안내만 한다(길이에서 빼기, 점수 상한 59점 기각). 다른 플랫폼 구현과 공통 샘플 점수에 주는 영향이 가장 작다.

## 검증

- `npm run check` 통과.
- 독립 코드 리뷰: 알고리즘 버그 없음, 낮음 3건(방향 전환 사례, 비ASCII 숫자·서로게이트 사례, 정책 문구의 "한 방향") 반영. 방향 전환 처리를 일부러 틀리게 바꾸면 새 테스트 7건이 실패하는 것을 확인했다.

## 검증하지 못한 것

1. Apple 클라이언트는 아직 이 안내가 없다. 강도 표시를 구현할 때 같은 규칙을 넣어야 한다.

## AI의 오류와 정정

1. 처음 테스트에는 방향이 바뀐 뒤 다시 이어지는 사례(`1210`, `2123`)가 없어, 방향 전환 처리를 틀리게 바꿔도 통과했다.
2. 정책 문구가 "1씩 오르거나 내리는"만 적어 `121`처럼 오르내리는 경우도 포함되는 것으로 읽힐 수 있었다.
