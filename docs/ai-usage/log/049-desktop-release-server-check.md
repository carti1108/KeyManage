# 2026-11-01 · 데스크톱 릴리스 빌드의 서버 통신 확인

- 이슈·PR: PR #81
- 커밋: b22a027

> **요약** 배포 서버 없이 로컬 HTTPS 프록시로 데스크톱 릴리스 빌드가 서버와 통신하는지 확인했다. 로그 023의 미검증 항목(릴리스 빌드의 서버 통신)을 닫았다. README의 릴리스 빌드 명령이 릴리스 CSP를 빠뜨리는 명령으로 적혀 있어 바로잡았다.

## 사용 도구

- 도구: Claude Code (Opus 5.5)
- 외부 도구: mkcert 1.4.4, Caddy 2.11.7 (winget으로 설치)

## 요청

인수인계 문서의 남은 일 중 빌드된 데스크톱 앱이 실제 서버와 통신하는지 확인하는 일을 진행하도록 했다.

## AI 산출물

- 확인 방법 4가지 제안: 로컬 HTTPS 프록시, 임시 공개 터널, 배포 서버 먼저 결정, 자동 검사만 보강
- mkcert 로컬 인증서와 Caddy 프록시(`https://localhost:8443` → 8080) 구성, 앱 출처만 CORS 허용한 백엔드 실행
- 서버 주소를 넣은 릴리스 빌드와 실행, curl로 HTTPS 인증서 검증과 CORS 허용·거절 확인
- `Apps/Web/README.md`: 릴리스 빌드 명령 정정(`npm run tauri:build`), 낡은 CSP·서버 주소 설명 갱신, 로컬 확인 절차 추가

## 검증

| 검증 | 결과 |
| :--- | :--- |
| 릴리스 CSP 파일 | `connect-src`에 `https://localhost:8443`만 추가됨 |
| 번들의 서버 주소 | 빌드 결과 JS에 `https://localhost:8443` 포함 |
| curl: HTTPS와 CORS | 인증서 검증 통과. `http://tauri.localhost`는 허용, 다른 출처는 403 |
| 릴리스 앱 수동 확인(사람) | 가입·로그인·항목 저장·브라우저 동기화 정상, 화면 깨짐 없음 |
| `bash Scripts/check-docs.sh` | 통과 |

## 검증하지 못한 것

1. 실제 배포 서버(공인 인증서, 실제 도메인)에서의 통신. 배포 방식이 정해지면 다시 확인한다.
2. 설치 파일(NSIS)로 설치한 앱. 실행 파일만 빌드했다(`--no-bundle`).
3. macOS 앱 출처(WKWebView)와 그 CORS 값
