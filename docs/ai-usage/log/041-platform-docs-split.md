# 2026-11-01 · 플랫폼 ADR과 문서를 각 플랫폼 폴더로 분리 (#69 PR B)

> 요약: 웹·Apple·백엔드 전용 ADR 12개를 번호와 본문을 그대로 둔 채 각 플랫폼의 `docs/adr/`로 옮기고, `docs/iOS`와 `docs/reports`를 `Apps/Apple/docs`로 합쳤다. 문서 검사 스크립트가 플랫폼 문서 폴더와 플랫폼 접두어 ADR 번호(`ADR-WEB-001` 등)까지 검사하도록 넓혔다. 독립 리뷰에서 나온 검사 누락 대부분을 고쳤다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), GitHub CLI
- 플러그인/스킬: `project-docs:ai-usage`, 독립 리뷰 서브에이전트

## 요청

- PR A(#71)를 머지한 뒤 #69의 다음 단계(플랫폼 문서 분리)를 진행했다. 구조는 앞선 대화에서 사람이 정했다: 정책·공통 ADR은 `docs/`에 단일 원천으로 두고, 플랫폼 문서는 각 플랫폼 폴더에 둔다.

## AI 산출물

- ADR 이동(번호·본문 그대로)
  - 웹: ADR-0012·0013·0018~0020 → `Apps/Web/docs/adr/`
  - Apple: ADR-0014~0017 → `Apps/Apple/docs/adr/`
  - 백엔드: ADR-0002·0003·0007 → `Back/docs/adr/`
  - ADR-0004(영역 간 격리)는 본문을 확인한 뒤 모든 플랫폼에 걸친 결정이라 공통으로 남겼다.
- `docs/iOS/README.md`와 실험 보고서 3개를 `Apps/Apple/docs/`로 옮기고 링크를 고쳤다. 공통 로그와 중복된 Apple 전용 AI 로그 인덱스는 지웠다.
- 플랫폼 README(웹·Apple·백엔드)와 플랫폼 ADR 목록 README를 새로 쓰고, 루트 문서 지도와 공통 ADR 목록을 갱신했다.
- `Scripts/check-docs.sh`
  - 루트에서 두 단계 아래까지의 `docs/`를 링크·번호 검사에 넣고, 그 안의 ADR 목록 표도 검사한다.
  - ADR 번호 `ADR-0001`과 `ADR-WEB-001` 형식을 인식하고, 모든 ADR 폴더에서 번호가 겹치면 위반으로 본다.
- `CLAUDE.md`에 플랫폼 ADR 위치와 번호 규칙을, `.gemini` 규칙에 바뀐 Apple 문서 경로를 적었다.

- `Scripts/check-docs.sh`: 통과.
- 위반 사례를 일부러 만들어 검사가 잡는지 확인했다: 폴더를 넘는 번호 겹침, 목록 표 누락, 없는 번호 참조, 형식이 틀린 번호, 파일 이름과 첫 줄 번호 불일치, 중첩 docs 폴더의 깨진 링크(한 번만 보고). 확인 뒤 임시 파일은 지웠다.
- 독립 리뷰(작성 맥락과 분리된 서브에이전트): HIGH 0건, MEDIUM 2건, LOW 6건.
  - 반영: adr-manager 스킬의 전체 순번 규칙과 충돌하지 않도록 CLAUDE.md에 플랫폼 번호 규칙 추가; 형식이 틀린 번호 검출; ADR 번호 안의 정책 접두어 이중 보고 방지; 파일 이름과 첫 줄 번호 비교; 중첩 docs 중복 검사 방지; 폴더 이름 대소문자 차이로 Windows와 Linux 결과가 갈리는 문제; 플랫폼 실험 ADR의 위치 기준.
  - 반영하지 않음: 플랫폼 ADR 폴더에 README가 없을 때 종료 코드가 루트(2)와 다르게 1인 점. 현재 레포 구성에서는 영향이 없다.

## AI의 오류와 정정

1. 플랫폼 ADR 목록 README에서 공통 ADR로 가는 상대 경로의 깊이를 잘못 계산했다. 검사 전에 고쳤다.
