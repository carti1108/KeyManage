# 2026-10-29 · API 클라이언트와 계정 인증 구현 (ADR-0013, #34)

> 요약: 웹 MVP 세 번째 단계로 fetch 기반 API 클라이언트와 가입·로그인·로그아웃 유스케이스를 만들었다. 데스크톱 앱의 서버 요청 경로는 사람이 고른 방향대로 ADR-0013에 기록했다. 독립 보안 리뷰에서는 확신도 8 이상의 취약점이 나오지 않았고, 코드 리뷰 지적 8건과 보안 리뷰의 낮은 확신도 참고 3건을 모두 반영했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest, Spring Boot 테스트(MockMvc)
- 플러그인/스킬: `adr-manager:adr-manager`, `superpowers:test-driven-development`, `code-review`(독립 서브에이전트), `security-review`(독립 서브에이전트), `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 앞 단계 PR을 머지했다는 알림과 함께 웹 계획의 다음 단계(API 클라이언트·인증)를 이어서 진행.

## AI 산출물

- ADR-0013: 데스크톱 앱도 웹뷰 fetch로 요청하고, 릴리스 CSP에는 빌드할 때 정한 서버 출처 하나만 연다.
- 백엔드: 설정한 출처만 허용하는 CORS 필터(기본은 모두 거절, 사전 요청은 토큰 필터 앞에서 처리), 거절 응답은 `403 ORIGIN_NOT_ALLOWED` 표준 본문.
- 웹 domain: 가입(새 salt, 600,000회)·로그인(prelogin 값 검증 후 인증 해시 전송)·로그아웃 유스케이스, 서버 오류 구분(ServerError·NetworkError·UnexpectedResponseError).
- 웹 adapters: fetch 클라이언트(HTTPS 출처만, 쿠키 미전송, 리다이렉트 거부, 30초 제한, Retry-After), 인증 API 어댑터.
- 데스크톱: `npm run tauri:build`가 서버 출처를 CSP에 더한 릴리스 설정을 만들어 넘기는 스크립트.

## 사람의 판단

- 데스크톱 요청 경로(CSP에 서버 출처 하나)와 서버 주소 결정 방식(빌드할 때 고정)을 선택지 중에서 골랐다.
- ADR-0013 초안을 확인하고 승인했다.

## 검증

- 웹 `npm run check`(테스트 57건), 백엔드 `./gradlew check` 통과.
- 독립 보안 리뷰: 확신도 8 이상 취약점 없음.
- 독립 코드 리뷰 8건 반영. 반영 전 새 테스트가 실패하는 것을 먼저 확인했다.
- 릴리스 설정 스크립트를 실제로 실행해 CSP에 서버 출처만 더해지는 것과, 주소가 없을 때 멈추는 것을 확인.

## 검증하지 못한 것

1. 실제 데스크톱 릴리스 빌드에서 서버와 통신하는 것은 배포할 서버가 정해진 뒤 확인한다.
2. TLS를 끝내는 프록시 뒤 같은 출처 배포는 설정 안내만 남겼다. 배포 방식을 정할 때 다시 검토한다.
3. 세션 토큰은 이번 단계에서 메모리에만 둔다. 영구 저장 여부는 자동 잠금(SEC-003)·데스크톱 저장소 단계에서 정한다.

## AI의 오류와 정정

1. 인증 유스케이스를 테스트보다 먼저 작성했다. 구현을 빈 껍데기로 바꿔 테스트 9건이 모두 실패하는 것을 확인한 뒤 되돌렸다.
2. 서버 주소 검사가 호스트 이름의 `*`를 막지 않아 CSP에 와일드카드가 들어갈 수 있었다. 테스트를 쓰다 발견해 허용 문자를 제한했다.
3. 릴리스 CSP 테스트 일부가 구현 없이도 통과했다. 예외 종류까지 확인하도록 고쳤다.
4. 리뷰 지적: TLS를 끝내는 프록시 뒤에 웹을 같은 출처로 두면 CORS 검사가 POST를 막는다. 설정 안내를 문서와 설정 파일에 남겼다.
5. 리뷰 지적: 릴리스 스크립트가 경로 비교에 실패하면 조용히 건너뛰어 지난 빌드의 CSP로 빌드될 수 있었다. 실행 파일을 분리하고 시작할 때 지난 설정을 지우게 했다.
6. 리뷰 지적: Node 22.12~22.17은 `.ts` 파일을 바로 실행하지 못하는데 engines가 이를 허용했다. 22.18 이상으로 올렸다.
7. 리뷰 지적: 본문을 받는 중 시간 초과를 형식 오류로 분류했고, 이메일 검사가 서버보다 느슨해 불필요한 키 유도를 했다. 둘 다 고쳤다.
