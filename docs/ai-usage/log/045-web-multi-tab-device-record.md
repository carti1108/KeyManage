# 2026-11-01 · 웹 여러 탭 기기 기록 동기화

- 이슈·PR: #65, PR #77
- 커밋: 78d103d, c9ed977, 91967d2, 728f4f1, 2346810, 088db5d, 8a91b74, 81fded1, fd435e7, eebc2b5, 10717d9, 5debe97, 693b44c, 4bc88e0

> **요약** 같은 계정을 연 여러 탭이 기기 기록을 덮어써 오프라인 대기 내용이 사라지던 문제를 고쳤다. 탭 간 잠금 아래에서 기록을 읽고 병합해 쓰고, 잠금·로그아웃·기록 변경·조작을 다른 탭에 알린다. 사람이 "여러 탭은 함께 동기화", "암호화 키는 탭 사이로 넘기지 않음", "잠금은 원인에 따라 모든 탭 또는 그 탭만"을 정했다.

## 사용 도구

- 도구: Claude Code (Opus 5.5). 구현 서브에이전트 1개, 독립 리뷰 서브에이전트 1개
- 플러그인·스킬: superpowers:brainstorming, superpowers:writing-plans, adr-manager, policy-manager, project-docs:ai-usage

## 요청

이슈 #65의 웹 작업을 이어 하기로 했다. 여러 탭은 함께 동기화되는 것이 맞다는 방향을 주었다. 구현은 이 세션에서 하되, 단계마다 서브에이전트를 나누지 말고 구현과 리뷰 두 에이전트로만 나누도록 요청했다.

## AI 산출물

- 설계 문서와 구현 계획(8단계). 구현자 입장의 검토 서브에이전트가 설계를 먼저 읽고 질문 5건과 코드 충돌 3건을 냈다.
- ADR-WEB-001(웹 여러 탭 기기 기록), `Apps/Web/docs/device-storage.md` 계약 추가, SEC-003 웹 적용 범위 보완
- 탭 간 포트(`TabLock`, `TabChannel`)와 브라우저 어댑터(`navigator.locks`, `BroadcastChannel`, 미지원 시 탭 하나 동작)
- 쓰기 직전 판단 함수(그대로 쓰기·병합·건너뜀·다른 곳에서 로그아웃·비밀번호 바뀜)와 세션의 읽기·병합·쓰기
- 다른 탭 알림 처리, 잠금 원인별 전파 범위, 조작 공유(1초에 최대 1번), 재전송 단일 탭, 모든 탭 기준 로그아웃 확인
- 세션 파일이 846줄이 되어 타입을 `sessionTypes.ts`로 분리(762줄)

## 사람의 판단

| 판단 | 내용 |
| :--- | :--- |
| 방향 결정 | 같은 계정의 여러 탭은 같은 볼트를 보이고 함께 동기화한다. 한 탭의 잠금·로그아웃은 모든 탭에 적용한다. |
| 채택 | 암호화 키를 탭 사이로 넘기면 비밀번호 없이 열리는 경로와 XSS 피해 범위가 넓어진다는 설명을 듣고, 탭마다 따로 잠금을 푸는 방식을 골랐다. |
| 채택 | 잠금 원인을 나누는 AI 안을 받았다. 잠금 버튼·보이는 탭의 시간 초과·로그아웃은 모든 탭, 새로고침·닫기·동결·"즉시" 설정의 숨김은 그 탭만이다. |
| 채택 | 다른 계정으로 로그인하면 이전 계정의 다른 탭을 로그아웃시키는 추천안과 SEC-003 문구 추가를 승인했다. |
| 수정 | 계획의 "단계마다 서브에이전트" 방식 대신 구현·리뷰 두 에이전트로만 나누게 했다. |

## 검증하지 못한 것

1. 로컬 통합 테스트. 백엔드(`localhost:8080`)가 떠 있지 않아 CI 결과로만 확인했다.
2. 실제 브라우저 여러 탭에서의 `navigator.locks`·`BroadcastChannel` 동작. 테스트는 메모리 안의 가짜 허브로 두 탭을 흉내 냈다.
3. Safari와 Tauri 웹뷰(WebView2·WKWebView).
4. 두 탭이 처음 로그인할 때 드물게 겹치면 로그아웃한 계정의 암호화된 기록이 남을 수 있다. 고치지 않고 명세 4장에 알려진 제약으로 적었다.
5. "알림을 놓쳐도 잠금을 풀 때 최신 기록으로 연다" 등 테스트 3건은 구현 전에도 통과해, 실패를 먼저 확인하지 못했다.

## AI의 오류와 정정

| 오류 | 발견 | 조치 |
| :--- | :--- | :--- |
| 새 웹 ADR 번호를 ADR-0021이라고 안내함(실제 규칙은 `ADR-WEB-001`부터) | AI가 웹 ADR 목록 문서를 읽고 발견 | 사용자에게 정정하고 ADR-WEB-001로 씀 |
| 설계의 "대기 표시는 OR로 합침"을 그대로 두면 두 탭이 병합을 주고받으며 대기를 계속 다시 켬 | 구현 서브에이전트가 구현 중 발견 | 합친 내용이 한쪽과 같으면 그쪽 값을 따르게 바꾸고 ADR·명세를 맞춤 |
| 계획의 "수정 횟수 카운터"는 재연결 중 다른 탭의 대기 내용을 서버 볼트로 덮을 수 있음 | 구현 서브에이전트가 발견 | 기존 볼트 객체 비교를 유지 |
| 잠금을 풀 때 기기 기록으로 메모리를 덮어써, 기기에 쓰지 못한 대기 변경이 사라짐(탭 하나에서도 생기는 회귀) | 독립 리뷰 1차, 재현 테스트로 확인 | 잠금 해제 때는 병합으로 처리하고 회귀 테스트 추가 |
| 숨겨진 탭의 타이머 만료가 모든 탭을 잠가, 방금 연 다른 탭이 몇 초 만에 잠길 수 있음 | 독립 리뷰 1차 | 숨겨진 탭의 만료는 그 탭만 잠그고, 잠금 해제 때 조작을 알림 |
| SEC-003에 계정 전환·숨겨진 탭 만료 규칙 누락, 기록을 읽지 못하면 확인 없이 로그아웃 | 독립 리뷰 1차 | 정책 보완, 읽기 실패 시 확인 |
| 구현 서브에이전트가 adr-manager의 작성 전 승인 단계를 건너뜀 | 구현 서브에이전트가 보고 | 설계에서 승인된 결정이라 그대로 두고 PR에서 확인받기로 함 |
