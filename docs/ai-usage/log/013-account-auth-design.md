# 2026-10-28 · 계정 인증 설계: 인증 해시 분리와 서버 세션 (ADR-0008, SEC-002)

> 요약: 인증 공백(#10)을 해결하기 위한 설계를 문서로 확정했다. 마스터 키에서 HKDF로 암호화 키와 인증 해시를 분리하고, 서버 저장형 세션 토큰으로 볼트 접근을 계정 단위로 통제한다. 검토 중 키 구조와 salt 위치의 결함을 발견해 vault-spec을 고쳤다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), 다른 AI(Gemini)와 나눈 대화 일부를 검토 입력으로 사용
- 플러그인/스킬: `adr-manager:adr-manager`, `policy-manager:policy-manager`, `project-docs:ai-usage`

## 요청

- 인증(#10) 진행을 요청받았다. 진행 중 애플 암호 앱의 방식, 오픈소스 공개 시 바뀔 점, 애플 생태계를 넘는 크로스 플랫폼 동기화 방식에 대한 의견을 요청받았다.

## AI 산출물

- vault-spec 검토로 발견한 결함 2건: 마스터 비밀번호에서 유도한 키로 볼트를 바로 암호화해 안전한 인증 정보를 만들 수 없는 점, salt가 볼트 안에 있어 새 기기가 로그인 전에 키를 유도할 수 없는 점.
- 인증 설계안 7개 항목(인증 해시, 600,000회, 이메일·계정당 볼트 1개, 서버 저장형 토큰, 시도 제한, 파일 저장소, 범위 밖 항목)과 대안 비교.
- 애플 iCloud 키체인 방식(기기 신뢰 그룹, HSM 에스크로)과의 비교. 하드웨어를 통제해야 가능한 구조라 그대로 도입할 수 없다는 판단.
- 다른 AI 의견 검토: 오픈소스 관련 의견에서 빠진 HTTPS 필수, 설치본별 서버 비밀키, 가입 끄기, 신뢰 프록시를 지적했다. 동기화 방식 의견에서는 구글 드라이브가 원자적 조건부 쓰기를 지원하지 않아 ADR-0006을 지킬 수 없을 가능성, Supabase 무료 티어에 대한 과장, 현재 설계에 없는 실시간 반영 주장을 지적했고, 크로스 플랫폼의 핵심 과제로 자동 완성을 제시했다.
- [`docs/adr/ADR-0008-auth-hash-and-server-session.md`](../../adr/ADR-0008-auth-hash-and-server-session.md), [`docs/policies/SEC/SEC-002-account-auth-and-session.md`](../../policies/SEC/SEC-002-account-auth-and-session.md) 작성, SEC-001·vault-spec·api-spec·open-questions·CHANGELOG 수정.

## 사람의 판단

- 인증 설계안 7개 항목을 추천대로 승인했다.
- 기존 기기 승인으로 새 기기를 추가하는 기능을 후속으로 넣기를 원했다.
- 프로젝트 목표를 포트폴리오·시연으로 정했다. 실제 배포 방식은 백엔드 완성 후 결정하기로 했다.
- SEC-002의 8개 카테고리 제안을 수정 없이 승인했다.
