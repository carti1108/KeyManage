# 2026-10-31 · 볼트 잠금·잠금 해제와 자동 잠금 구현 (SEC-003, #44)

> 요약: 웹 MVP 다섯 번째 단계로 볼트 세션(로그인·가입·잠금·잠금 해제·로그아웃)과 자동 잠금을 만들었다. 잠금 해제 확인 방식에 걸린 보안 결정(모든 계정이 볼트를 갖도록 가입 직후 빈 볼트 저장)은 사람이 정했다. 독립 보안 리뷰와 코드 리뷰가 모두 같은 경쟁 조건(잠금 뒤 진행 중 작업이 볼트를 다시 여는 문제)을 찾았고, 코드 리뷰 10건을 모두 반영했다.

## AI 산출물

- SEC-003: 모든 계정이 볼트를 갖는 규칙, 잠긴 동안 메모리에 남기는 값, 자동 잠금 시간 기준, 웹의 페이지 떠남·탭 동결 시 잠금.
- `domain/session`: 로그인·가입(볼트가 없으면 빈 볼트 저장), 잠금(키·평문 폐기), 저장해 둔 암호화 볼트로 오프라인 잠금 해제, 잠금 해제 직후 동기화, 로그아웃, 잠금·잠금 해제 알림. 세대 값으로 잠금·로그아웃 전에 시작한 작업의 결과를 버린다.
- `domain/lock`: 자동 잠금 타이머(기본 5분, 즉시·1·5·15·60분), 백그라운드 타이머 지연을 고려한 경과 시간 판정.
- `adapters/browser`, `app`: 조작·화면 전환·탭 동결 이벤트 연결, 볼트가 열려 있는 동안만 타이머가 돌도록 조립.
- 로그인·가입 결과에 잠금 해제용 KDF 값, 동기화 결과에 암호화 볼트 추가. 인증 해시 바이트는 보낸 뒤 지운다.

## 사람의 판단

- 잠금 해제 확인을 위해 가입 직후 빈 볼트를 저장한다(인증 해시를 메모리에 남기는 방식, 서버 로그인으로 확인하는 방식 기각).

- `npm run check`(테스트 141건) 통과.
- 독립 보안 리뷰: 확신도 8 이상 1건(잠금 뒤 진행 중 작업이 볼트를 다시 엶). 반영.
- 독립 코드 리뷰 10건 반영. 반영 전 새 테스트가 실패하는 것을 먼저 확인했다.

## 검증하지 못한 것

1. 잠금 화면·가림 화면과 실제 브라우저에서의 자동 잠금 동작은 화면 단계에서 확인한다.
2. 화면이 `state()`로 받은 평문 볼트를 잠근 뒤에도 들고 있지 않도록 하는 것은 화면 단계의 몫이다.
3. 백그라운드 탭에서 타이머가 늦게 도는 동안(다시 보이기 전까지)은 키가 메모리에 남을 수 있다.

## AI의 오류와 정정

1. 잠금·로그아웃이 진행 중인 저장·잠금 해제·로그인을 끊지 않아, 작업이 끝나면 볼트가 비밀번호 없이 다시 열릴 수 있었다. 두 리뷰가 모두 지적해 세대 값으로 늦게 끝난 결과를 버리게 했다.
2. 되돌림 감지 기준을 계정과 상관없이 공유해, 같은 탭에서 다른 계정으로 로그인하면 되돌림으로 오인했고 로그인에는 수락 방법도 없었다. 로그아웃·계정 전환 시 기준을 지우고 로그인에 수락 옵션을 추가했다.
3. 잠금 해제 직후 동기화가 네트워크 외 이유(세션 만료, 서버 오류)로 실패하면 비밀번호가 맞아도 잠금을 풀 수 없었다. 세션 만료는 로그아웃, 그 밖의 오류는 저장해 둔 볼트로 열게 했다.
4. 탭 동결·뒤로 가기 캐시에서는 타이머가 돌지 않아 잠금이 무기한 늦어질 수 있었다. 해당 이벤트에서 바로 잠그게 했다.
5. 가입 뒤 빈 볼트 저장 실패, 서버 볼트가 사라진 뒤의 되돌림 수락, 이미 열린 세션에 자동 잠금을 붙이는 경우를 처리하지 않았다. 각각 고쳤다.
