# 2026-10-31 · 웹 볼트 항목 목록·상세·추가·수정·삭제 화면 (#51)

## AI 산출물

- 정책: VLT-001에 서비스 이름 필수, 삭제 확인과 문구 추가.
- `domain/vault/itemList`: 한국어 사전순 정렬, 서비스 이름·아이디·URL 검색, 입력 검사, 바뀐 필드만 고르는 비교.
- `domain/vault/vaultData`: 수정 시 선택 필드에 null을 주면 필드를 없앤다.
- `ui/vault`: 목록·상세·추가/수정 폼·삭제 확인, 저장 중복 방지.
- `ui/components/ConfirmPrompt`: 되돌림 확인과 삭제 확인이 같이 쓰는 확인 상자.

## 사람의 판단

- 입력 규칙·정렬·URL 표시 방식은 되돌리기 쉬운 결정이라 추천 기본값으로 정하고 PR에 적었다.
- 실제 Chrome에서 항목 추가 뒤 비밀번호 저장 제안이 뜨는 것을 사람이 찾았다. 리뷰 반영(폼 제출 제거)만으로는 막히지 않았다.
- 항목 입력값을 검사하지 않는 이유를 물었다. 사이트마다 규칙이 달라 막지 않고, 다음 단계에서 강도 경고만 보이기로 했다.

## 검증

- `npm run check`(테스트 252건) 통과. Chrome에서 항목 추가·수정 뒤 저장 제안이 뜨지 않고 비밀번호가 가려 보이는 것을 사람이 확인했다.
- 독립 보안 리뷰: 중간 2건 반영. 반영 전 새 테스트가 실패하는 것을 먼저 확인했다.
- 독립 코드 리뷰: 중간 3건, 낮음 3건 반영.

## 검증하지 못한 것

1. Edge·Firefox에서의 저장 제안과 CSS 가림 동작. Chrome은 사람이 확인했다.
2. 편집 중 자동 잠금이 걸리면 저장하지 않은 입력은 사라진다.
3. 오프라인에서 저장하면 실패 안내만 보인다. 로컬 저장 후 재연결 동기화는 아직 없다.

## AI의 오류와 정정

1. 항목 폼을 일반 `<form>`으로 만들어, 다른 사이트의 아이디·비밀번호 쌍을 브라우저가 이 앱의 로그인 정보로 저장하려 할 수 있었다. `autocomplete="off"`는 비밀번호 칸에서 무시된다. 폼 제출 대신 버튼과 Enter로 저장하게 했다.
2. 아이디·URL·메모 칸의 맞춤법 검사를 끄지 않아, 향상된 맞춤법 검사를 켠 브라우저가 내용을 외부로 보낼 수 있었다.
3. 수정하면 비어 있던 선택 필드가 빈 문자열로 생겼고, 아무것도 고치지 않아도 저장해 다른 기기의 변경을 병합에서 덮어쓸 수 있었다. 바뀐 필드만 저장하고 지운 필드는 없애게 했다.
4. 삭제를 기다리는 동안 다른 화면으로 갈 수 있어, 삭제가 끝나면 입력 중인 화면을 빼앗거나 실패를 숨겼다.
5. 화면이 바뀐 뒤 포커스가 사라졌고, 비밀번호 칸이 정의 목록(`dl`) 규칙을 어겼다.
6. 항목 폼 비밀번호 칸이 type=password라 Chrome이 다른 사이트 자격 증명을 이 앱 로그인으로 저장하자고 했다. 사람이 브라우저에서 찾았다. text 칸을 CSS로 가리고, 지원하지 않는 브라우저는 type=password로 돌아가게 했다. 대신 화면 낭독기가 글자를 읽을 수 있다.
7. 개발 프록시가 브라우저 Origin을 넘겨 백엔드가 가입을 403으로 막았다. 이전 단계부터 있던 버그로, 브라우저로 처음 가입해 보며 드러났다. 개발 프록시에서만 Origin을 지웠다. 원인을 찾으며 사람이 쓰던 이메일로 가짜 가입 요청을 보내 열 수 없는 계정을 만든 실수도 있었다.
8. 다른 기기 삭제를 흉내 낸 테스트가 항목을 배열에서 빼 버려, 실제 동기화(삭제 표시만 남김)를 검증하지 못했다.
