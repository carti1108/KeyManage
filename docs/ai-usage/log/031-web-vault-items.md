## 검증하지 못한 것

1. Chrome·Edge가 항목을 추가한 뒤 비밀번호 저장을 제안하지 않는지는 실제 브라우저에서 사람이 확인해야 한다. jsdom은 브라우저의 비밀번호 저장 판단을 흉내 내지 못한다.
2. 편집 중 자동 잠금이 걸리면 저장하지 않은 입력은 사라진다.
3. 오프라인에서 저장하면 실패 안내만 보인다. 로컬 저장 후 재연결 동기화는 아직 없다.

## AI의 오류와 정정

1. 항목 폼을 일반 `<form>`으로 만들어, 다른 사이트의 아이디·비밀번호 쌍을 브라우저가 이 앱의 로그인 정보로 저장하려 할 수 있었다. `autocomplete="off"`는 비밀번호 칸에서 무시된다. 폼 제출 대신 버튼과 Enter로 저장하게 했다.
2. 아이디·URL·메모 칸의 맞춤법 검사를 끄지 않아, 향상된 맞춤법 검사를 켠 브라우저가 내용을 외부로 보낼 수 있었다.
3. 수정하면 비어 있던 선택 필드가 빈 문자열로 생겼고, 아무것도 고치지 않아도 저장해 다른 기기의 변경을 병합에서 덮어쓸 수 있었다. 바뀐 필드만 저장하고 지운 필드는 없애게 했다.
4. 삭제를 기다리는 동안 다른 화면으로 갈 수 있어, 삭제가 끝나면 입력 중인 화면을 빼앗거나 실패를 숨겼다.
5. 화면이 바뀐 뒤 포커스가 사라졌고, 비밀번호 칸이 정의 목록(`dl`) 규칙을 어겼다.
6. 다른 기기 삭제를 흉내 낸 테스트가 항목을 배열에서 빼 버려, 실제 동기화(삭제 표시만 남김)를 검증하지 못했다.
