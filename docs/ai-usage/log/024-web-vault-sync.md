# 2026-10-29 · 볼트 모델·항목 병합·동기화 구현 (#36)

> 요약: 웹 MVP 네 번째 단계로 평문 볼트 모델, 항목 병합, 409 자동 병합 재시도를 갖춘 동기화를 만들었다. 저장 데이터 형식과 보안 경계에 걸린 세 가지(삭제 항목 내용 제거, 모르는 필드 보존·높은 버전 읽기 전용, revision 되돌림 경고)는 사람이 정했다. 독립 보안 리뷰에서는 확신도 8 이상의 취약점이 나오지 않았고, 코드 리뷰 지적 8건은 모두 반영했다.

## AI 산출물

- 문서: VLT-001과 vault-spec 4장에 병합·호환 규칙, 되돌림 경고, 시각 형식, 요청 제한 시간(30초) 반영.
- `domain/vault`: 볼트 해석·검증(모르는 필드 보존, null 처리, UTC 시각만 허용), 항목 추가·수정·삭제(삭제는 내용 제거, 변경 시각은 늘기만 함), 항목 병합.
- 동기화: 불러오기(볼트 없으면 revision 0), 저장(저장 전 규격 재확인, 5MB 초과 거절, 409면 병합 후 최대 3회 재시도), 되돌림 감지(기준은 동기화 밖에 두어 재로그인 뒤에도 유지).
- `adapters/http`: 볼트 API 어댑터(404는 볼트 없음).

## 사람의 판단

- 삭제 항목은 내용을 지우고 표시만 남긴다.
- 모르는 필드는 보존하고, 더 높은 스키마 버전은 읽기 전용으로 연다.
- 서버 revision이 되돌아가면 경고하고 사용자가 확인할 때만 받아들인다.

## 검증

- `npm run check`(테스트 100건) 통과.
- 독립 보안 리뷰: 확신도 8 이상 취약점 없음. 낮은 확신도 참고 중 저장 응답 revision 검증과 되돌림 감지의 한계 문서화를 반영.
- 독립 코드 리뷰 8건 반영. 반영 전 새 테스트가 실패하는 것을 먼저 확인했다.

## 검증하지 못한 것

1. 앱을 다시 켠 뒤의 되돌림 감지는 기기 저장소가 필요해 오프라인 저장소 단계로 미뤘다.
2. 악의적인 서버의 옛 볼트 재전송은 revision이 인증되지 않아 막을 수 없다. 막으려면 별도 결정(암호문 안의 증가 값)이 필요하다.
3. 삭제 표시 항목의 영구 삭제 시점은 아직 미정이다(open-questions).

## AI의 오류와 정정

1. 같은 초 안에 다시 고친 항목이나 다른 기기 시계가 앞선 항목은 병합에서 방금 한 수정이 사라질 수 있었다. 리뷰 지적으로 변경 시각이 항상 늘어나게 했다.
2. `undefined` 변경값이 필수 필드를 지워, 모든 기기가 열 수 없는 볼트를 올릴 수 있었다. 리뷰 지적으로 변경값을 거르고 저장 전에 규격을 다시 확인하게 했다.
3. 불러오기 응답을 기다리는 사이 저장이 끝나면 되돌림 경고가 잘못 뜰 수 있었고, 되돌림 기준이 동기화를 새로 만들 때마다 사라졌다. 리뷰 지적으로 요청 시점 값과 비교하고 기준을 동기화 밖으로 뺐다.
4. 시각 표기와 null 처리 규칙이 없어 다른 플랫폼과 결과가 달라질 수 있었다. 규격에 적고 검사를 추가했다.
5. 기존 정책의 네트워크 타임아웃(5초)과 앞 단계에서 만든 API 클라이언트의 제한 시간(30초)이 어긋나 있었다. 이번에 정책 값을 30초로 맞췄다.
