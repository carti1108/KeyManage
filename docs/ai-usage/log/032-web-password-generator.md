# 2026-10-31 · 웹 비밀번호 생성기와 강도 경고 (#53)

> 요약: 웹 MVP 아홉 번째 단계의 앞부분으로 GEN-001에 따른 비밀번호 생성기와 강도 점수·경고를 항목 폼에 붙였다. 클립보드 소각의 웹 한계 처리(최선을 다해 지우고 실패하면 돌아올 때 다시 지움)는 사람이 정했고 다음 PR에서 구현한다. 독립 보안 리뷰는 확신도 7 이상 발견이 없었고, 독립 코드 리뷰의 9건(접근성 위주)을 모두 반영했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest, Testing Library
- 플러그인/스킬: `superpowers:test-driven-development`, 독립 코드 리뷰·보안 리뷰 서브에이전트, `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 볼트 항목 화면을 병합한 뒤 다음 단계(생성기·클립보드)를 진행했다. 웹 브라우저가 클립보드 소각 정책을 다 지킬 수 없는 부분의 처리 방식을 물었고, 사람이 추천안을 골랐다.

## AI 산출물

- `domain/generator`: CSPRNG 균등 추출, 나머지 편향 제거, 빠진 문자군이 있으면 통째로 다시 뽑기, 옵션 검사, 코드포인트 기준 강도 점수.
- `ui/vault/PasswordGenerator`: 길이·문자군 선택, 다시 생성, 강도 표시, 잘못된 옵션 안내.
- 항목 폼: 생성기, 강도 게이지, 60점 미만 경고(저장은 허용).
- `.gitignore`: 개발 서버 데이터 폴더(서버 비밀키·계정 포함) 제외.

## 사람의 판단

- 웹 클립보드 소각은 최선을 다하고 실패하면 다시 돌아올 때 지운다. 읽기 권한을 요청하지 않으므로 그사이 직접 복사한 내용도 지워질 수 있다(읽기 권한 요청, 웹 복사 금지 기각).
- 9단계를 생성기와 클립보드 두 PR로 나누는 것을 받아들였다.

## 검증

- `npm run check`(테스트 293건) 통과. 생성 1,000회 문자군 포함, 고정 난수로 거부 샘플링·편향 제거, 플랫폼 공통 점수 샘플을 검증했다.
- 독립 보안 리뷰: 확신도 7 이상 0건.
- 독립 코드 리뷰: 중간 1건, 낮음 8건 반영. 생성기 안 Enter가 저장으로 넘어가지 않는 테스트는 방지 코드를 빼면 실패하는 것을 확인했다.

## 검증하지 못한 것

1. 실제 화면 낭독기에서 생성 알림과 취약 경고가 읽히는지.
2. 정책 공식은 문자 종류만 보므로 `Password123!` 같은 흔한 패턴도 보통(77점)으로 본다. 사전·패턴 검사는 정책을 바꿔야 한다.

## AI의 오류와 정정

1. 생성기를 열고 닫을 때 누른 버튼이 사라져 키보드 포커스를 잃었다. 열면 길이 칸, 닫으면 비밀번호 칸으로 옮겼다.
2. 길이를 고치는 중간값(예: 16을 20으로 바꾸는 중의 2)마다 경고가 깜빡였고, 잘못된 옵션 동안 이전 결과가 그대로 보였다.
3. `Number('1e1')`이 10으로 통과해 칸에 보이는 값과 다른 길이로 만들었다.
4. 강도 게이지 두 개가 같은 이름이었고, 새 비밀번호와 새로 생긴 경고가 보조 기술에 알려지지 않았다.
5. 테스트용 고정 난수가 바닥나면 테스트가 실패하지 않고 무한 루프에 빠질 수 있었다.
