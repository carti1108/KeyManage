# 2026-10-31 · 웹 로그인·가입·잠금 해제 화면과 자동 잠금 연결 (#48)

> 요약: 웹 MVP 일곱 번째 단계로 로그인·가입·잠금 해제 화면, 볼트 첫 화면, 가림 화면을 만들고 자동 잠금을 앱에 연결했다. 정책에 없던 마스터 비밀번호 최소 길이(12자)는 사람이 정했다. 독립 보안 리뷰는 확신도 7 이상 발견이 없었고, 독립 코드 리뷰의 중간 3건과 낮음 7건 중 8건을 반영했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest, Testing Library
- 플러그인/스킬: `policy-manager:policy-manager`, `superpowers:test-driven-development`, 독립 코드 리뷰·보안 리뷰 서브에이전트, `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 디자인 시스템 단계를 병합한 뒤 다음 단계(로그인 화면)를 진행했다. 가입 시 마스터 비밀번호 최소 길이를 묻는 질문에 추천안(12자)을 골랐다.

## AI 산출물

- 정책: SEC-002에 마스터 비밀번호 최소 12자(코드포인트 기준, 가입 시 클라이언트 검사)와 확인 입력. SEC-002·SEC-003·COM-001에 화면 오류 문구 추가.
- `domain/auth/masterPassword`: 새 마스터 비밀번호 검사.
- `ui/messages`: 오류를 정책 문구로 바꾸는 함수, 볼트 상태 안내 문구.
- `ui/session`: 세션 포트, 요청 처리 훅(중복 제출 방지, 서버 볼트 되돌림 확인 뒤 재요청), 상태별 화면 선택.
- `ui/screens`: 로그인·가입, 잠금, 볼트 첫 화면(항목 수), 가림 화면.
- `app`: 서비스 생성, 자동 잠금 연결, 탭 가림 여부 전달.

## 사람의 판단

- 가입 시 마스터 비밀번호 최소 길이를 12자로 정했다(8자·10자 기각).

## 검증

- `npm run check`(테스트 216건)와 프로덕션 빌드 통과.
- 독립 보안 리뷰: 확신도 7 이상 0건. 참고 사항 2건(실패한 비밀번호가 입력 칸에 남음, 모드 전환 뒤 되돌림 확인이 남음)은 반영.
- 독립 코드 리뷰: 중간 3건, 낮음 7건. 8건 반영. 반영 전 새 테스트가 실패하는 것을 먼저 확인했고, 중복 제출 테스트는 방지 코드를 빼면 실패하는 것도 확인했다.

## 검증하지 못한 것

1. 실제 브라우저에서 가입부터 잠금 해제, 로그아웃까지 이어지는 흐름은 사람이 확인한다.
2. 서버 주소 설정이 틀린 빌드는 빈 화면이 된다. 빌드 설정 오류라 후속으로 넘겼다.
3. 오프라인 안내는 다시 연결돼도 다음 잠금 해제 전까지 남는다. 재연결 동기화와 함께 다룬다.

## AI의 오류와 정정

1. 잠금 화면에서 로그아웃하면 서버 응답을 기다리는 동안(최대 30초) 화면이 바뀌지 않았다. 가짜 세션의 로그아웃이 바로 끝나서 테스트가 이를 숨겼다. 세션이 이 기기 정리를 먼저 끝내므로 바로 화면을 바꾸고, 가짜 세션도 실제처럼 늦게 끝나게 했다.
2. 되돌림 확인이 모드를 바꿔도 남아 있어 가입 화면에서 이전 로그인을 다시 보낼 수 있었다. 모드를 바꾸면 지우고, 확인은 취소에 포커스를 두는 alertdialog로 바꿨다.
3. 볼트 형식 오류와 동기화 충돌이 정책 문구 대신 공통 문구로 나왔다.
4. 가림 화면을 볼트 화면에만 씌워, 평문으로 펼친 마스터 비밀번호가 앱 전환 화면에 보일 수 있었다. 모든 화면을 덮게 했다.
5. 중복 제출 테스트가 버튼 비활성 때문에 통과해 방지 코드를 검증하지 못했다. 폼 제출을 두 번 보내도록 바꿨다.
