# 2026-11-01 · 문서 템플릿과 한국어 STE 규칙, 정책 10개 변환 (#70 PR 1)

- 이슈·PR: #70, #69(종료)
- 커밋: db3b1a0, 4336bc1, 1c47314, 99a66bc, 793c854

> **요약** 정책·ADR·플랫폼 명세·AI 로그 템플릿을 만들고, ASD-STE100 원칙을 한국어로 옮긴 작성 규칙 8개를 정했다. 정책 10개를 제목·표·번호 목록 구조로 옮겼다. 사람은 모든 내용이 같은 크기로 보이면 읽기 어렵다고 지적하며 시각 구조를 요구했고, 외부 스킬 설치 대신 템플릿과 STE 규칙을 고르게 했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), GitHub CLI
- 플러그인·스킬: `policy-manager:policy-manager`, `humanize-korean:humanize-scan`, `project-docs:ai-usage`, 독립 리뷰 서브에이전트

## 요청

- #70(문서 전반 가독성 정리)의 계획을 세우고 첫 PR을 진행했다.
- 사람은 AI의 첫 초안(같은 크기의 `- 필드:` 목록을 번호 목록으로만 바꾼 것)을 보고, 사람이 읽는 문서이니 마크다운 제목과 표로 위계를 만들라고 했다.
- 가독성 정리에 쓸 스킬을 GitHub에서 찾아보라고 했고, 결과를 본 뒤 설치하지 말고 기본 템플릿을 잡으라고 했다. 항공 정비 문서 언어(ASD-STE100)를 적용할 수 있는지도 물었다.

## AI 산출물

- 문서 점검에서 정책 사이의 충돌을 찾았다. COM-001의 "네트워크 타임아웃 5초"가 VLT-001과 웹 코드의 30초와 달랐다.
- COM-001에서 오류 안내를 COM-002로 나누고, 5초를 지웠다(내용 변경 커밋을 따로 둠).
- `docs/templates/`: 정책, ADR, 플랫폼 명세, AI 로그 템플릿. 각 README의 옛 틀은 템플릿 링크로 바꿨다.
- `docs/README.md`: 한국어 STE 규칙 8개(한 문장 한 사실, 문장 길이 권장 기준, 주어 명시, 조건 먼저, 한 용어 한 뜻, 명사 셋 이상 잇지 않기, 주의 먼저, 사용자 문구 예외).
- 정책 10개 변환: 요약 → 용어 → 규칙 → 값(표) → 예외 → 사용자 문구(표) → 검증 방법(표) → 근거 → 이력(접기). COM-001은 같은 동작을 부르던 "소각·비움·삭제·덮어쓰기"를 규칙 본문에서 "비운다"로 통일했다.
- GitHub에서 문서 작성 스킬 후보 5개를 찾아 별 수, 라이선스, 맞는 곳을 비교했다.
