## AI 산출물

- 프롬프트 대조 분석: GEN-001·api-spec·이슈 #7을 비교해 점수 공식이 어느 문서에도 없다는 점, api-spec 2.2의 사전 패턴·재사용 진단이 범위에서 빠졌다는 점, SEC-001과 api-spec 2.1·2.2가 충돌한다는 점을 보고했다.
- 점수 공식 후보 2개(A: `min(100, 비트)`, B: `비트/128×100`)와 샘플별 등급 비교표, 거부 샘플링 제안.
- Gemini 분석 검토: 2.1(생성)도 같은 충돌이라는 점이 빠졌고, "원래 의도는 공개 유틸리티"라는 해석은 문서에 근거가 없으며, SRP 필수와 요청 제한 효과는 과장이라고 지적했다. 이슈 #7을 동기화 작업으로 바꾸는 대신 닫고 새 이슈를 여는 절차를 제안했다.
- [`docs/adr/ADR-0005-client-only-password-generation-and-audit.md`](../../adr/ADR-0005-client-only-password-generation-and-audit.md) 작성.
- [`GEN-001`](../../policies/GEN/GEN-001-password-generation-and-entropy-scoring.md) 수정: 공식, 문자군 크기, 기타 문자 +7, 거부 샘플링, 문구, 공통 샘플, 적용 범위.
- `api-spec.md` 2.1·2.2 제거, `open-questions.md` 1건 등록, 정책 CHANGELOG 갱신.

## 사람의 판단

- 점수 공식으로 A(`min(100, floor(비트))`)를 선택했다.
- 거부 샘플링과 기타 문자 +7 규칙은 원리 설명을 들은 뒤 승인했다.
- Gemini의 방안 A(백엔드는 동기화를 먼저)를 방향으로 받아들이되, AI가 제안한 보정안(2.1도 제거, #7은 닫고 새 이슈, ADR-0005 작성)을 승인했다.
