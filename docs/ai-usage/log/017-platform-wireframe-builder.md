# 2026-10-28 · 플랫폼별 와이어프레임 Figma 빌더 제작

> 요약: 클라이언트 착수 전에 플랫폼별 화면 형태를 눈으로 정할 수 있도록, iOS·Android·Web·macOS 저충실도 와이어프레임 26개를 그리는 Figma 플러그인과 Figma 없이 돌릴 수 있는 모의 검증기를 만들었다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Node.js
- 플러그인/스킬: `code-review`(Claude Code 내장, 독립 서브에이전트), `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 클라이언트가 어떤 형태로 만들어질지 정해지지 않아 방향을 잡기 어렵다며, 기존 `Tools/figma-builder`처럼 플러그인을 만들어 Figma에서 플랫폼별 와이어프레임을 볼 수 있게 해 달라는 요청.

## AI 산출물

- [`Tools/wireframe-builder/`](../../../Tools/wireframe-builder/README.md): `manifest.json`, `code.js`, `README.md`, `verify.js`.
- 화면 구성: 로그인, 가입, 볼트 목록(오프라인 배너), 항목 상세(복사 직후 30초 배지), 항목 편집, 생성기, 설정. 플랫폼 관례(iOS 탭·시트, Android Material 3·FAB, Web·macOS 3분할)를 따르고 화면마다 근거 정책 메모를 붙였다.
- 회색조 저충실도로 범위를 제한했다. 시각 디자인은 기존 DS Builder 단계로 남겼다.
- `verify.js`: 오토레이아웃 밖 FILL, 글꼴을 불러오지 않은 텍스트 수정, dynamic-page에서 `currentPage` 대입, 불러오지 않은 페이지의 children 접근 등 Figma API 오류 규칙을 흉내 낸 모의 실행기. CI 문서 작업에 추가했다.

## 사람의 판단

- 클라이언트 구현 전에 플랫폼별 형태를 Figma로 먼저 보기로 결정했다.
- 별도 플러그인으로 만들고 바로 진행하는 것은 합의한 확인 범위(위험도 낮은 작업은 진행 후 보고)에 따랐다.

## 검증

- `node --check`와 `verify.js` 모의 실행 통과: 4개 페이지, 화면 26개(iOS 7, Android 7, Web 6, macOS 6). 두 번 실행해 다시 그리기 후에도 페이지마다 보드 하나만 남고, 글꼴이 없으면 페이지를 만들지 않고 멈춤을 확인.
- 검증기 자체 검증: 다섯 가지 변형(FILL을 부모에 넣기 전에 설정, `currentPage` 대입, 화면 하나가 중간에 실패, 실패 정리 코드 제거, 글꼴 실패 시 중단 제거)을 만들어 모두 검증기가 실패로 잡는 것을 확인.
- 독립 리뷰(`/code-review`) 10건 모두 반영: 게이지 등급 이름을 GEN-001대로 '취약'으로, 복구 불가 경고와 클립보드 배지를 SEC-001·COM-001 원문으로 교체, 정책에 없는 "자동 잠금 5분" 제거, 게이지·슬라이더를 값 비율대로 표시, 글꼴 실패 시 중단, 화면 실패 시 남은 노드 정리, 검증기의 페이지 부착·삭제·화면 개수 검사 보강, Web·macOS 화면 목록 중복 제거.

## 검증하지 못한 것

1. 실제 Figma 앱에서 실행해 보지 않았다. 모의 검증은 오류 여부만 보며, 레이아웃이 보기에 맞는지는 Figma에서 사람이 확인해야 한다.
2. Noto Sans KR이 없는 환경에서 Inter로 대체되면 한글이 대체 글꼴로 표시될 수 있다.

## AI의 오류와 정정

1. 와이어프레임에 정책 원문이 아닌 문구(게이지 '위험', 복구 불가 경고, 클립보드 배지)와 정책에 없는 기능("자동 잠금 5분")을 넣었다. 독립 리뷰가 정책 SSOT와 어긋난다고 지적해 원문으로 바꾸고 정책에 없는 항목을 지웠다.
2. 첫 모의 검증기는 새 노드를 현재 페이지에 붙이지 않고 페이지 노드 삭제도 실제로 반영하지 않아, 실패 후 남은 노드나 다시 그리기 문제를 잡지 못했다. 독립 리뷰 지적으로 실제 Figma처럼 동작하게 고치고 화면 개수 검사를 더했다.

## 발견 사항

1. 정책끼리 용어가 다르다: SEC-001은 "마스터 키", SEC-002는 "마스터 비밀번호"를 쓴다. 와이어프레임은 각 정책 원문을 그대로 썼으며, 용어 통일은 정책 수정 사항으로 남긴다.
2. 기존 `Tools/figma-builder/code.js`는 `documentAccess: "dynamic-page"`인데 `figma.currentPage = page`로 페이지를 바꾼다. 이 모드에서는 `setCurrentPageAsync`를 써야 하므로 Figma 버전에 따라 실행이 실패할 수 있다. 이번 범위에서는 고치지 않고 기록만 남긴다.
