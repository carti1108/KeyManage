# 2026-10-31 · 웹 클라이언트와 실제 백엔드 통합 테스트 (#59)

> 요약: 웹 MVP 마지막 단계로 웹 클라이언트 코드(키 유도·암호화·세션·동기화)를 실제 백엔드에 붙여 가입부터 두 기기 동기화, 동시 저장 병합, 삭제 전달, 잠금 해제, 로그아웃까지 확인하는 통합 테스트를 만들고 CI에서 백엔드를 띄워 돌리게 했다. 방식(새 의존성 없는 실제 서버 통합 테스트)은 사람이 골랐다. 독립 리뷰의 낮음 항목을 모두 반영했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest, GitHub Actions
- 플러그인/스킬: 독립 코드 리뷰 서브에이전트, `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 클립보드 단계를 병합한 뒤 웹 MVP 마지막 단계(통합 확인)를 진행했다.

## AI 산출물

- `src/integration/vaultFlow.integration.test.ts`: 기기 두 대를 각자 서비스로 만들어 가입·저장·다른 기기 로그인·동시 저장 병합(revision으로 409 경로 확인)·삭제 전달·잠금 해제·틀린 비밀번호 거절·로그아웃 뒤 재로그인을 확인한다.
- `vitest.integration.config.ts`, `npm run test:integration`. 단위 테스트(`npm run check`)에서는 제외한다.
- CI `integration` 작업: 실행 가능한 jar로 백엔드를 띄우고, 준비될 때까지 기다리고(시작하다 죽으면 바로 실패), 통합 테스트를 돌리고, 실패하면 백엔드 로그를 보인다.

## 사람의 판단

- 통합 확인은 새 의존성 없이 실제 서버에 붙는 통합 테스트로 한다(Playwright 브라우저 E2E, 둘 다 기각). 화면 동작은 화면 테스트와 사람의 브라우저 확인으로 이미 다뤘다.

## 검증

- 로컬 백엔드로 통합 테스트 7건 통과(리뷰 반영 전후 두 번), CI 6개 작업 통과, `npm run check`(테스트 343건) 통과.
- 독립 리뷰: 높음 이상 0건. 낮음 항목(충돌 경로를 결과만으로 추정, 서버 동기화 여부 미확인, 시도 제한 메시지, CI 시작 실패 대기, 기본 제외 목록 덮어쓰기, 의미 없는 순서 설정) 모두 반영.

## 검증하지 못한 것

1. 서버 볼트 되돌림 감지와 오프라인 잠금 해제는 서버를 조작해야 해 통합 테스트에 넣지 않았다. 단위 테스트로 확인한다.
2. 인증 API는 IP당 1분 30회 제한이 있어 로컬에서 1분 안에 여러 번 돌리면 걸린다.

## AI의 오류와 정정

1. 동시 저장 테스트가 최종 항목 목록만 봐서 409 병합 경로를 거쳤는지 직접 확인하지 않았다. revision이 2 오른 것을 확인하게 했다.
2. 잠금 해제가 서버에서 받지 못하면 저장해 둔 볼트로 조용히 열리는데, 테스트가 이를 구분하지 않았다.
3. 단위 테스트 제외 목록을 새로 지정하면서 Vitest 기본 제외 목록을 덮어썼다.
4. CI가 백엔드 시작에 실패해도 2분을 다 기다린 뒤 실패했다.
