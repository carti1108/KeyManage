# 2026-11-01 · 문서 경계 기준과 VLT 정책 분할 (#69 PR A)

> 요약: 공통 정책에 웹 구현 세부가 섞이고 한 문단짜리 규칙이 길어진 문제를 정리했다. VLT-001에서 오프라인 동기화 대기(VLT-002)와 기기 볼트 보존(VLT-003)을 나누고, VLT-001~003·SEC-003의 규칙을 번호 목록으로 다시 썼다. 플랫폼 구현 세부는 웹 명세와 Apple 문서로 옮겼다. 문서 구조(공통은 `docs/`, 플랫폼 문서는 각 플랫폼 폴더)는 사람이 AI 제안 두 개를 고쳐 정했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest, GitHub CLI
- 플러그인/스킬: `policy-manager:policy-manager`, `project-docs:ai-usage`

## 요청

- 이슈 #69(문서 체계 정리)를 확인하고 리뷰한 뒤 계획을 세우라고 했다.
- 계획을 확정한 뒤 이슈를 고치고 첫 PR을 진행하라고 했다.

## AI 산출물

- 이슈 #69 리뷰: ADR 분류 예시가 실제 ADR 내용과 다른 점, 플랫폼별 독립 번호가 `check-docs.sh`의 번호 검사와 충돌하는 점, 이미 있는 `docs/README.md`·`docs/iOS/adr/`를 고려하지 않은 점, 채택한 ADR 본문을 옮기면 불변 원칙과 부딪히는 점을 짚었다.
- 이슈 #69 본문을 확정한 구조로 고쳐 쓰고, 문서 전반 가독성 정리를 #70으로 따로 올렸다.
- 정책
  - VLT-001: 동기화, revision, 병합, 항목 입력 규칙만 남겼다(규칙 11개).
  - VLT-002(신규): 오프라인 동기화 대기와 재전송(규칙 12개).
  - VLT-003(신규): 기기 볼트 보존(규칙 8개).
  - SEC-003: 규칙을 번호 목록으로 바꾸고, 토큰 보관 방식과 Keychain 세부를 뺐다.
  - 규칙·값·문구는 바꾸지 않았다. 웹에서만 쓰는 문구 두 개에는 `(웹)`을 붙였다.
- `docs/README.md`에 문서 경계 기준(무엇을 어디에 쓰는지, 참조 방향, 판단 순서, 작성 형식)을 추가했다.
- `Apps/Web/docs/device-storage.md`(웹 기기 저장 명세)를 새로 썼다. `docs/iOS/README.md`에는 생체 해제 키 보관 방식을 적었다.
- 웹 코드·테스트 주석의 정책 참조 28곳을 VLT-002·VLT-003으로 바꿨다.

## 사람의 판단

- AI는 ADR 파일을 한 폴더에 두고 목록 표에 '영역' 열만 추가하는 안을 추천했다. 사람은 "플랫폼마다 ADR을 따로 두는 게 당연하다"며 이 안을 받아들이지 않았다.
- AI가 다음으로 제안한 `docs/web/`, `docs/apple/` 구조도 고쳤다. 정책과 공통 ADR만 `docs/`에 단일 원천으로 두고, 플랫폼 문서는 플랫폼끼리 서로 알 필요가 없으니 각 플랫폼 폴더에 두기로 했다.
- 가독성 정리는 이번에 쪼개는 정책만 함께 하고, 나머지 문서는 별도 이슈(#70)로 미루는 추천안을 받아들였다.
- VLT-001 분할 초안과 웹 전용 문구 표시 방식을 그대로 승인했다.

## 검증

- `Scripts/check-docs.sh`: 통과.
- 웹 `tsc --noEmit`: 오류 없음.
- 웹 단위 테스트: 434건 모두 통과.
- 독립 리뷰(작성 맥락과 분리된 서브에이전트): 옛 VLT-001·SEC-003과 새 문서를 문장 단위로 대조했다. 사용자 문구는 글자 단위로 같았다. HIGH 1건, MEDIUM 5건, LOW 여러 건이 나왔다.
  - HIGH: VLT-002 규칙 3에 "대기로 두지 않고"를 새로 넣었다. 서버가 분명히 거절해도 대기를 남기는 코드와 어긋나 원래 문장으로 되돌렸다.
  - 반영: VLT-001 이력을 원문 그대로 되살림, SEC-003 규칙 10의 조건이 좁아진 표현을 원래 뜻으로 고침, 떠남 확인 주석 참조를 VLT-002로 고침, "즉시"·"이벤트 기반"·"서버 복구 또는 옛 볼트 재전송"·"Windows Hello" 복원.
  - 반영하지 않음: 공통 정책에서 웹 ADR-0020 참조를 뺀 것. 공통 문서는 플랫폼 문서를 참조하지 않는다는 이번 기준에 따른 것이며, 결정 근거는 웹 명세에서 따라간다.

## 검증하지 못한 것

1. `check-docs.sh`는 아직 `Apps/Web/docs/`를 검사하지 않는다. 웹 명세의 정책 링크는 파일이 있는지만 직접 확인했다. 플랫폼 문서 검사는 #69 PR B에서 추가한다.
2. Apple과 백엔드는 이번 PR에서 바꾸지 않았으므로 빌드와 테스트를 돌리지 않았다.
3. 독립 코드 리뷰는 받지 않았다.
4. 정책을 다시 쓴 뒤 규칙이 빠지지 않았는지는 AI(작성 AI와 독립 리뷰 서브에이전트)가 대조했을 뿐, 사람이 문장 단위로 확인하지는 않았다.
5. `check-policy-acceptance.sh`는 이 PC의 python3가 Windows 스토어 가짜 실행 파일이라 돌리지 못했다. 이 스크립트는 Apple 테스트 파일만 읽고 정책 문서는 읽지 않아 결과가 달라지지 않는다.

## AI의 오류와 정정

1. 이전 세션에서 AI가 쓴 이슈 #69 본문에 ADR 분류 예시가 틀려 있었다. ADR-0002를 KDF로, ADR-0003을 스프링 아키텍처로, ADR-0004를 프론트 스택으로 적었다. 이번 리뷰에서 실제 ADR 제목과 대조해 고쳤다.
2. 이슈는 ADR-0020의 결정 4~6을 명세로 옮긴다고 적었다. 실제로 명세로 옮길 대상은 결정 5~6이고, 결정 4는 SEC-003의 동작 규칙이었다.
3. VLT-002 규칙 3에 옛 정책에 없던 "대기로 두지 않고"를 넣어, 코드와 다른 규칙을 만들었다. 독립 리뷰에서 발견해 되돌렸다.
4. VLT-001 이력을 요약하면서 옛 이력 세부를 지웠다. 독립 리뷰에서 발견해 원문대로 되살렸다.
5. 정책 초안의 이력 날짜를 실제 날짜보다 하루 뒤로 적었다. 파일에 반영하기 전에 고쳤다.
