# 2026-11-01 · 웹 오프라인 저장 2단계: 기기 저장과 재시작 뒤 잠금 화면 (#64)

> 요약: 웹 클라이언트가 한 계정의 암호화된 볼트와 동기화 상태를 IndexedDB에 저장하게 했다. 그래서 새로고침하거나 재시작해도 잠금 화면에서 마스터 비밀번호만으로 볼트를 열 수 있고, 오프라인에서도 열린다. 인증 해시를 남기지 않는 방식(오프라인으로 열었으면 다시 입력)은 사람이 골랐다. 독립 보안 리뷰와 코드 리뷰를 네 차례 돌리며 대기 내용이 사라지는 경로와 되돌림 감지를 피하는 경로를 고쳤고, 그 결정을 ADR-0020으로 남겼다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest, fake-indexeddb, GitHub Actions
- 플러그인/스킬: `adr-manager:adr-manager`, `policy-manager:policy-manager`, `code-review`(독립 서브에이전트), `security-review`(독립 서브에이전트), `project-docs:ai-usage`

## 요청

- 1단계(PR #62) 머지 뒤, 보안 리뷰가 짚은 ADR-0018의 빈틈을 보완하는 ADR 초안을 먼저 보고 2단계(기기 저장)를 진행하기로 했다.
- 작업 전에 main 브랜치를 확인하고, 띄워 둔 백엔드는 끄라고 했다.

## AI 산출물

- ADR-0019(ADR-0018 대체): 기기에는 한 계정만 두고, 인증 해시는 잠금 해제 요청 하나 안에서만 쓰며, KDF 값이 바뀌면 비밀번호가 바뀐 것으로 본다.
- ADR-0020(ADR-0019 대체): 리뷰를 반영한 결정을 담았다.
  - 다른 계정의 인증이 성공하면 이전 기록을 먼저 지운다.
  - KDF가 바뀌어도 되돌림 검사를 유지한다.
  - 시작할 때 읽지 못한 기록은 로그인한 뒤 다시 확인한다.
  - 서버가 거절해도 볼트는 열고 사유를 알린다.
  - 저장소 열기 제한 시간은 3초로 하고, 탭 하나를 전제로 한다.
- SEC-003·VLT-001 갱신
  - SEC-003: 재시작 뒤 잠금 화면, 세션 없는 잠금 해제와 비밀번호 재입력, 비밀번호 바뀜 문구
  - VLT-001: 기기 저장 실패 경고, 로그아웃 때 기록 삭제 실패 문구, 탭 하나 전제
- 코드
  - `deviceRecord.ts`: 기록 형식과 읽기 검증. 규격 밖 KDF 값은 거른다.
  - `devicePersistence.ts`: 쓰기를 순서대로 처리하고 실패를 표시한다.
  - `indexedDbDeviceStore.ts`: 열기 제한 시간, 다른 탭의 차단, 버전 변경을 처리한다.
  - `authService.resume`: 이미 만든 인증 해시로 로그인하고 해시를 지운다.
  - 세션: 복원(`restore`), 세션 없는 잠금 해제, 비밀번호 재입력(`reconnect`), 로그인마다 따로 두는 되돌림 기억, 계정 전환과 로그아웃 때 기록 삭제
  - 화면: 비밀번호 재입력 칸(되돌림 확인 포함), 저장 실패 경고, 로그아웃 삭제 실패 안내
- 테스트: 기기 저장 세션 테스트 29건과 어댑터·기록·인증·App·화면 테스트를 새로 썼다. 전체 단위 테스트는 381건에서 434건이 됐다.

## 사람의 판단

- 인증 해시를 메모리에 두거나 토큰을 암호화해 저장하는 대안 대신, 오프라인으로 열었으면 다시 연결된 뒤 비밀번호를 다시 입력받는 추천안을 골랐다.
- IndexedDB 어댑터 테스트용으로 fake-indexeddb 개발 의존성을 받아들였다.
- 기기 기록을 읽지 못한 채 로그인하는 경우 두 가지 방식을 비교했다. "다시 읽어 병합"을 고르고, "다시 시도 화면"은 기각했다.
- 보안 리뷰 반영분은 ADR-0020으로 남기라고 했다.
- 재입력 로그인이 실패할 때 "서버에 연결할 수 없습니다"만 보여 주면 사용자가 원인을 알 수 없다고 지적했다. 그래서 실제 사유를 보여 주도록 바꿨다.
- AI가 정책 수정을 묻지 않고 진행한 점을 지적했다. 지적 이후 바뀐 항목은 그대로 진행하라고 했다.

## 검증

- 로컬 `npm run check`: 단위 테스트 434건 통과. `Scripts/check-docs.sh` 통과.
- 독립 보안 리뷰: CRITICAL·HIGH는 없었고 MEDIUM 1건, LOW 4건이 나왔다. MEDIUM(서버가 KDF 값만 바꿔 되돌림 감지를 피하고 기기 사본을 덮어씀)과 LOW 2건을 반영했다.
- 독립 코드 리뷰 1차: HIGH 1건, MEDIUM 여러 건 등 11건이 나와 9건을 반영했다. 여러 탭 문제는 #65로 미뤘다.
  - HIGH: 저장 실패 경고가 설정되자마자 지워졌다.
  - 그 밖에 비밀번호 재입력 중 되돌림 확인 없음, 기록 복원이 끝나지 않으면 빈 화면, 규격 밖 KDF 값, 이전 계정의 늦은 응답, 토큰 고아, 연결 누수 등.
- 같은 리뷰어의 재확인을 세 번 더 받았다. 수정이 새로 만든 문제가 매번 나와 모두 고쳤다.
  - 2차: 열기 제한 시간 때문에 대기 내용이 덮어써질 수 있음.
  - 3차: 다시 읽기마저 실패하면 덮어쓰기가 진행됨.
- IndexedDB 어댑터는 fake-indexeddb로 실제 IndexedDB 규격에 맞춰 테스트했다.

## 검증하지 못한 것

1. 실제 브라우저와 Tauri WebView2에서 새로고침, 오프라인 재시작, 비밀번호 재입력 흐름을 직접 확인하지 않았다.
2. 마지막 수정(읽지 못한 기록을 덮어쓰지 않음)은 테스트로만 확인했고, 리뷰어의 확인은 받지 않았다.
3. 이 PC에서는 python3가 Windows 스토어의 가짜 실행 파일이라 `check-policy-acceptance.sh`(Apple 정책 감사)를 돌리지 못했다. 검사 규칙을 직접 읽어, 정책 문서를 바꿔도 결과가 달라지지 않는 것을 확인했다.
4. 여러 탭 동시 사용(#65)과 Apple 클라이언트의 오프라인 처리는 다루지 않았다.

## AI의 오류와 정정

1. 정책 수정(SEC-003·VLT-001 문구와 리뷰 반영 규칙)을 사용자에게 묻지 않고 진행했다. CLAUDE.md의 "되돌리기 쉬운 결정은 기본값" 규칙을 근거로 삼았지만, 보안 경계와 데이터 손실에 닿는 항목이 섞여 있었다. 사람이 지적한 뒤 항목별로 정리해 확인을 받았다.
2. 1단계에서 VLT-001 규칙을 쓸 때 플랫폼 범위를 표시하지 않았다. 그래서 웹에서 정한 규칙이 Apple에도 요구 사항으로 읽히게 됐다.
3. 기기 기록 검증 코드(`deviceRecord.ts`)는 테스트를 먼저 실패시키지 않고 구현을 함께 썼다.
4. 의존성을 물을 때 fake-indexeddb의 라이선스를 MIT라고 했지만 실제로는 Apache-2.0이었다. 설치 뒤 정정했다.
5. KDF가 바뀐 경우를 처리하면서 되돌림 기준을 지웠다. 그 결과 서버가 salt만 바꾸면 되돌림 감지를 피할 수 있었다. 보안 리뷰에서 발견했다.
6. 리뷰 반영 수정이 새 결함을 연달아 만들었다.
   - 열기 제한 시간을 넣자 대기 내용 덮어쓰기 경로가 열렸다.
   - 그것을 막으려고 넣은 다시 읽기는 실패했을 때 쓰기를 막지 못했다.
7. 테스트 몇 개가 처음에는 의도한 경로를 확인하지 못했다.
   - 화면을 그리지 않아 항상 통과하는 테스트가 있었다.
   - 요청이 서버에 도착하기 전에 로그아웃해 버리는 경합 테스트가 있었다.
   - 의미 없는 단언이 들어간 KDF 테스트가 있었다.
8. ADR 번호를 바꾸면서 정책의 '이력' 줄에 있던 지난 기록까지 ADR-0020으로 바꿨다. 커밋 전에 되돌렸다.
9. 후속 이슈 본문에 아직 없는 PR 번호(#65, 실제로는 그 이슈 자신)를 적었다. 바로 고쳤다.
