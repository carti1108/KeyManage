# 2026-10-31 · 웹 클립보드 복사와 30초 자동 소각 (#57)

> 요약: 웹 MVP 아홉 번째 단계의 뒷부분으로 아이디·비밀번호 복사와 30초 자동 소각, 잠금 시 즉시 비움을 구현했다. 브라우저가 정책을 다 지킬 수 없는 부분의 처리는 사람이 정했다. 독립 보안 리뷰는 확신도 7 이상 발견이 없었고, 독립 코드 리뷰는 복사 도중 잠기면 클립보드가 남는 경쟁 조건 등을 찾아 7건을 반영했다.

## 사용 도구

- 도구: Claude Code (Claude Opus 5.5), Vitest, Testing Library
- 플러그인/스킬: `policy-manager:policy-manager`, `superpowers:test-driven-development`, 독립 코드 리뷰·보안 리뷰 서브에이전트, `issue-worktree:commit-rules`, `project-docs:ai-usage`

## 요청

- 생성기 단계와 이어지는 숫자 안내를 병합한 뒤 클립보드 단계를 진행했다.

## AI 산출물

- COM-001: 아이디 등 볼트 값에도 적용, 웹 예외(백그라운드 탭이면 돌아오거나 누를 때 비움, 읽기 권한 없이 비움, 닫힘·동결 때는 못 비울 수 있음), 복사 실패·비우지 못함 문구, 안내 문구를 "복사된 내용"으로.
- `domain/clipboard/clipboardBurner`: 30초 뒤 비움, 다시 복사하면 새로 잼, 잠기면 바로 비움, 실패하면 대기 후 재시도, 복사 도중 잠금 처리.
- 브라우저 연결: `navigator.clipboard.writeText`, 잠금 → 비움, 포커스·다시 보임·누름·키 입력 → 재시도.
- 화면: 상세의 아이디·비밀번호 복사, 목록 카드 옆 비밀번호 복사, 남은 초 배지, 비우지 못함 안내와 직접 비우기 버튼.

## 사람의 판단

- 웹은 최선을 다해 비우고 실패하면 다시 시도한다. 클립보드 읽기 권한은 요청하지 않는다(읽기 권한 요청, 웹 복사 금지 기각).

## 검증

- `npm run check`(테스트 343건) 통과.
- 독립 보안 리뷰: 확신도 7 이상 0건. 모든 잠금 경로(수동·자동 잠금, 로그아웃, 계정 전환)가 비우기로 이어지는 것을 확인했다.
- 독립 코드 리뷰: 중간 4건, 낮음 4건 중 7건 반영. 복사 실패 문구가 다음 복사 전까지 남는 것(낮음)은 해가 없어 그대로 뒀다.

## 검증하지 못한 것

1. 실제 브라우저(Chrome·Safari·Firefox)에서 30초 뒤 비우기, 백그라운드 탭에서 돌아온 뒤 비우기. Safari·Firefox는 사용자 조작 없이 쓰기를 막을 수 있어 누름·키 입력과 직접 비우기 버튼을 더했지만 확인하지 못했다.
2. 실제 세션과 클립보드를 함께 묶은 잠금 경로 통합 테스트는 없다. 코드상 모든 경로가 같은 잠금 알림을 거친다.

## AI의 오류와 정정

1. 복사(클립보드 쓰기)가 끝나기 전에 잠기면 상태가 아직 비어 있어 비우지 않았고, 쓰기가 끝난 뒤 30초 타이머를 걸어 잠긴 뒤에도 비밀번호가 남았다.
2. 타이머와 재시도가 사용자 조작 없이 쓰기를 해서, 이를 막는 브라우저에서는 계속 비우지 못한 상태로 남을 수 있었다.
3. 비우지 못한 상태를 화면에 보이지 않아 사용자가 지워졌다고 믿게 됐다.
4. 정책 문구가 읽기 권한 없이 비울 때의 영향 범위를 "30초 안"으로 작게 적었다. 비우지 못한 채 기다린 시간까지 포함된다.
5. 아이디를 복사해도 "복사된 비밀번호" 안내가 나왔고, 안내 영역이 새로 생겨 화면 낭독기가 읽지 않을 수 있었다.
