# 2026-11-02 · 웹 암호화 백업 내보내기와 복원 (VLT-004)

- 이슈·PR: PR #95
- 커밋: 8f91c4f, 24c8584, e3810a6, 688c18a, 657ec7c, c8caa09, f186efc, ac347bb

> **요약** 볼트를 내보낸 시점의 마스터 비밀번호로 잠근 백업 파일로 내보내고, 그 파일로 백업에 있던 항목을 백업 시점 내용으로 되돌리는 기능을 웹·데스크톱에 넣었다. 사람이 백업 암호와 복원 방식을 정했고, 실제로 써 본 뒤 "백업 뒤 고치거나 지운 항목도 돌아와야 한다"며 복원 규칙을 병합에서 되돌리기로 바꿨다.

## 사용 도구

- 도구: Claude Code (Opus 5.5). 구현 서브에이전트 1개, 독립 리뷰 서브에이전트 3회(전체, 수정분, 복원 규칙 변경분)
- 플러그인·스킬: policy-manager, adr-manager, project-docs:ai-usage

## 요청

웹 정책 점검에서 정책에 없는 흔한 기능을 물었고, 내보내기·가져오기의 뜻을 들은 뒤 암호화 백업과 복원부터 하기로 했다. 마스터 비밀번호 변경과 계정 삭제도 정책이 필요한지 물었다.

## AI 산출물

- 내보내기·가져오기 설명(평문과 암호화 형식 비교), 마스터 비밀번호 변경·계정 삭제에 정책이 필요한 이유와 순서 제안
- VLT-004 정책, ADR-0022(백업 파일 형식), vault-spec 6장, 정책 감사 스크립트의 VLT-004 웹 규칙
- 백업 파일 읽기·쓰기(`domain/backup`), 세션의 내보내기·복원(키는 세션 밖으로 나가지 않음), 복원 규칙(`restoreItems`), 다운로드·파일 선택 어댑터, 내보내기·복원 화면과 안내·오류 문구
- 리뷰 중 발견한 기존 버그 수정: Base64 형식 검사 정규식이 볼트 한도 근처(약 7MB) 문자열에서 스택을 넘쳐 큰 볼트를 열지 못하던 문제

## 검증하지 못한 것

1. 다른 플랫폼과 백업 파일을 주고받는 상호 운용(Apple·Android 미구현)
2. macOS·Linux 웹뷰의 파일 다운로드
3. 복원 직전에 서버 볼트를 먼저 받지 않으므로, 아직 받지 않은 다른 기기의 변경이 나중에 복원 결과를 덮을 수 있다(VLT-004 예외 5, 후속).
4. 복원과 다른 저장이 몇 ms 안에 겹칠 때의 경쟁(웹 알려진 제약에 기록)
5. `vaultSession.ts`가 791줄로 800줄 한도에 가깝다. 다음 세션 기능 전에 분리가 필요하다.
6. 커밋 이력은 PR을 연 뒤 다시 묶었다(아래 정정). 테스트를 먼저 쓰고 실패를 확인한 과정은 원래 이력(로컬 백업 브랜치)에만 남아 있다.
