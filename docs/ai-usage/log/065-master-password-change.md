# 2026-11-02 · 마스터 비밀번호 변경 (SEC-004)

> **요약** 현재 비밀번호를 확인한 뒤 클라이언트가 새 키로 볼트를 다시 암호화하고, 서버가 KDF 값·인증 해시·볼트를 한 번에 교체한 뒤 다른 기기 세션을 모두 끝내는 마스터 비밀번호 변경을 백엔드와 웹에 넣었다. 서버는 새 볼트 ID에 먼저 쓰고 계정 파일 교체 한 번으로 확정한다. 사람이 다른 기기 세션 처리와 Secret Key 보류를 정했고, 직접 확인하며 "비밀번호 바뀜" 안내 버그를 찾아냈다.

## 사용 도구

- 도구: Claude Code (Opus 5.5). 구현 서브에이전트 1개, 독립 리뷰 서브에이전트 4회(전체, HIGH 수정분, 비밀번호 바뀜 수정분 등), 백엔드 저장 구조 조사 서브에이전트 1개
- 플러그인·스킬: policy-manager, adr-manager, superpowers:systematic-debugging, project-docs:ai-usage

## 요청

남은 작업을 순서대로 하도록 했고, 세션 파일 분리 다음 작업으로 마스터 비밀번호 변경을 진행했다. 작업이 끝나면 맥 쪽도 알아야 하는지 물었다.

## AI 산출물

- 정책 SEC-004, 공통 ADR-0023(절차, API, Secret Key 보류), 백엔드 ADR-BE-001(볼트 ID 교체로 원자적 확정, 세션의 볼트 ID 결속), api-spec 2.5.5, SEC-002·SEC-003 보완
- 백엔드: `ChangePasswordUseCase`, 계정·볼트·세션 저장소 포트 확장, 고아 볼트 정리, 세션 파일에 볼트 ID 저장과 인증 시 비교
- 웹: 세션의 비밀번호 변경(새 salt·현재 반복 횟수로 새 키, 대기 변경 포함 재암호화, 저장 대기열에 줄 세우기), 변경 대화상자(모달), 기기 볼트를 열지 못했을 때 서버 KDF 확인, 탭별 KDF 기억(`sessionStorage`)
- 정책 감사 스크립트의 SEC-004 웹 규칙, 통합 테스트 5개
- 맥 쪽 이슈 #101(VLT-004 백업) 작성, SEC-004 이슈는 머지 뒤 작성 예정

## 사람의 판단

| 판단 | 내용 |
| :--- | :--- |
| 채택 | 비밀번호를 바꾸면 다른 기기 세션을 모두 끝내는 추천안을 골랐다. |
| 채택 | Secret Key는 이번에 넣지 않고 보류했다. |
| 채택 | 서버의 원자적 교체 방식, API, 정책 문구 초안을 승인했다. |
| 발견 | 직접 확인하며 다른 탭이 안내 없이 로그인 화면으로 가고, 시크릿 창은 새 비밀번호를 "틀렸다"고 하는 문제를 찾았다. |
| 발견 | 1차 수정 뒤 다시 확인해 새로 로드된 탭이 안내 없이 잠금 화면으로 가는 문제를 찾았다. |
| 확인 | 마지막 수정 뒤 여러 탭·시크릿 창에서 안내와 로그인이 정상임을 확인했다. |

## 검증하지 못한 것

1. 실제로 다른 물리 기기(다른 브라우저·PC)에서의 확인. 시크릿 창으로 흉내 냈다.
2. 데스크톱 앱(WebView2)에서의 비밀번호 변경.
3. Apple 클라이언트의 대응(세션 만료와 KDF 변경 감지). 맥 쪽 이슈로 넘긴다.
4. 리베이스로 들어온 웹 3분할 레이아웃(#106)에서 변경 진입점 위치는 테스트로만 확인했다.
