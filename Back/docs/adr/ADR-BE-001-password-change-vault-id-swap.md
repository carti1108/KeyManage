### ADR-BE-001 마스터 비밀번호 변경은 새 볼트 ID에 볼트를 먼저 쓰고, 계정 파일 교체 한 번으로 확정한다
- 상태: 채택
- 날짜: 2026-11-02
- 영역: 백엔드

> **요약** 서버는 다시 암호화된 볼트를 새 볼트 ID의 파일로 먼저 쓰고, 계정 파일 하나를 새 KDF 값·인증 해시·볼트 ID로 원자적으로 교체해 변경을 확정한다. 확정 뒤 옛 볼트 파일을 지운다.

#### 배경

공통 ADR-0023은 비밀번호 변경 때 KDF 값, 인증 해시, 볼트를 한 번에 교체하도록 정했다. 계정은 `accounts/{SHA-256(email)}.json`, 볼트는 `{vaultId}.json`으로 따로 저장되고(ADR-0003, ADR-0007), 두 파일을 함께 바꾸는 기능은 없다. 어느 파일을 먼저 바꾸든 둘째 쓰기가 실패하면 인증 정보와 볼트가 어긋난다.

#### 결정

1. **새 볼트 ID:** 새 볼트를 새로 만든 볼트 ID(UUID)의 파일로 먼저 쓴다. 옛 볼트 파일은 건드리지 않는다.
2. **확정 시점:** 계정 파일을 새 KDF 값, 새 인증 해시(Argon2id), 새 볼트 ID로 원자적으로 교체한다(임시 파일 → `ATOMIC_MOVE`). 이 교체가 성공한 순간이 변경 확정이다.
3. **잠금 순서:** 계정(이메일)별 잠금을 잡고, 그 안에서 옛 볼트의 볼트별 잠금을 잡는다. 잠금 안에서 현재 인증 해시와 revision을 확인하고 1·2를 한다. 같은 계정의 저장·변경이 겹치지 않는다.
4. **revision:** 새 볼트의 revision은 옛 볼트 revision에 1을 더한 값이다.
5. **정리:** 확정 뒤 옛 볼트 파일을 지운다. 확정 전 실패로 남은 새 볼트 파일이나 지우지 못한 옛 볼트 파일은 어느 계정도 가리키지 않으므로 해가 없다. 서버 시작 때 계정이 가리키지 않는 볼트 파일을 지운다.
6. **세션:** 확정 뒤 그 계정의 세션 파일을 모두 지우고 새 토큰을 발급한다. 세션 파일에는 이메일 색인이 없으므로 세션 폴더를 훑는다. 단일 인스턴스의 데모 규모에서는 비용이 작다.

#### 고려했던 대안

| 대안 | 고르지 않은 이유 |
| :--- | :--- |
| 전환 기록(journal) 파일로 두 파일 교체를 복구 | 시작 때 복구 로직이 필요하고 상태가 늘어난다. 볼트 ID를 바꿔 끼우면 파일 하나의 원자적 교체로 끝난다. |
| 계정 파일을 먼저 쓰고 볼트를 나중에 | 볼트 쓰기가 실패하면 새 인증 해시와 옛 볼트가 남아 계정이 열리지 않는다. |
| 볼트를 같은 ID로 덮어쓰고 계정을 나중에 | 계정 쓰기가 실패하면 새 볼트와 옛 인증 정보가 남아 계정이 열리지 않는다. |
| RDBMS로 옮겨 트랜잭션 사용 | 저장소 전체 교체(ADR-0003 대체)라 이번 범위에 과하다. |

#### 결과

- 장점: 별도 복구 장치 없이 "전부 아니면 전무"가 된다. 기존 원자적 쓰기(`AtomicFiles`)를 그대로 쓴다.
- 비용: 볼트 ID가 바뀐다. 클라이언트는 볼트 ID를 쓰지 않으므로 계약은 바뀌지 않는다. 남은 파일 정리 코드가 필요하다. 계정·세션 저장소에 새 메서드(교체, 계정 세션 모두 삭제)가 생긴다.
