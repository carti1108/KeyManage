# KeyManage Wireframe Builder (Figma 개발 플러그인)

Figma 파일에 **플랫폼별(iOS · Android · Web · macOS) 저충실도 와이어프레임**을 한 번에 그리는 플러그인입니다.
색·글꼴·아이콘은 일부러 회색조 자리표시로 두었습니다. 지금 단계의 목적은 "각 플랫폼에서 무엇이 어디에 놓이는가"를 정하는 것이고,
시각 디자인은 [DS Builder](../figma-builder/README.md)와 [디자인 시스템](../../docs/design-system.md) 단계에서 입힙니다.

---

## 1. 생성되는 내용

플랫폼마다 페이지 하나(`📐 iOS`, `📐 Android`, `📐 Web`, `📐 macOS`)가 만들어지고, 각 화면 아래에 **그 요소가 어느 정책에서 나왔는지** 메모가 붙습니다.

| 화면 | iOS | Android | Web | macOS | 근거 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| 로그인 | ✅ | ✅ | ✅ | ✅ | SEC-002, api-spec 2.5 |
| 가입 (강도 게이지, 복구 불가 경고) | ✅ | ✅ | ✅ | ✅ | SEC-001, GEN-001 |
| 볼트 목록 (오프라인 배너) | ✅ | ✅ | 목록+상세 3분할 | 목록+상세 3분할 | VLT-001 |
| 항목 상세 (복사 직후 30초 배지) | ✅ | ✅ | (위와 합침) | (위와 합침) | COM-001 |
| 항목 편집 | 시트 | 화면 | 상세 패널 | 상세 패널 | VLT-001, ADR-0006 |
| 비밀번호 생성기 | 탭 | 탭 | 메뉴 | 메뉴 | GEN-001 |
| 설정 (서버 주소, 로그아웃) | 탭 | 탭 | 메뉴 | 메뉴 | SEC-002 |

플랫폼 관례:
- **iOS** (393 × 852): 하단 탭 3개, 큰 제목 내비게이션, 편집은 시트.
- **Android** (412 × 915): Material 3 상단 앱 바, 하단 내비게이션, 목록의 추가는 FAB.
- **Web** (1440 × 900): 사이드바 · 목록 · 상세 3분할, 편집은 상세 패널 안에서 전환.
- **macOS** (1280 × 800): 창 하나에 사이드바 · 목록 · 상세, 검색과 추가는 툴바.

한글이 깨지지 않도록 **Noto Sans KR**을 먼저 쓰고, 없으면 Inter로 대체합니다(대체되면 완료 알림에 경고가 표시됩니다).

## 2. Figma에서 실행하는 방법

1. **Figma 데스크톱 앱**에서 디자인 파일을 엽니다(빈 파일 권장).
2. `Ctrl + /` (Mac: `Cmd + /`) → **`Import plugin from manifest...`** 실행.
3. 이 폴더의 **`Tools/wireframe-builder/manifest.json`**을 선택합니다.
4. 이후 `Ctrl + /` → **`KeyManage Wireframe Builder`** 를 실행하면 네 페이지가 만들어집니다.

같은 이름의 페이지가 이미 있으면 내용을 지우고 다시 그립니다.

---

## 3. 수정과 검증

- 화면 구성은 `code.js`의 `SCREENS`(플랫폼별 화면 목록)와 `loginContent`·`vaultListContent` 같은 내용 함수에서 바꿉니다.
- Figma 없이 먼저 확인하려면:

  ```bash
  node Tools/wireframe-builder/verify.js
  ```

  Figma API의 대표적인 오류 규칙(오토레이아웃 밖 FILL, 글꼴을 불러오지 않은 텍스트 수정, dynamic-page에서 `currentPage` 대입 등)을 흉내 낸 모의 환경에서 실행합니다. CI에서도 같은 검사를 돌립니다(ADR-0009).
- 모의 검증은 오류 여부만 봅니다. 화면이 보기에 맞는지는 Figma에서 직접 확인해야 합니다.
